\section{Foundations and Intuition}
% ============================================================================

Every binary search works like a high-low guessing game: pick the midpoint of your remaining candidate range, test one question, and throw away half the search space immediately.

\begin{notationbox}[Symbols Used in Binary Search]
$[L, R)$ & Half-open search interval: $L$ inclusive, $R$ exclusive (one past last valid index) & $[0, N)$ \\
$[L, R]$ & Closed search interval: both endpoints $L$ and $R$ are active candidates & $[0, N-1]$ \\
$P(x) \in \{F, T\}$ & Monotonic boolean feasibility predicate returning \texttt{false} then \texttt{true} & $P(x) = (A[x] \ge X)$ \\
$x^*$ & Exact monotonic transition boundary (first \texttt{true} or last \texttt{false}) & $x^* = 5$ \\
\end{notationbox}

\subsection{Overflow-Safe Midpoints and Half-Open Invariants}

\painbeat Writing binary search looks trivial, yet two classic bugs break even veteran code:
\begin{enumerate}
    \item \textbf{Midpoint Overflow:} Writing \texttt{(L + R) / 2} on 32-bit \texttt{int} overflows when $L + R > 2^{31} - 1 = 2{,}147{,}483{,}647$ (e.g., $L = 1.5 \times 10^9,\; R = 1.8 \times 10^9$ wraps to $-994{,}967{,}296$!).
    \item \textbf{Off-by-One Infinite Loops:} Mixing closed-interval updates with \texttt{while (L < R)} freezes when $R = L + 1$ and $\text{mid} = L$ sets $L = \text{mid}$ forever!
\end{enumerate}

\ahabeat Pair C++20's \texttt{std::midpoint(L, R)} (equivalent to $L + (R - L)/2$, never overflows!) with the \textbf{Half-Open Interval $[L, R)$} convention:

\begin{formulabox}[The Half-Open $[L, R)$ First-True Invariant]
$$\text{Init: } [L, R) = [0, N), \quad \text{Loop: } \texttt{while (L < R)}, \quad \text{mid} = \texttt{std::midpoint(L, R)}$$
$$\text{If } P(\text{mid}) \text{ is true: } R = \text{mid}; \qquad \text{else: } L = \text{mid} + 1; \qquad \text{Return } L.$$
\textbf{Read this as:} Since $\text{mid} = \lfloor (L + R) / 2 \rfloor$ always satisfies $L \le \text{mid} < R$ whenever $L < R$, \emph{both} branches strictly shrink $R - L$: setting $R = \text{mid}$ drops $R$, and setting $L = \text{mid} + 1$ raises $L$. Infinite loops and unsigned \texttt{mid - 1} underflow are \textbf{mathematically impossible}!
\end{formulabox}

\invariantbeat{Half-Open First-True} Every index $< L$ is guaranteed \texttt{false}; every index $\ge R$ is guaranteed \texttt{true}. When $L == R$, $L$ is the exact first \texttt{true} index (or $N$ if none exists).

\begin{tryitbox}{Debug}{Spotting an Infinite Loop in Binary Search}{ex1}
A programmer tries to find the \textbf{last true} index using \texttt{while (L < R) \{ mid = L + (R - L) / 2; if (P(mid)) L = mid; else R = mid - 1; \}}. Trace what happens when $L = 4,\; R = 5$ and $P(4) = \text{true}$, and explain the exact one-line fix.
\end{tryitbox}

\subsection{Boundary Lookups: Lower Bound and Upper Bound}

\painbeat When a sorted array contains duplicate values like $[1, 2, 4, 4, 4, 6, 7]$, plain equality search might land on \emph{any} of the three $4$s---and scanning left/right to count them degrades back to $O(N)$!

\ahabeat Replace equality with two half-open $[0, N)$ \textbf{First-True} predicates:
\begin{itemize}
    \item \textbf{Lower Bound:} First index $i$ where $A[i] \ge X$ (returns $N$ if all elements $< X$).
    \item \textbf{Upper Bound:} First index $i$ where $A[i] > X$ (returns $N$ if no element $> X$).
\end{itemize}

\begin{formulabox}[Frequency Count in $O(\log N)$]
$$\text{count}(X) = \texttt{upper\_bound}(A, X) - \texttt{lower\_bound}(A, X)$$
\textbf{Read this as:} The half-open index span $[\texttt{lower\_bound},\; \texttt{upper\_bound})$ contains every occurrence of $X$ and nothing else (Figure~\ref{fig:bs-lower-upper-bound}).
\end{formulabox}

\subsection{Predicate Monotonicity and Binary Search on the Answer}

\painbeat Optimization problems often ask: \emph{``What is the \textbf{minimum} ship capacity to deliver all cargo in $D$ days?''} Testing capacities $C = 1, 2, 3, \dots$ linearly takes $O(N \cdot R)$ time---instant timeout when $R = 10^9$!

\ahabeat \textbf{You do not need a sorted array---only a monotonic yes/no predicate $P(x)$!} If capacity $C$ works, every larger capacity $C' > C$ also works, partitioning the abstract answer domain into $[\text{F}, \text{F}, \dots, \text{F} \mid \text{T}, \text{T}, \dots, \text{T}]$ (Figure~\ref{fig:bs-predicate-monotonicity}). Binary search isolates the exact transition $x^*$ in $O(\text{check} \cdot \log(\text{Range}))$ time!

\subsection{Peak Elements via Slope Analysis}

Given an array where adjacent elements never tie ($A[i] \neq A[i+1]$) and virtual endpoints are $-\infty$, compare $A[\text{mid}]$ with $A[\text{mid} + 1]$:
\begin{itemize}
    \item If $A[\text{mid}] < A[\text{mid} + 1]$ (rising slope), walking uphill guarantees a peak to the \textbf{right}: $L = \text{mid} + 1$.
    \item Otherwise (falling slope), $\text{mid}$ itself or an element to its \textbf{left} is a peak: $R = \text{mid}$.
\end{itemize}

\examplebeat \textbf{Trace on $A = [1, 2, 1, 3, 5, 6, 4]$ ($L = 0, R = 6$):}
\begin{enumerate}
    \item $[0, 6],\; \text{mid} = 3$: $A[3] = 3 < A[4] = 5$ (rising) $\implies L = 4$.
    \item $[4, 6],\; \text{mid} = 5$: $A[5] = 6 > A[6] = 4$ (falling) $\implies R = 5$.
    \item $[4, 5],\; \text{mid} = 4$: $A[4] = 5 < A[5] = 6$ (rising) $\implies L = 5$.
\end{enumerate}
Terminates at $L = R = \mathbf{5}$ ($A[5] = 6$, strictly greater than neighbors $5$ and $4$).

\subsection{2D Row-Sorted Matrix Search}

Two common matrix variants leverage binary search:
\begin{itemize}
    \item \textbf{Globally sorted $M \times N$ matrix} (every row's first element exceeds the previous row's last): map virtual 1D index $\text{mid} \in [0, M \cdot N)$ to $(\text{mid} / N,\; \text{mid} \bmod N)$ for $O(\log(M \cdot N))$ lookup.

\end{itemize}

1 & $[1, 11]$ & $6$ & $1 + 1 + 2 + 2 = 6 \le 8$ (\texttt{T}) & $R = 6$ \\
2 & $[1, 6]$ & $3$ & $1 + 2 + 3 + 4 = 10 > 8$ (\texttt{F}) & $L = 4$ \\
3 & $[4, 6]$ & $5$ & $1 + 2 + 2 + 3 = 8 \le 8$ (\texttt{T}) & $R = 5$ \\
4 & $[4, 5]$ & $4$ & $1 + 2 + 2 + 3 = 8 \le 8$ (\texttt{T}) & $R = 4$ (Stop: $L = R = \mathbf{4}$) \\
\arrayrulecolor{primaryblue}\bottomrule[1.1pt]
\end{tabularx}\endgroup
\end{center}

\begin{calloutbox}{Exact Integer Ceiling Division Without Floating-Point Precision Loss}
Never write \texttt{std::ceil(static\_cast<double>(A) / B)} for 64-bit integers---\texttt{double} loses exact integer precision past $2^{53} \approx 9 \times 10^{15}$! Use exact integer arithmetic: $\lceil A / B \rceil = (A + B - 1) / B$ (or $1 + (A - 1) / B$ for $A \ge 1$ to prevent $A + B$ overflow).
\end{calloutbox}

\begin{example}[Counting Target Frequencies with Half-Open Bounds]
Find how many times $X = 7$ occurs in sorted $A = [1, 3, 5, 7, 7, 7, 9, 11]$ ($N = 8$) using half-open $[0, 8)$.
\begin{enumerate}
    \item \textbf{Lower Bound ($A[\text{mid}] \ge 7$):}
    $[0, 8) \xrightarrow{\text{mid}=4,\; 7 \ge 7} [0, 4) \xrightarrow{\text{mid}=2,\; 5 < 7} [3, 4) \xrightarrow{\text{mid}=3,\; 7 \ge 7} [3, 3) \implies \mathbf{3}$.
    \item \textbf{Upper Bound ($A[\text{mid}] > 7$):}
    $[0, 8) \xrightarrow{\text{mid}=4,\; 7 \ngtr 7} [5, 8) \xrightarrow{\text{mid}=6,\; 9 > 7} [5, 6) \xrightarrow{\text{mid}=5,\; 7 \ngtr 7} [6, 6) \implies \mathbf{6}$.
    \item \textbf{Count:} $6 - 3 = \mathbf{3}$ occurrences (indices $3, 4, 5$).
\end{enumerate}
\end{example}

\begin{example}[Minimizing the Maximum Workload (Painter's Partition)]
Partition boards $[12, 34, 67, 90]$ among $K = 2$ contiguous painters to minimize the heaviest workload. Bounds: $L = \max = 90$, $R = \sum = 203$.
\begin{enumerate}
    \item $[90, 203],\; \text{mid} = 146$: $[12,34,67]=113,\; [90]=90$ ($2 \le 2$, \texttt{T}) $\implies R = 146$.
    \item $[90, 146],\; \text{mid} = 118$: $113 \le 118,\; 90 \le 118$ ($2 \le 2$, \texttt{T}) $\implies R = 118$.
    \item $[90, 118],\; \text{mid} = 104$: $[12,34]=46,\; [67],\; [90]$ ($3 > 2$, \texttt{F}) $\implies L = 105$.
    \item $[105, 118],\; \text{mid} = 111$: needs $3$ painters (\texttt{F}) $\implies L = 112$.
    \item $[112, 118],\; \text{mid} = 115$: needs $2$ painters (\texttt{T}) $\implies R = 115$.
    \item $[112, 115],\; \text{mid} = 113$: $[12,34,67]=113,\; [90]$ ($2 \le 2$, \texttt{T}) $\implies R = 113$.
    \item $[112, 113],\; \text{mid} = 112$: needs $3$ painters (\texttt{F}) $\implies L = 113$.
\end{enumerate}
Terminates at $L = R = \mathbf{113}$.
\end{example}

\begin{example}[Rotated Array Search (Unique Elements)]
Locate target $X = 3$ in $A = [6,7,1,2,3,4,5]$ with $L = 0, R = 6$.
\begin{enumerate}
    \item $\text{mid} = 3$ ($A[3] = 2 \neq 3$): $A[0] = 6 > A[3] = 2 \implies$ right half $[2,3,4,5]$ is sorted. Since $2 < 3 \le 5$, set $L = 4$.
    \item $[4, 6],\; \text{mid} = 5$ ($A[5] = 4 \neq 3$): $A[4] = 3 \le A[5] = 4 \implies$ left half $[3, 4]$ is sorted. Since $3 \le 3 < 4$, set $R = 4$.
    \item $[4, 4],\; \text{mid} = 4$ ($A[4] = 3 == 3$) $\implies$ Found at index $\mathbf{4}$.
\end{enumerate}
\end{example}

\begin{example}[Integer Square Root Without \texttt{std::sqrt} (Complete Step Trace)]
Find $\lfloor \sqrt{50} \rfloor$: the largest integer $k \ge 0$ satisfying $k^2 \le 50$. Bounds: $[L, R] = [0, 50]$, \texttt{ans = 0}.
\begin{enumerate}
    \item $[0, 50],\; \text{mid} = 25$: $25^2 = 625 > 50 \implies R = 24$.
    \item $[0, 24],\; \text{mid} = 12$: $12^2 = 144 > 50 \implies R = 11$.
    \item $[0, 11],\; \text{mid} = 5$: $5^2 = 25 \le 50 \implies \text{ans} = 5,\; L = 6$.
    \item $[6, 11],\; \text{mid} = 8$: $8^2 = 64 > 50 \implies R = 7$.
    \item $[6, 7],\; \text{mid} = 6$: $6^2 = 36 \le 50 \implies \text{ans} = 6,\; L = 7$.
    \item $[7, 7],\; \text{mid} = 7$: $7^2 = 49 \le 50 \implies \text{ans} = 7,\; L = 8$.
\end{enumerate}
Loop stops ($L = 8 > R = 7$): $\lfloor \sqrt{50} \rfloor = \mathbf{7}$. \emph{Overflow tip:} For large $N \le 2^{31} - 1$, test \texttt{mid <= N / mid} (or use \texttt{std::int64\_t}) so $\text{mid}^2$ never overflows!
\end{example}

\begin{example}[Maximizing the Minimum Gap (Aggressive Placement)]
Place $C = 3$ items in stalls $X = [1, 2, 4, 8, 9]$ to maximize the minimum gap $D$. Predicate $P(D)$ is \texttt{TTTFFF}; search $[L, R] = [1, 8]$.
\begin{enumerate}
    \item $[1, 8],\; \text{mid} = 4$: greedy places at $1, 8$ ($2 < 3$, \texttt{F}) $\implies R = 3$.
    \item $[1, 3],\; \text{mid} = 2$: places at $1, 4, 8$ ($3 \ge 3$, \texttt{T}) $\implies \text{ans} = 2,\; L = 3$.
    \item $[3, 3],\; \text{mid} = 3$: places at $1, 4, 8$ ($3 \ge 3$, \texttt{T}) $\implies \text{ans} = 3,\; L = 4$.
\end{enumerate}
Terminates ($L = 4 > R = 3$): maximum minimum gap $= \mathbf{3}$.
\end{example}

\section{C++ Implementations}
% ============================================================================

Every listing below compiles cleanly as standalone C++23 (\texttt{-std=c++23 -Wall -Wextra}). Implementations use \texttt{std::ranges::fold\_left}, \texttt{std::midpoint}, \texttt{std::optional}, and \texttt{std::invocable}.

\subsection{Classic Binary Search (\texorpdfstring{\texttt{std::midpoint}}{std::midpoint})}
Returns the index if found or \texttt{std::nullopt} otherwise, guarding empty input and unsigned underflow.

\begin{lstlisting}[caption={Classic binary search using std::midpoint}]
#include <cstddef>
#include <numeric>
#include <optional>
#include <span>

[[nodiscard]] std::optional<std::size_t> binary_search(
    std::span<const int> nums,
    int target
) noexcept {
    if (nums.empty()) return std::nullopt;
    std::size_t left = 0;
    std::size_t right = nums.size() - 1;

    while (left <= right) {
        const std::size_t mid = std::midpoint(left, right);
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) {
            left = mid + 1;
        } else {
            if (mid == 0) break;
            right = mid - 1;
        }
    }
    return std::nullopt;
}
\end{lstlisting}

\subsection{Half-Open \texorpdfstring{$[L, R)$}{[L, R)} Lower Bound and Upper Bound}
Both functions maintain the exact half-open invariant $[0, N)$ with \texttt{right = mid} and \texttt{left = mid + 1}, matching the prose and requiring zero unsigned underflow guards.

\begin{lstlisting}[caption={Half-open lower\_bound and upper\_bound using std::midpoint}]
#include <cstddef>
#include <numeric>
#include <span>

[[nodiscard]] std::size_t lower_bound_index(
    std::span<const int> nums,
    int target
) noexcept {
    std::size_t left = 0;
    std::size_t right = nums.size(); // Half-open [left, right)

    while (left < right) {
        const std::size_t mid = std::midpoint(left, right);
        if (nums[mid] >= target) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }
    return left;
}

[[nodiscard]] std::size_t upper_bound_index(
    std::span<const int> nums,
    int target
) noexcept {
    std::size_t left = 0;
    std::size_t right = nums.size();

    while (left < right) {
        const std::size_t mid = std::midpoint(left, right);
        if (nums[mid] > target) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }
    return left;
}
\end{lstlisting}

\subsection{Binary Search on the Answer (Painter's Partition)}
Uses \texttt{std::optional} to guard empty input or \texttt{k <= 0}, \texttt{std::ranges::fold\_left} for the upper bound, and \texttt{std::midpoint} over \texttt{std::int64\_t}.

\begin{lstlisting}[caption={Minimizing maximum partition sum using C++23 ranges and std::midpoint}]
#include <algorithm>
#include <cstdint>
#include <functional>
#include <numeric>
#include <optional>
#include <span>

[[nodiscard]] std::optional<std::int64_t> split_array_min_max(
    std::span<const int> nums,
    int k
) noexcept {
    if (nums.empty() || k <= 0) return std::nullopt;

    auto can_partition = [&](std::int64_t limit) noexcept -> bool {
        int parts = 1;
        std::int64_t running = 0;
        for (int x : nums) {
            if (running + x <= limit) {
                running += x;
            } else {
                ++parts;
                running = x;
                if (parts > k) return false;
            }
        }
        return true;
    };

    std::int64_t left = *std::ranges::max_element(nums);
    std::int64_t right = std::ranges::fold_left(nums, std::int64_t{0}, std::plus<>{});

    while (left < right) {
        const std::int64_t mid = std::midpoint(left, right);
        if (can_partition(mid)) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }
    return left;
}
\end{lstlisting}

\subsection{Search in a Rotated Sorted Array}
Checks which half is strictly sorted at each midpoint and narrows the closed interval in $O(\log N)$ time.

\begin{lstlisting}[caption={Search in a cyclically rotated sorted array of unique elements}]
#include <cstddef>
#include <numeric>
#include <optional>
#include <span>

[[nodiscard]] std::optional<std::size_t> search_rotated_array(
    std::span<const int> nums,
    int target
) noexcept {
    if (nums.empty()) return std::nullopt;
    std::size_t left = 0;
    std::size_t right = nums.size() - 1;

    while (left <= right) {
        const std::size_t mid = std::midpoint(left, right);
        if (nums[mid] == target) return mid;

        if (nums[left] <= nums[mid]) {
            if (nums[left] <= target && target < nums[mid]) {
                if (mid == 0) break;
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            if (nums[mid] < target && target <= nums[right]) {
                left = mid + 1;
            } else {
                if (mid == 0) break;
                right = mid - 1;
            }
        }
    }
    return std::nullopt;
}
\end{lstlisting}

\subsection{Peak Element Search (\texorpdfstring{\texttt{std::optional}}{std::optional})}
Returns \texttt{std::nullopt} on empty input instead of a spurious index $0$; uses \texttt{std::midpoint} and slope comparison.

\begin{lstlisting}[caption={Finding any peak element in O(log N) time}]
#include <cstddef>
#include <numeric>
#include <optional>
#include <span>

[[nodiscard]] std::optional<std::size_t> find_peak_element(
    std::span<const int> nums
) noexcept {
    if (nums.empty()) return std::nullopt;
    std::size_t left = 0;
    std::size_t right = nums.size() - 1;

    while (left < right) {
        const std::size_t mid = std::midpoint(left, right);
        if (nums[mid] < nums[mid + 1]) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }
    return left;
}
\end{lstlisting}

\subsection{Continuous Floating-Point Bisection (C++20 \texorpdfstring{\texttt{std::invocable}}{std::invocable})}
Avoids \texttt{std::function} heap/type-erasure overhead via a C++20 concept-constrained callable, and runs 80 fixed iterations to reach full IEEE 754 \texttt{double} precision without epsilon stalls.

\begin{lstlisting}[caption={Continuous floating-point binary search with std::invocable}]
#include <concepts>
#include <numeric>
#include <type_traits>

template <std::invocable<double> Fn>
requires std::convertible_to<std::invoke_result_t<Fn, double>, double>
[[nodiscard]] double continuous_binary_search(double left, double right, Fn&& f) {
    // 80 halvings shrink width by 2^-80 (~8e-25), surpassing IEEE 754 double precision
    for (int iter = 0; iter < 80; ++iter) {
        const double mid = std::midpoint(left, right);
        if (static_cast<double>(f(mid)) < 0.0) {
            left = mid;
        } else {
            right = mid;
        }
    }
    return std::midpoint(left, right);
}
\end{lstlisting}

\section{Problem Pattern Recognition}
% ============================================================================

\subsection*{Step 1: What Does the Problem Ask For?}
\begin{itemize}
    \item \textbf{Exact lookup in sorted data} $\implies$ Classic Binary Search ($O(\log N)$).
    \item \textbf{First/last occurrence or duplicate count} $\implies$ \texttt{lower\_bound} / \texttt{upper\_bound}.
    \item \textbf{Minimize the maximum / maximize the minimum} $\implies$ Binary Search on the Answer + Greedy check.
    \item \textbf{Local peak in distinct-neighbor array} $\implies$ Slope Analysis Binary Search.
    \item \textbf{Target or minimum in cyclically shifted sorted array} $\implies$ Rotated Binary Search.
\end{itemize}

\subsection*{Step 2: What Is the Key Constraint?}
\begin{itemize}
    \item \textbf{Monotonicity:} Does \texttt{feasible(x)} imply \texttt{feasible(x')} for all $x' > x$ (or all $x' < x$)?
    \item \textbf{Check cost $C$:} With $60$ steps and an $O(N)$ check ($N \le 10^5$), $60 \times 10^5 = 6 \times 10^6$ ops passes easily.
    \item \textbf{Duplicates in rotated arrays:} Worst case degrades to $O(N)$ when $A[L] = A[\text{mid}] = A[R]$.
\end{itemize}

\subsection*{Step 3: Constraint Thresholds}
\begin{itemize}
    \item Answer domain up to $10^{18}$: $\approx 60$ iterations; always use \texttt{std::int64\_t} + \texttt{std::midpoint}.
    \item $Q \le 10^5$ queries on $N \le 10^5$ static data: sort once ($O(N \log N)$) + $O(\log N)$ per query.
    \item Row-sorted $M \times N$ matrix: value-range BS costs $O(M \log N \log(\text{Range}))$.
\end{itemize}

\section{Glossary}
% ============================================================================

\subsection*{Core Concepts}
\begin{itemize}
    \item \textbf{Binary Search:} Halving a candidate domain repeatedly using a monotonic condition.
    \item \textbf{Feasibility Predicate ($P(x)$):} Boolean check testing whether candidate answer $x$ satisfies all constraints.
    \item \textbf{Half-Open Interval ($[L, R)$):} Range with $L$ inclusive and $R$ exclusive; guarantees termination without \texttt{mid - 1} underflow.
    \item \textbf{Integer Overflow:} Wrap-around when $L + R$ exceeds type max; prevented by \texttt{std::midpoint}.
    \item \textbf{Loop Invariant:} Condition preserved before and after every iteration (e.g., all $< L$ are false, all $\ge R$ are true).
    \item \textbf{Lower Bound:} First index $i \in [0, N]$ where $A[i] \ge \text{target}$.
    \item \textbf{Monotonicity:} Order-preserving property ensuring a predicate switches value at most once (\texttt{FFFTTT} or \texttt{TTTFFF}).
    \item \textbf{Peak Element:} Element strictly greater than its immediate neighbors.
    \item \textbf{Rotated Sorted Array:} Sorted array cyclically shifted so at most one downward cliff exists.
    \item \textbf{Upper Bound:} First index $i \in [0, N]$ where $A[i] > \text{target}$.
\end{itemize}

\subsection*{Mathematical Symbols}
\begin{itemize}
    \item $[L, R],\; [L, R)$: Closed vs.\ half-open search intervals.
    \item $P(x) \in \{F, T\},\; x^*$: Monotonic boolean predicate and its exact transition boundary.
    \item $\lfloor x \rfloor,\; \lceil x \rceil$: Floor and ceiling functions ($\lceil A / B \rceil = (A + B - 1) / B$ for integers).
    \item $\log_2 N$: Base-2 logarithm; halving steps needed to reduce $N$ to $1$.
    \item $\epsilon$: Small positive tolerance threshold for floating-point convergence.
\end{itemize}

\begin{tryitbox}{Edge Cases}{Why Duplicates Break Rotated Binary Search}{ex13}

\end{tryitbox}

\begin{tryitbox}{Derive}{Exact Worst-Case Iterations of Half-Open Search}{ex14}

\section*{Solutions to Pen-and-Paper Exercises}
\addcontentsline{toc}{section}{Solutions to Pen-and-Paper Exercises}
\markboth{Solutions to Pen-and-Paper Exercises}{}

\begin{enumerate}[itemsep=2pt]
    \item \label{sol:ex1}\textbf{Exercise 1 (Debug) --- Infinite Loop in Binary Search:}
    At $L = 4,\; R = 5$, $\text{mid} = 4 + (5 - 4)/2 = 4$. Since $P(4) = \text{true}$, \texttt{L = mid} sets $L = 4$ again---interval $[4, 5]$ never shrinks! Fix: use upper-biased midpoint \texttt{mid = L + (R - L + 1) / 2} for last-true loops, or rewrite as first-true on \texttt{!P(x)} with \texttt{L = mid + 1, R = mid}.
    \trapnote{Assigning \texttt{L = mid} alongside a floor-rounded midpoint \texttt{L + (R - L) / 2}---that always freezes on 2-element intervals $[L, L+1]$.}

    \item \label{sol:ex2}\textbf{Exercise 2 (Trace) --- Lower Bound vs.\ Upper Bound on \texttt{[2, 4, 4, 4, 7]}:}
    \texttt{lower\_bound(4)}: $[0, 5) \xrightarrow{\text{mid}=2} [0, 2) \xrightarrow{\text{mid}=1} [0, 1) \xrightarrow{\text{mid}=0} [1, 1) \implies \mathbf{1}$.
    \texttt{upper\_bound(4)}: $[0, 5) \xrightarrow{\text{mid}=2} [3, 5) \xrightarrow{\text{mid}=4} [3, 4) \xrightarrow{\text{mid}=3} [4, 4) \implies \mathbf{4}$.
    $\text{count}(4) = 4 - 1 = \mathbf{3}$; \texttt{lower\_bound(5)} $= \mathbf{4}$ (index of $7$); \texttt{lower\_bound(9)} $= \mathbf{5}$ (\texttt{nums.size()}).
    \trapnote{Initializing \texttt{right = nums.size() - 1} in a half-open loop---that prevents ever returning \texttt{nums.size()} when all elements are $< X$.}

    \item \label{sol:ex3}\textbf{Exercise 3 (Edge Cases) --- Unsigned Underflow:}
    At $L = 0,\; R = 0,\; \text{mid} = 0$, $A[0] = 10 > 5$ runs \texttt{right = 0 - 1}, wrapping unsigned \texttt{std::size\_t} to $2^{64} - 1 \approx 1.8 \times 10^{19}$, crashing on the next \texttt{nums[mid]} read! Half-open $[L, R)$ only ever assigns \texttt{right = mid} (never \texttt{mid - 1}), so underflow is impossible.
    \trapnote{Using \texttt{std::size\_t} with \texttt{right = mid - 1} and forgetting the \texttt{if (mid == 0) break;} guard.}

    \item \label{sol:ex4}\textbf{Exercise 4 (Derive) --- Package-Shipping Predicate $P(C)$:}
    \textbf{(1)} If capacity $C$ finishes in $\le D$ days, any $C' > C$ packs at least as much per day, also using $\le D$ days (\texttt{FFFTTT}). Tightest bounds: $L = \max(w),\; R = \sum w$.
    \textbf{(2)} Greedy: \texttt{days = 1, load = 0}; for each \texttt{x}: if \texttt{load + x <= C} add to \texttt{load}, else \texttt{++days; load = x}; return \texttt{days <= D}.
    \textbf{(3)} On \texttt{[3, 2, 2, 4, 1, 4]}, $D = 3$: $P(6)$ uses $[3,2],\; [2,4],\; [1,4]$ ($3 \le 3$, \textbf{True}); $P(5)$ uses $[3,2],\; [2],\; [4,1],\; [4]$ ($4 > 3$, \textbf{False}). Optimal $C^* = \mathbf{6}$.
    \trapnote{Setting $L = 0$ instead of $L = \max(w)$---if $C < \max(w)$, a single package cannot fit on any day and breaks the greedy loop!}

    \item \label{sol:ex5}\textbf{Exercise 5 (Trace) --- Rotated Search on \texttt{[6, 7, 1, 2, 3, 4, 5]}:}
    \textbf{(a) $T = 2$:} $L = 0, R = 6, \text{mid} = 3 \implies A[3] = 2 == 2$, found at index $\mathbf{3}$ in $1$ step.
    \textbf{(b) $T = 7$:} Step 1: $[0, 6],\; \text{mid} = 3$ ($A[3] = 2$); $A[0] = 6 > 2 \implies$ right $[2..5]$ sorted; $7 \notin (2, 5] \implies R = 2$. Step 2: $[0, 2],\; \text{mid} = 1$ ($A[1] = 7 == 7$) $\implies$ found at index $\mathbf{1}$.
    \trapnote{Writing strict \texttt{nums[left] < nums[mid]} instead of \texttt{<=}---when $L = \text{mid}$ on a 2-element slice, \texttt{<} misidentifies the left half as unsorted.}

    \item \label{sol:ex6}\textbf{Exercise 6 (Twist) --- Minimum Element in Rotated Array:}
    Compare $A[\text{mid}]$ with $A[R]$: if $A[\text{mid}] > A[R]$, the drop lies strictly to the right ($L = \text{mid} + 1$); else the minimum is at $\text{mid}$ or left ($R = \text{mid}$).
    Trace on $[4, 5, 6, 7, 0, 1, 2]$: $[0, 6] \xrightarrow{\text{mid}=3,\; 7 > 2} [4, 6] \xrightarrow{\text{mid}=5,\; 1 \le 2} [4, 5] \xrightarrow{\text{mid}=4,\; 0 \le 1} [4, 4] \implies A[4] = \mathbf{0}$.
    \trapnote{Comparing $A[\text{mid}]$ against $A[L]$ instead of $A[R]$---that fails when the array is \emph{not} rotated at all (already sorted $[1, 2, 3]$)!}

    \item \label{sol:ex7}\textbf{Exercise 7 (Debug) --- Floating-Point Epsilon Hang:}
    An IEEE 754 \texttt{double} has $53$ significand bits. Near $31{,}622.77 \approx 2^{15}$, 1 ULP is $2^{15 - 52} \approx 7.3 \times 10^{-12} > 10^{-12}$. Once $R - L$ hits 1 ULP, \texttt{mid} equals $L$ or $R$ and \texttt{while (R - L > 1e-12)} loops forever! Fix: \texttt{for (int iter = 0; iter < 80; ++iter)}.
    \trapnote{Assuming a fixed absolute $\epsilon = 10^{-12}$ works regardless of the magnitude of the answer.}

    \item \label{sol:ex8}\textbf{Exercise 8 (Debug) --- Three Classic Binary Search Bugs:}
    \textbf{(1)} $1.5 \times 10^9 + 1.8 \times 10^9 = 3.3 \times 10^9 > 2^{31} - 1$: signed 32-bit overflow UB wraps negative! Use \texttt{std::midpoint}.
    \textbf{(2)} With $k = 0$, \texttt{can\_partition} immediately returns \texttt{false} for every limit, returning an invalid answer instead of \texttt{std::nullopt}.
    \textbf{(3)} Returning \texttt{0} on an empty array is indistinguishable from a valid peak at index \texttt{0}; return \texttt{std::optional<std::size\_t>}.
    \trapnote{Using magic sentinel index \texttt{0} or \texttt{-1} instead of \texttt{std::optional<std::size\_t>}.}

    \item \label{sol:ex9}\textbf{Exercise 9 (Triage) --- Does Binary Search Apply?:}
    \textbf{(1)} First-True Binary Search in $O(\log N)$ ($\approx 24$ checks for $10^7$).
    \textbf{(2)} Binary Search on the Answer in $O(N \log(\max A))$.
    \textbf{(3)} \textbf{No binary search}---use a single $O(N)$ linear scan (sorting first costs $O(N \log N)$, slower than scanning once!).
    \trapnote{Sorting an array for $O(N \log N)$ just to perform a single $O(\log N)$ lookup.}

    \item \label{sol:ex10}\textbf{Exercise 10 (Trace) --- Flattened 3x4 Matrix Search:}
    Cols $N = 4$: Step 1: $[0, 11],\; \text{mid} = 5 \to (1, 1) = 11 < 16 \implies L = 6$.
    Step 2: $[6, 11],\; \text{mid} = 8 \to (2, 0) = 23 > 16 \implies R = 7$.
    Step 3: $[6, 7],\; \text{mid} = 6 \to (1, 2) = 16 == 16 \implies$ Found at $\mathbf{(1, 2)}$.
    \trapnote{Dividing and taking modulo by the number of \emph{rows} $M$ instead of the number of \emph{columns} $N$!}

    \item \label{sol:ex11}\textbf{Exercise 11 (Debug) --- Ceiling Division Pitfalls:}
    \textbf{(1)} \texttt{double} has only $53$ bits of precision ($\approx 9 \times 10^{15}$), so $10^{17} + 1$ rounds down to $10^{17}$ before division!
    \textbf{(2)} $a + b - 1 = 3 \times 10^9$ overflows 32-bit signed \texttt{int}. Safe fix: promote to \texttt{std::int64\_t} and compute \texttt{1 + (a - 1) / b} (for $a \ge 1$).
    \trapnote{Calling \texttt{std::ceil} on 64-bit integers and silently losing the low-order bits.}

    \item \label{sol:ex12}\textbf{Exercise 12 (Twist) --- Count \& Last Index via \texttt{lower\_bound}:}
    For integers, $\texttt{upper\_bound}(A, x) = \texttt{lower\_bound}(A, x + 1)$. Thus $\text{count}(x) = \texttt{lb}(x + 1) - \texttt{lb}(x)$, and if $\text{count}(x) > 0$, the last index is $\texttt{lb}(x + 1) - 1$. Watch out for $x = \texttt{INT\_MAX}$ ($x + 1$ overflows signed \texttt{int}---use \texttt{nums.size()} as the upper bound instead!).
    \trapnote{Writing \texttt{x + 1} without checking \texttt{x == std::numeric\_limits<int>::max()}.}

    \item \label{sol:ex13}\textbf{Exercise 13 (Edge Cases) --- Rotated Array with Duplicates:}
    At $L = 0, R = 4, \text{mid} = 2$: $A[0] = A[2] = A[4] = 1$. The test $A[L] \le A[\text{mid}]$ falsely treats $[1, 0, 1]$ as sorted, sees $0 \notin [1, 1)$, and jumps to $L = 3$, discarding $0$ forever! Fallback: whenever $A[L] = A[\text{mid}] = A[R]$, shrink linearly (\texttt{++L; {-}{-}R;}), degrading worst-case time to $O(N)$.
    \trapnote{Assuming rotated binary search stays $O(\log N)$ when arbitrary duplicates are allowed.}

    \item \label{sol:ex14}\textbf{Exercise 14 (Derive) --- Exact Worst-Case Iterations of Half-Open Search:}
    Max iterations for $[0, N)$: $N = 1 \to 1$, $N = 2 \to 2$, $N = 3 \to 2$, $N = 4 \to 3$, $N = 8 \to 4$. Closed form: $\mathbf{\lfloor \log_2 N \rfloor + 1 = \lceil \log_2(N + 1) \rceil}$.
    At $N = 10^9$: $\lfloor \log_2(10^9) \rfloor + 1 = \mathbf{30}$; at $N = 10^{18}$: $\lfloor \log_2(10^{18}) \rfloor + 1 = \mathbf{60}$.
    \trapnote{Assuming $N = 1$ takes $0$ iterations---for \texttt{lower\_bound}, the single element $A[0]$ must still be tested once to decide between returning $0$ or $1$!}
\end{enumerate}
