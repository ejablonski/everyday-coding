\whybeat \textbf{\texttt{std::deque} vs. \texttt{std::stack<int, std::vector<int>>} (Module~11):} Monotonic sliding-window queues need $O(1)$ pops from \emph{both} ends, making \texttt{std::deque} ideal. For LIFO monotonic stacks, overriding the backing container to \texttt{std::stack<int, std::vector<int>>} (or using a plain \texttt{std::vector}) eliminates chunk indirection for better cache locality.

\subsection{Priority Queue: Min-Heaps and Custom Comparators}

By default, \texttt{std::priority\_queue<T>} puts the \emph{largest} element on top (comparator returns \texttt{true} when the first argument has \emph{lower} priority than the second). Since C++20, stateless lambdas are default-constructible, so you no longer need to pass \texttt{(cmp)} to the constructor unless the lambda captures variables.

\begin{lstlisting}[caption={Min-heap and custom comparator patterns for \texttt{std::priority\_queue}}]
#include <functional>
#include <queue>
#include <utility>
#include <vector>

struct Edge {
    int to;
    int weight;
};

struct ComparePair {
    bool operator()(const std::pair<int, int>& a,
                    const std::pair<int, int>& b) const noexcept {
        return a.second > b.second; // Smaller distance has higher priority
    }
};

void priority_queue_examples() {
    // 1. Standard min-heap for primitives (transparent std::greater<>)
    std::priority_queue<int, std::vector<int>, std::greater<>> min_pq;

    // 2. Custom functor struct (classic Dijkstra pattern)
    std::priority_queue<std::pair<int, int>, std::vector<std::pair<int, int>>, ComparePair> dij_pq;

    // 3. C++20 stateless lambda comparator (default-constructible; no "(cmp)" needed)
    auto cmp = [](const Edge& a, const Edge& b) noexcept { return a.weight > b.weight; };
    std::priority_queue<Edge, std::vector<Edge>, decltype(cmp)> lambda_pq;

    min_pq.push(10);
    dij_pq.emplace(0, 0);
    lambda_pq.push(Edge{1, 5});
}
\end{lstlisting}

\section{Constrained Algorithms (\texttt{std::ranges}) and Projections}
% ============================================================================

\whybeat Classic \texttt{std::sort(v.begin(), v.end())} is verbose and allows mismatched iterator pairs from two different containers. C++20 \textbf{constrained algorithms} (\texttt{std::ranges::*}) accept whole ranges, validate Concepts for readable error messages, and accept \textbf{projections} so you can sort by struct members (\texttt{\&Player::score}) without writing comparator lambdas.

\begin{xltabular}{\textwidth}{>{\raggedright\arraybackslash\ttfamily}p{4.3cm} >{\raggedright\arraybackslash}X >{\raggedright\arraybackslash}p{3.1cm}}
\arrayrulecolor{primaryblue}\toprule[1.1pt]
\rowcolor{primaryblue!10}
\textcolor{primaryblue}{\normalfont\bfseries Algorithm (\texttt{<algorithm>})} & \textcolor{primaryblue}{\textbf{Plain-English Behavior}} & \textcolor{primaryblue}{\textbf{Complexity}} \\
\arrayrulecolor{codeframe}\midrule[0.6pt]
\endhead
\arrayrulecolor{primaryblue}\bottomrule[1.1pt]
\endfoot
ranges::any\_of / all\_of / none\_of & Check if any, all, or no elements satisfy predicate. & $O(N)$ \\
ranges::count / count\_if & Count elements matching value or predicate. & $O(N)$ \\
ranges::find / find\_if / contains & Find first match (\texttt{contains} is C++23). & $O(N)$ \\
ranges::mismatch / equal & Compare two ranges element-by-element. & $O(N)$ \\
ranges::copy\_if / transform & Filter or map elements into an output range. & $O(N)$ \\

\begin{lstlisting}[caption={Projections (\texttt{\&Player::score}) and C++23 \texttt{std::ranges::fold\_left} (\texttt{<algorithm>})}]
#include <algorithm>
#include <functional>
#include <string>
#include <vector>

struct Player {
    std::string name;
    int score;
};

void ranges_and_folds() {
    std::vector<Player> players = {{"Alice", 50}, {"Bob", 80}, {"Charlie", 40}};

    // Projection sorts by Player::score without a lambda
    std::ranges::sort(players, std::less<>{}, &Player::score);
    auto best = std::ranges::max_element(players, {}, &Player::score);

    // C++23 fold_left lives in <algorithm> (not <numeric>!)
    int total = std::ranges::fold_left(players, 0, [](int acc, const Player& p) {
        return acc + p.score;
    });
    (void)best;
    (void)total;
}
\end{lstlisting}

\subsection{\texttt{<bit>} Operations, \texttt{std::bitset}, and Safe Infinity}

Every function in \texttt{<bit>} requires an \textbf{unsigned integer} (\texttt{std::unsigned\_integral})---passing a signed \texttt{int} will not compile! Note carefully that \texttt{std::bit\_width(0u) == 0} (the $\lfloor \log_2 x \rfloor + 1$ formula applies only for $x > 0$).

\begin{lstlisting}[caption={Modules 09--12 idioms: \texttt{<bit>}, \texttt{std::bitset}, safe \texttt{INF}, and C++23 deducing \texttt{this}}]
#include <bit>
#include <bitset>
#include <cstdint>
#include <limits>
#include <vector>

void modern_module_idioms() {
    // 1. Safe sentinel infinity (prevents INF + INF signed overflow UB in DP / Dijkstra)
    constexpr std::int64_t INF = std::numeric_limits<std::int64_t>::max() / 2;

    // 2. <bit> + 64-bit shift safety (always 1ULL << k for k < 64)
    std::uint64_t mask = (1ULL << 40) | (1ULL << 3);
    int lowest_idx = std::countr_zero(mask); // 3
    int bits_used = std::bit_width(0U);      // 0 (not -1!)

    // 3. std::bitset for fixed-size >64-bit DP / Subset-Sum acceleration (64x speedup)
    std::bitset<256> reachable;
    reachable.set(0);
    reachable |= (reachable << 7); // Add item of weight 7 in O(W / 64)

    // 4. C++23 Deducing 'this' for zero-overhead recursive lambdas (replaces std::function)
    std::vector<std::vector<int>> adj(4);
    std::vector<bool> vis(4, false);
    auto dfs = [&](this auto&& self, int u) -> void {
        vis[u] = true;
        for (int v : adj[u]) {
            if (!vis[v]) self(v);
        }
    };
    dfs(0);
    (void)INF; (void)lowest_idx; (void)bits_used;
}
\end{lstlisting}

\section{Lazy Ranges and View Pipelines (\texttt{std::views})}

\section{Strings, \texttt{std::string\_view}, and Formatting}
% ============================================================================

\whybeat \textbf{\texttt{std::string\_view} (Module~09):} Calling \texttt{s.substr(pos, len)} on a \texttt{std::string} copies bytes and allocates on the heap ($O(L)$). \texttt{std::string\_view} is just a \texttt{(const char*, size\_t)} pair: slicing with \texttt{substr}, \texttt{remove\_prefix}, and \texttt{remove\_suffix} runs in $O(1)$ with zero heap allocations!

\begin{watchoutbox}[Watch Out --- Dangling \texttt{std::string\_view} Lifetime]
Because \texttt{std::string\_view} does \textbf{not} own its characters, never store or return a \texttt{string\_view} pointing to a temporary \texttt{std::string} (e.g., \texttt{std::string\_view sv = get\_temp\_string();}). Once the temporary dies at the semicolon, reading \texttt{sv} is instant Undefined Behavior!
\end{watchoutbox}

#include <cstdint>
#include <functional>
#include <iostream>
#include <unordered_map>
#include <utility>

void enable_fast_io() {

    std::cin.tie(nullptr);

struct PairHash {
    template <typename T1, typename T2>
    [[nodiscard]] std::size_t operator()(const std::pair<T1, T2>& p) const noexcept {
        const std::size_t h1 = std::hash<T1>{}(p.first);
        const std::size_t h2 = std::hash<T2>{}(p.second);
        return h1 ^ (h2 + 0x9e3779b97f4a7c15ULL + (h1 << 6) + (h1 >> 2));
    }
};

\begin{calloutbox}{When to Use What? (Rapid Triage)}
\begin{itemize}[itemsep=2pt]
    \item \textbf{Default contiguous array}: \texttt{std::vector} (call \texttt{reserve(N)} when final size is known).
    \item \textbf{Zero-copy function parameter}: \texttt{std::span<const T>} for arrays; \texttt{std::string\_view} for read-only text.
    \item \textbf{Mutate / sort / search in place}: \texttt{std::ranges::*} with member projections (\texttt{\&Item::key}).
    \item \textbf{Lazy filter / transform / take pipeline}: \texttt{std::views::*} chained with \texttt{|}.
    \item \textbf{Min-heap / custom priority}: \texttt{std::priority\_queue<T, std::vector<T>, std::greater<>>}.
    \item \textbf{Bit counts, shifts, powers of two}: \texttt{<bit>} on unsigned types + \texttt{1ULL << k}.
\end{itemize}
\end{calloutbox}

\begin{enumerate}[itemsep=3pt]
    \item \label{sol:ex1}\textbf{Exercise 1 (Triage) --- Pick the Right C++23 Container or View:}
    (1) \texttt{std::span<const int>} (non-owning contiguous view).
    (2) \texttt{std::deque<int>} ($O(1)$ push/pop at both front and back).
    (3) C++23 \textbf{deducing \texttt{this}} lambda: \texttt{auto dfs = [\&](this auto\&\& self, int u) -> void \{ ... \};}.
    \trapnote{Defaulting to \texttt{const std::vector<int>\&} forces callers holding a \texttt{std::array} or sub-slice to copy data onto the heap.}

    \item \label{sol:ex2}\textbf{Exercise 2 (Debug) --- Spot Three Silent C++23 UB Traps:}
    (1) Dangling \texttt{string\_view}: the temporary \texttt{std::string} is destroyed at the semicolon, leaving \texttt{name} pointing at freed memory.
    (2) Pointer invalidation: \texttt{v.push\_back(3)} doubles capacity and frees the old buffer, making \texttt{p} dangle!
    (3) Signed 32-bit shift UB: \texttt{1} is a 32-bit \texttt{int}, so \texttt{1 << 40} is UB before assignment to \texttt{uint64\_t}. Fix: \texttt{1ULL << 40}.
    \trapnote{All three bugs compile cleanly without warnings on default compiler flags and may even appear to work on small tests!}

    \item \label{sol:ex3}\textbf{Exercise 3 (Edge Cases) --- Header and Boundary Checks:}
    (1) \texttt{<algorithm>} (unlike classic \texttt{std::accumulate} in \texttt{<numeric>}).
    (2) \texttt{std::bit\_width(0u)} returns \textbf{0}; \texttt{std::popcount(-1)} fails because \texttt{<bit>} functions require \texttt{std::unsigned\_integral} arguments.
    (3) \texttt{std::vector} has no \texttt{.subspan()} member function; wrap it first: \texttt{std::span\{vec\}.subspan(0, 2)}.
    \trapnote{Subtracting $1$ from \texttt{std::bit\_width(0u)} in an unsigned variable wraps to \texttt{UINT\_MAX}---always check $x == 0$ first.}
\end{enumerate}
