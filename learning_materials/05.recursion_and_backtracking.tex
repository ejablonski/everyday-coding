% ============================================================================
\section{Foundations: The Call Stack and Recursion}
% ============================================================================

Before writing a single recursive function, you need a crisp mental model of \emph{where} paused function calls live in memory and \emph{why} they resume in reverse order.

\begin{notationbox}[Symbols Used in Section 1]
    $n$ & Problem size passed to the current recursive call & \texttt{fac(4)} has $n = 4$ \\
    $d$ & Peak recursion depth (maximum live frames on the stack) & $d = n$ for linear recursion \\
    $f$ & Memory size of one stack frame (locals + return address) & Typically $32$--$128$ bytes \\
    $O(b^d)$ & Tree size with branching factor $b$ and depth $d$ & $O(2^n)$ for naive \texttt{fib(n)} \\
\end{notationbox}

\subsection{The Call Stack: Recursion Is Literally an Implicit Stack}

\painbeat When function $A$ calls function $B$ and $B$ calls $C$, the CPU must remember each paused function's local variables and exact line number so it can resume seamlessly once the inner call returns.

\ahabeat Your program maintains a hardware-managed \textbf{call stack} of \textbf{stack frames} (think of sticky notes stacked vertically). Calling a function \emph{pushes} a fresh sticky note on top; returning \emph{pops} the top note and resumes the note immediately underneath (Last-In, First-Out).

\examplebeat Tracing \texttt{fac(4)} (where $n! = n \times (n - 1)!$ and $1! = 1$): the CPU pushes four sticky notes downward (\texttt{fac(4)} $\to$ \texttt{fac(3)} $\to$ \texttt{fac(2)} $\to$ \texttt{fac(1)}), hits the base case $1$, and unwinds upward, multiplying $1 \to 2 \to 6 \to 24$ (Figure~\ref{fig:call-stack}).

\begin{watchoutbox}[Watch Out --- Stack Overflow on Deep Recursion]
Default OS stack limits are typically $1$--$8$ MB. If each frame takes $f \approx 100$ bytes, depth $d = 10{,}000$ consumes $\approx 1$ MB---already near the crash limit! For linear recursion deeper than $\sim 10^4$, rewrite using an iterative loop or an explicit heap-allocated \texttt{std::vector} stack.
\end{watchoutbox}

\subsection{Recursion and the Three Laws}

\textbf{Recursion} is simply a function calling itself on a strictly smaller subproblem. Every valid recursive function must satisfy three non-negotiable laws:
\begin{enumerate}
    \item \textbf{Base case:} A direct stopping condition that returns without recursing.
    \item \textbf{Strict progress:} Every recursive call moves the state strictly closer to a base case.
    \item \textbf{Self-delegation:} Combine the smaller subproblem's return value into the answer for the current call.
\end{enumerate}

\begin{tryitbox}{Trace}{Unwinding the Call Stack for power(2, 4)}{ex1}
Trace \texttt{power(b, e)} defined by \texttt{power(b, 0) = 1} and \texttt{power(b, e) = b * power(b, e - 1)} for \texttt{power(2, 4)}. List every frame pushed during descent, state the peak stack depth, and list the return values as each frame pops.
\end{tryitbox}

\subsection{Recursion Trees and Redundant Work}

\painbeat When a function makes \emph{two or more} recursive calls per invocation (branching factor $b \ge 2$), the call trace fans out into an exponential \textbf{recursion tree}.

\ahabeat Drawing the tree immediately exposes whether subproblems are \emph{independent} (good for divide-and-conquer / backtracking) or \emph{repeated} (signals Dynamic Programming).

\examplebeat For Fibonacci $\text{fib}(n) = \text{fib}(n-1) + \text{fib}(n-2)$ with $\text{fib}(0) = 0, \text{fib}(1) = 1$, Figure~\ref{fig:fib-tree} reveals that \texttt{fib(4)} computes \texttt{fib(2)} completely from scratch \emph{twice} and \texttt{fib(1)} \emph{three times}!

% ============================================================================
\section{Backtracking: Choose, Explore, Undo}
% ============================================================================

When you must \emph{list every valid configuration} (or find one valid puzzle layout), recursion becomes \textbf{backtracking}: a depth-first walk through a decision tree that cuts off hopeless branches immediately.

\begin{notationbox}[Symbols Used in Section 2]
    State tuple & Minimal live state describing the current decision node & \texttt{(current, open, close)} \\
    $b,\; d$ & Branching factor (choices per node) and maximum depth & $b = 2,\; d = 2n$ for brackets \\
    $C_n$ & $n$-th Catalan number $\frac{1}{n+1}\binom{2n}{n}$ (valid bracket strings) & $C_2 = 2,\; C_3 = 5,\; C_8 = 1{,}430$ \\
    $\times$ & Pruned branch aborted immediately upon violating a constraint & Dashed red node in trees \\
\end{notationbox}

\subsection{Backtracking vs.\ Brute Force}

\painbeat Naive brute force builds \emph{every} possible sequence to full length and filters at the end. For Generate Parentheses with $n = 8$, brute force constructs all $2^{16} = 65{,}536$ bracket strings even though only $C_8 = 1{,}430$ are valid!

\ahabeat Check constraints \textbf{at every step} as you extend a partial candidate. The instant a partial prefix becomes impossible to complete (like starting with \texttt{')'}), abandon that entire subtree immediately (\textbf{pruning})!

\examplebeat Imagine exploring a maze: pick a corridor, walk down it, and the moment you hit a brick wall, step back to the junction (\textbf{undo}) and try the next corridor. You never walk past a dead end.

\subsection{The Universal Backtracking Template}

\painbeat Copying a partial array or string on every recursive call burns $O(d)$ memory per active frame ($O(d^2)$ total) and slows allocation dramatically.

\ahabeat Share \textbf{one mutable state buffer} (e.g., \texttt{current}) across the entire recursion! Before recursing into a child, mutate \texttt{current}; immediately after the call returns, undo that exact mutation so \texttt{current} is restored for the next sibling.

\begin{formulabox}[The Universal Choose $\to$ Explore $\to$ Undo Template]
\begin{verbatim}
void backtrack(State& state, ChoiceParams params, Results& results) {
    if (is_complete(state)) {          // 1. Base case: valid full solution
        results.push_back(state);
        return;
    }
    for (const auto& choice : candidates(params)) {
        if (!is_feasible(state, choice)) continue;   // 2. Prune early!
        apply(state, choice);                        // 3. Choose
        backtrack(state, next_params(choice), results); // 4. Explore
        undo(state, choice);                         // 5. Undo (rollback)
    }
}
\end{verbatim}
\textbf{Read this as:} ``Check if done; otherwise try each legal next move, recurse deeper, and cleanly roll back your move before trying the sibling move.''
\end{formulabox}

\invariantbeat{Backtracking Rollback} Upon returning from any call \texttt{backtrack(state, ...)}, the shared \texttt{state} buffer contains the \textbf{exact same elements} it held right before the call began.

\subsection{Two Kinds of Pruning}

\textbf{Pruning} stops a recursive branch before it reaches a leaf. Every pruning rule falls into one of two categories:
\begin{itemize}
    \item \textbf{Hard Feasibility Constraint:} Violating it makes every descendant invalid (e.g., \texttt{close > open}, or two queens on the same diagonal). Always safe and always speeds up search.
    \item \textbf{Optimality Bound (Branch-and-Bound):} The partial path is legal, but even its best-case completion cannot beat the best solution already found (e.g., current path cost $\ge \text{best\_cost}$).
\end{itemize}

\begin{enumerate}

    \item You may append \texttt{')'} only if $\text{close} < \text{open}$ (otherwise you create an unmatched closer).
\end{enumerate}

\section{Key Algorithmic Patterns: Canonical Families \& Duplicates}
% ============================================================================

Almost every combinatorial search problem is a slight twist on one of four canonical backtracking skeletons: \textbf{Subsets}, \textbf{Combinations}, \textbf{Permutations}, or \textbf{Constraint Satisfaction (N-Queens)}.

\begin{notationbox}[Symbols Used in Section 3]
    \texttt{start} & Leftmost index still eligible to pick (enforces ascending order) & Prevents $[2,1]$ after $[1,2]$ \\
    \texttt{used[i]} & Boolean flag marking whether \texttt{nums[i]} is on the current path & Used in Permutations \\
    $d_1,\; d_2$ & N-Queens main ($r - c + n - 1$) and anti-diagonal ($r + c$) IDs & $d_1, d_2 \in [0, 2n - 2]$ \\
\end{notationbox}

\subsection{Why Naive Filtering Fails: Before vs.\ After}

Imagine finding valid permutations of $n = 10$ elements where placing \texttt{5} first violates a rule. There are $10! = 3{,}628{,}800$ permutations (and $12! \approx 4.79 \times 10^8$). Naive generate-and-filter builds all $9! = 362{,}880$ doomed permutations starting with \texttt{5}, whereas backtracking discards that entire $362{,}880$-leaf subtree in $O(1)$ time!

\begin{itemize}
    \item \textbf{Subsets (Power Set):} For each element, either \emph{include} it or \emph{exclude} it ($2^n$ leaves, Figure~\ref{fig:subsets-tree}).
    \item \textbf{Combinations ($\binom{n}{k}$):} Order does not matter, so passing \texttt{start = i + 1} guarantees strictly increasing picks (never generating both $[1, 2]$ and $[2, 1]$).
    \item \textbf{Permutations ($n!$):} Order matters and every element is used once. Without a \texttt{used} array you would pick the same index twice and generate $n^n$ \textbf{permutations with repetition} instead of $n!$ permutations!
\end{itemize}

\subsection{Handling Duplicate Elements Without a Hash Set}

\painbeat When the input has repeated values like \texttt{[1, 2, 2]}, standard backtracking treats the two \texttt{2}s at indices $1$ and $2$ as distinct and emits duplicate outputs like \texttt{[1, 2]} twice. Dumping outputs into a \texttt{std::set} wastes both time and memory.

\ahabeat \textbf{Sort the input first} (\texttt{std::ranges::sort(nums)}) so identical values sit side-by-side. Then enforce one simple symmetry-breaking rule: \emph{never start a new sibling branch with a value identical to a sibling you already finished exploring at the same depth!}

\begin{formulabox}[The Two Duplicate-Skipping Rules (After Sorting)]
\begin{itemize}
    \item \textbf{Subsets II / Combinations II (uses \texttt{start}):}
    \quad \texttt{if (i > start \&\& nums[i] == nums[i - 1]) continue;}
    \item \textbf{Permutations II (uses \texttt{used}):}
    \quad \texttt{if (i > 0 \&\& nums[i] == nums[i - 1] \&\& !used[i - 1]) continue;}
\end{itemize}
\textbf{Read this as:} ``At any single loop level, if \texttt{nums[i]} equals the previous element \emph{and that previous element is not currently active above us}, skip \texttt{nums[i]} because its entire subtree was already explored!''
\end{formulabox}

\begin{watchoutbox}[Watch Out --- \texttt{i > start} vs.\ \texttt{i > 0} in Subsets II]
Writing \texttt{if (i > 0 \&\& nums[i] == nums[i - 1])} inside Subsets II is a famous bug! When \texttt{i == start}, you are at a \emph{deeper} recursion level where the first \texttt{2} was \textbf{chosen}---you \emph{must} allow picking the second \texttt{2} to form \texttt{[1, 2, 2]} and \texttt{[2, 2]}. Only skip when \texttt{i > start} (sibling level)!
\end{watchoutbox}

\begin{example}[Recursive Factorial: Computing $4!$]
Trace \texttt{factorial(4)} through descent and unwinding:
\begin{enumerate}
    \item \texttt{factorial(4)} $\to$ waits for \texttt{4 * factorial(3)}.
    \item \texttt{factorial(3)} $\to$ waits for \texttt{3 * factorial(2)}.
    \item \texttt{factorial(2)} $\to$ waits for \texttt{2 * factorial(1)}.
    \item \texttt{factorial(1)} hits the base case and returns $1$.
    \item Unwind: \texttt{factorial(2)} $= 2 \times 1 = 2 \to$ \texttt{factorial(3)} $= 3 \times 2 = 6 \to$ \texttt{factorial(4)} $= 4 \times 6 = \mathbf{24}$.
\end{enumerate}
\end{example}

\begin{example}[Generate Parentheses for $n = 3$]
The number of valid $n$-pair bracket strings equals the $n$-th Catalan number $C_n = \frac{1}{n+1}\binom{2n}{n}$. For $n = 3$, $C_3 = \frac{1}{4}\binom{6}{3} = \mathbf{5}$. Choosing \texttt{'('} before \texttt{')'} visits them in exact lexicographical order:
\[
    \texttt{((()))},\qquad \texttt{(()())},\qquad \texttt{(())()},\qquad \texttt{()(())},\qquad \texttt{()()()}.
\]
Notice that brute force would test all $2^6 = 64$ strings, whereas constraint pruning (\texttt{open < 3}, \texttt{close < open}) never generates a single unbalanced prefix.
\end{example}

\section{C++23 Implementations}
% ============================================================================

All listings below are standalone modern \textbf{C++23}, avoid C-style casts, guard domain boundaries (such as $n = 0$ or negative inputs), use \texttt{std::ranges::sort} for duplicate elimination, and compile cleanly under \texttt{-std=c++23 -Wall -Wextra}.

\subsection{Simple Recursion: Domain-Guarded Factorial}

Because $21! > 2^{63} - 1$ overflows signed 64-bit integers and negative inputs lack a standard factorial, returning \texttt{std::optional<std::int64\_t>} makes invalid domains impossible to miss silently.

\begin{lstlisting}[caption={Domain-Guarded Recursive Factorial in C++23}]
#include <cstdint>
#include <optional>

[[nodiscard]] constexpr std::optional<std::int64_t> factorial(int n) noexcept {
    if (n < 0 || n > 20) return std::nullopt; // Guard negative inputs and 64-bit overflow
    if (n <= 1) return 1;
    return static_cast<std::int64_t>(n) * (*factorial(n - 1));
}
\end{lstlisting}

\subsection{Constraint-Based Backtracking: Generate Parentheses}

At each recursion depth (at most $2n$), only branch into \texttt{'('} when \texttt{open < n} and into \texttt{')'} when \texttt{close < open}. Guard \texttt{n < 0} cleanly at entry.

\begin{lstlisting}[caption={Generate Parentheses with Constraint Pruning}]
#include <string>
#include <vector>

void backtrack_parentheses(int n, int open, int close,
                           std::string& current,
                           std::vector<std::string>& result) {
    if (open == n && close == n) {
        result.push_back(current);
        return;
    }

    if (open < n) {
        current.push_back('(');
        backtrack_parentheses(n, open + 1, close, current, result);
        current.pop_back();
    }

    if (close < open) {
        current.push_back(')');
        backtrack_parentheses(n, open, close + 1, current, result);
        current.pop_back();
    }
}

[[nodiscard]] std::vector<std::string> generate_parenthesis(int n) {
    if (n < 0) return {};
    std::vector<std::string> result;
    std::string current;
    current.reserve(static_cast<std::size_t>(2 * n));
    backtrack_parentheses(n, 0, 0, current, result);
    return result;
}
\end{lstlisting}

\subsection{Subsets (Unique Input) and Subsets II (With Duplicates)}

Every prefix reached in the loop-based subset tree is itself a valid subset, so we push \texttt{current} on entry. For \textbf{Subsets II}, sorting with \texttt{std::ranges::sort} puts duplicates adjacent so \texttt{if (i > start \&\& nums[i] == nums[i - 1]) continue;} eliminates duplicate subsets with zero hash-set overhead.

\begin{lstlisting}[caption={Subsets (Power Set) on Distinct Elements}]
#include <cstddef>
#include <span>
#include <vector>

void backtrack_subsets(std::span<const int> nums, std::size_t start,
                       std::vector<int>& current,
                       std::vector<std::vector<int>>& result) {
    result.push_back(current);

    for (std::size_t i = start; i < nums.size(); ++i) {
        current.push_back(nums[i]);
        backtrack_subsets(nums, i + 1, current, result);
        current.pop_back();
    }
}

[[nodiscard]] std::vector<std::vector<int>> subsets(std::span<const int> nums) {
    std::vector<std::vector<int>> result;
    std::vector<int> current;
    backtrack_subsets(nums, 0, current, result);
    return result;
}
\end{lstlisting}

\begin{lstlisting}[caption={Subsets II: Deduplicating Repeated Elements via std::ranges::sort}]

#include <cstddef>

#include <vector>

                           std::vector<int>& current,
                           std::vector<std::vector<int>>& result) {
    result.push_back(current);

    for (std::size_t i = start; i < nums.size(); ++i) {
        if (i > start && nums[i] == nums[i - 1]) {
            continue; // Skip equal sibling already explored at this depth
        }
        current.push_back(nums[i]);
        backtrack_subsets_dup(nums, i + 1, current, result);
        current.pop_back();
    }
}

[[nodiscard]] std::vector<std::vector<int>> subsets_with_dup(std::vector<int> nums) {
    std::ranges::sort(nums);
    std::vector<std::vector<int>> result;
    std::vector<int> current;
    backtrack_subsets_dup(nums, 0, current, result);
    return result;
}
\end{lstlisting}

\subsection{Permutations (Unique Input) and Permutations II (With Duplicates)}

Permutations use a \texttt{used} flag array (\texttt{std::vector<char>}) to prevent reusing an index. For \textbf{Permutations II}, sorting plus \texttt{!used[i - 1]} forces identical copies to be selected in strict left-to-right index order, eliminating every repeated permutation.

\begin{lstlisting}[caption={Permutations on Distinct Elements}]
#include <cstddef>
#include <span>
#include <vector>

void backtrack_permutations(std::span<const int> nums,
                            std::vector<char>& used,
                            std::vector<int>& current,
                            std::vector<std::vector<int>>& result) {
    if (current.size() == nums.size()) {
        result.push_back(current);
        return;
    }

    for (std::size_t i = 0; i < nums.size(); ++i) {
        if (used[i]) continue;
        used[i] = 1;
        current.push_back(nums[i]);
        backtrack_permutations(nums, used, current, result);
        current.pop_back();
        used[i] = 0;
    }
}

[[nodiscard]] std::vector<std::vector<int>> permutations(std::span<const int> nums) {
    std::vector<std::vector<int>> result;
    std::vector<int> current;
    std::vector<char> used(nums.size(), 0);
    backtrack_permutations(nums, used, current, result);
    return result;
}
\end{lstlisting}

\begin{lstlisting}[caption={Permutations II: Unique Permutations with Duplicate Input Elements}]
#include <algorithm>
#include <cstddef>
#include <span>
#include <vector>

void backtrack_unique_perms(std::span<const int> nums,
                            std::vector<char>& used,
                            std::vector<int>& current,
                            std::vector<std::vector<int>>& result) {
    if (current.size() == nums.size()) {
        result.push_back(current);
        return;
    }

    for (std::size_t i = 0; i < nums.size(); ++i) {
        if (used[i]) continue;
        if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) {
            continue; // Enforce left-to-right order among identical values
        }
        used[i] = 1;
        current.push_back(nums[i]);
        backtrack_unique_perms(nums, used, current, result);
        current.pop_back();
        used[i] = 0;
    }
}

[[nodiscard]] std::vector<std::vector<int>> unique_permutations(std::vector<int> nums) {
    std::ranges::sort(nums);
    std::vector<std::vector<int>> result;
    std::vector<int> current;
    std::vector<char> used(nums.size(), 0);
    backtrack_unique_perms(nums, used, current, result);
    return result;
}
\end{lstlisting}

\subsection{Combinations with Remaining-Elements Pruning}

Instead of blindly looping \texttt{i} up to \texttt{n}, compute \texttt{need = k - current.size()}. Any pick larger than \texttt{n - need + 1} leaves too few numbers remaining to reach size $k$ and is pruned immediately.

\begin{lstlisting}[caption={Combinations (n choose k) with Remaining-Elements Pruning}]
#include <cstddef>
#include <vector>

void backtrack_combinations(int n, int k, int start,
                            std::vector<int>& current,
                            std::vector<std::vector<int>>& result) {
    const int need = k - static_cast<int>(current.size());
    if (need == 0) {
        result.push_back(current);
        return;
    }

    // Prune tail: at least 'need' elements must remain in [i, n]
    const int max_pick = n - need + 1;
    for (int i = start; i <= max_pick; ++i) {
        current.push_back(i);
        backtrack_combinations(n, k, i + 1, current, result);
        current.pop_back();
    }
}

[[nodiscard]] std::vector<std::vector<int>> combinations(int n, int k) {
    if (n < 0 || k < 0 || k > n) return {};
    std::vector<std::vector<int>> result;
    std::vector<int> current;
    current.reserve(static_cast<std::size_t>(k));
    backtrack_combinations(n, k, 1, current, result);
    return result;
}
\end{lstlisting}

\subsection{N-Queens Constraint Satisfaction}

Tracking used columns and both diagonals in \textbf{$O(N)$-space lookup arrays} delivers \textbf{$O(1)$-time} attack checks: all cells on a main diagonal share constant $r - c$ (shifted by $+(n - 1)$ into $[0, 2n - 2]$), and all cells on an anti-diagonal share constant $r + c$. Guarding \texttt{n <= 0} prevents \texttt{2 * n - 1} from underflowing to a negative size.

\begin{lstlisting}[caption={N-Queens with O(1) Lookup Checks and Zero-Size Guard}]
#include <cstddef>
#include <string>
#include <vector>

void backtrack_queens(int row, int n, std::vector<std::string>& board,
                      std::vector<char>& cols,
                      std::vector<char>& diag1,
                      std::vector<char>& diag2,
                      std::vector<std::vector<std::string>>& result) {
    if (row == n) {
        result.push_back(board);
        return;
    }

    for (int col = 0; col < n; ++col) {
        const auto c  = static_cast<std::size_t>(col);
        const auto d1 = static_cast<std::size_t>(row - col + n - 1);
        const auto d2 = static_cast<std::size_t>(row + col);

        if (!cols[c] && !diag1[d1] && !diag2[d2]) {
            board[static_cast<std::size_t>(row)][c] = 'Q';
            cols[c] = diag1[d1] = diag2[d2] = 1;

            backtrack_queens(row + 1, n, board, cols, diag1, diag2, result);

            board[static_cast<std::size_t>(row)][c] = '.';
            cols[c] = diag1[d1] = diag2[d2] = 0;
        }
    }
}

[[nodiscard]] std::vector<std::vector<std::string>> solve_n_queens(int n) {
    if (n <= 0) return {}; // Prevent 2 * n - 1 underflow!

    const auto sz = static_cast<std::size_t>(n);
    std::vector<std::vector<std::string>> result;
    std::vector<std::string> board(sz, std::string(sz, '.'));
    std::vector<char> cols(sz, 0);
    std::vector<char> diag1(2 * sz - 1, 0);
    std::vector<char> diag2(2 * sz - 1, 0);

    backtrack_queens(0, n, board, cols, diag1, diag2, result);
    return result;
}
\end{lstlisting}

\end{tryitbox}

\section{Problem Pattern Recognition}
% ============================================================================

Use this three-step filter to decide whether a problem truly calls for backtracking or belongs in Dynamic Programming, Combinatorics, or an iterative stack.

\subsection*{Step 1: What Kind of Answer Does the Problem Ask For?}
\begin{itemize}
    \item \textbf{``Generate ALL valid subsets / permutations / boards''} $\implies$ \textbf{Backtracking} (you must construct every output).
    \item \textbf{``Count how many ways'' (without listing them)} $\implies$ Prefer \textbf{Dynamic Programming} or \textbf{Combinatorics formulas} (Modules 01 and 06); enumerating every configuration is exponentially slower.
    \item \textbf{``Find ANY ONE valid arrangement''} $\implies$ \textbf{Backtracking with early exit} (return \texttt{bool} and unwind immediately on first success).
\end{itemize}

\subsection*{Step 2: What Is the Key Constraint?}
\begin{itemize}
    \item \textbf{Input size $n \le 20$:} $O(2^n)$ subsets/combinations pass easily.
    \item \textbf{Input size $n \le 10$:} $O(n!)$ permutations ($10! \approx 3.6 \times 10^6$) or heavily pruned constraint puzzles ($N \le 13$ for N-Queens) are feasible.
    \item \textbf{Repeated input elements:} Sort first (\texttt{std::ranges::sort}) and skip equal siblings (\texttt{i > start} or \texttt{!used[i - 1]}).
    \item \textbf{Deep linear recursion ($d > 10^4$):} Switch to an iterative loop with an explicit \texttt{std::vector} stack to avoid stack overflow.
\end{itemize}

\subsection*{Step 3: Is the Input Too Large for Exponential Search?}
If $n \ge 30$ without severe constraint pruning (or $n = 100$ asking for subset sums), pure $O(2^n)$ backtracking will time out ($2^{100}$ exceeds the age of the universe). Pivot to Dynamic Programming, Meet-in-the-Middle, or Greedy.

\section{Glossary}
% ============================================================================

\subsection*{Core Concepts}
\begin{itemize}
    \item \textbf{Backtracking:} Depth-first search over a decision tree that rolls back choices and abandons invalid branches early.
    \item \textbf{Base Case:} Direct stopping condition that terminates recursive descent without further self-calls.
    \item \textbf{Branching Factor ($b$):} Number of candidate choices generated from a single decision-tree node.
    \item \textbf{Call Stack:} LIFO runtime memory structure holding active function frames during execution.
    \item \textbf{Combination:} Unordered selection of $k$ distinct items from $n$ (order ignored: $\{1, 2\} = \{2, 1\}$).
    \item \textbf{Constraint / Feasibility Check:} Rule tested before recursing to discard invalid partial states immediately.
    \item \textbf{Decision Tree:} Tree diagram mapping every choice made along paths of a backtracking search.
    \item \textbf{N-Queens:} Classic puzzle placing $N$ non-attacking queens on an $N \times N$ chessboard.
    \item \textbf{Permutation:} Ordered arrangement of elements ($[1, 2] \neq [2, 1]$).
    \item \textbf{Pruning:} Cutting off a recursive branch early once a feasibility constraint or optimality bound fails.
    \item \textbf{Recursion:} A function solving a problem by calling itself on strictly smaller subproblems.
    \item \textbf{Recursion Tree:} Diagram of every recursive call made (reveals overlapping subproblems like \texttt{fib(2)}).
    \item \textbf{Search Space:} Full universe of candidate configurations explored (and pruned) by a search algorithm.
    \item \textbf{Stack Frame:} Memory record on the call stack storing one call's parameters, locals, and return point.
    \item \textbf{Stack Overflow:} Runtime crash triggered when live recursion depth exceeds the OS call-stack memory limit.
    \item \textbf{Subset (Power Set):} Any selection of $0$ to $n$ elements from a set ($2^n$ subsets total).
\end{itemize}

\subsection*{Mathematical Symbols}
\begin{itemize}
    \item $n!$: Factorial, product $1 \times 2 \times \dots \times n$ (with $0! = 1$).
    \item $\binom{n}{k}$ or $C(n, k)$: ``$n$ choose $k$'' --- number of $k$-element combinations from $n$ items.
    \item $C_n$: $n$-th Catalan number $\frac{1}{n+1}\binom{2n}{n}$, counting valid $n$-pair bracket strings.
    \item $2^n$: Total number of subsets (power set size) of an $n$-element set.
    \item $b,\; d$: Branching factor and maximum depth of a recursion or decision tree ($O(b^d)$ nodes).
\end{itemize}

    Pushes: \texttt{power(2,4)} $\to$ \texttt{power(2,3)} $\to$ \texttt{power(2,2)} $\to$ \texttt{power(2,1)} $\to$ \texttt{power(2,0)} (peak stack depth $= \mathbf{5}$ frames).

    \trapnote{Reporting peak depth as $4$ instead of $5$---the base-case frame \texttt{e = 0} still occupies a stack slot before returning.}

    \item \label{sol:ex2}\textbf{Exercise 2 (Edge Cases) --- Stack Overflow Budget \& Missing Base Case:}
    \textbf{(1)} $2{,}097{,}152 / 128 = \mathbf{16{,}384}$ frames (depth $\gtrsim 16{,}000$ overflows).

Surviving leaves: \texttt{"(())"} and \texttt{"()()"} ($C_2 = \mathbf{2}$).
    \trapnote{Checking \texttt{close < n} instead of \texttt{close < open}, which permits invalid strings like \texttt{")("} and \texttt{"())("}.}

    \item \label{sol:ex4}\textbf{Exercise 4 (Debug) --- Missing-Undo Bug:}
    \texttt{result} receives \texttt{[]}, \texttt{[1]}, \texttt{[1, 2]}, and then (because $2$ and $1$ were never popped) the root's $i = 1$ step appends $2$ onto \texttt{[1, 2]}, emitting \textbf{\texttt{[1, 2, 2]}} instead of \texttt{[2]}!
    \trapnote{Forgetting that \texttt{current} is passed by reference across all frames---every \texttt{push\_back} must be paired with a matching \texttt{pop\_back} after recursion returns.}

    \item \label{sol:ex5}\textbf{Exercise 5 (Trace) --- Subsets II on \texttt{[1, 2, 2]}:}
    Visit order ($6$ unique subsets): \texttt{[]}, \texttt{[1]}, \texttt{[1, 2]}, \texttt{[1, 2, 2]}, \texttt{[2]}, \texttt{[2, 2]}.
    Skipped iterations: \textbf{(1)} inside \texttt{[1]} (\texttt{start = 1}) at \texttt{i = 2} (avoids second \texttt{[1, 2]}), and \textbf{(2)} at root (\texttt{start = 0}) at \texttt{i = 2} (avoids second \texttt{[2]}).
    \trapnote{Writing \texttt{i > 0} instead of \texttt{i > start}---that blocks the second $2$ at deeper calls and wrongly drops \texttt{[1, 2, 2]} and \texttt{[2, 2]}.}

    \item \label{sol:ex6}\textbf{Exercise 6 (Twist) --- Early-Exit Backtracking:}
    Change return type to \texttt{bool}. Return \texttt{true} at \texttt{row == n}. Inside the loop: \texttt{if (backtrack\_queens(row + 1, ...)) return true;} (leaving \texttt{board} intact with the solution). Return \texttt{false} if all columns fail.
    \trapnote{Writing \texttt{return;} inside a \texttt{void} function---that only exits one frame and keeps searching sibling columns instead of halting the whole tree.}

    \item \label{sol:ex7}\textbf{Exercise 7 (Derive) --- Remaining-Elements Pruning Bound:}
    With \texttt{need = 4 - 1 = 3} remaining picks from $[i, 6]$, we need $6 - i + 1 \ge 3 \implies i \le \mathbf{4}$ (so $\{4, 5, 6\}$ still fits). General bound: \texttt{max\_pick = n - (k - current.size()) + 1}.
    \trapnote{Using \texttt{n - k + 1} without subtracting \texttt{current.size()}, which over-prunes deeper levels and misses valid combinations like \texttt{[1, 2, 5, 6]}.}

    \item \label{sol:ex8}\textbf{Exercise 8 (Debug) --- Why \texttt{solveNQueens(0)} Crashes:}
    For $n = 0$, \texttt{2 * n - 1 = -1} (signed \texttt{int}), which implicitly converts to unsigned \texttt{std::size\_t} $= 2^{64} - 1 \approx 1.8 \times 10^{19}$! Trying to allocate $1.8 \times 10^{19}$ bits immediately throws \texttt{std::length\_error} / \texttt{std::bad\_alloc}. Fix: \texttt{if (n <= 0) return \{\};}.
    \trapnote{Assuming a negative \texttt{std::vector} size constructor argument produces an empty vector instead of wrapping to a huge unsigned \texttt{std::size\_t}.}

    \item \label{sol:ex9}\textbf{Exercise 9 (Triage) --- Backtracking vs.\ DP vs.\ Early Exit:}
    \textbf{(1)} \textbf{Backtracking} (sort + skip-equal-sibling + sum pruning): must emit actual subsets and $2^{15} = 32{,}768$ is tiny.
    \textbf{(2)} \textbf{0/1 Knapsack DP} in $O(nT)$: $2^{60}$ backtracking is impossible and only a count is needed.
    \textbf{(3)} \textbf{Backtracking with \texttt{bool} early exit} + row/col/box pruning: stops on first valid board.
    \trapnote{Reaching for backtracking on (2) because it says ``subsets''---whenever $n > 25$ and only a count is requested, use DP or math.}

    \item \label{sol:ex10}\textbf{Exercise 10 (Trace) --- Unique Permutations of \texttt{[1, 1, 2]}:}
    Visit order: \texttt{[1, 1, 2]}, \texttt{[1, 2, 1]}, \texttt{[2, 1, 1]} ($3! / 2! = \mathbf{3}$). The check \texttt{!used[i - 1]} forbids placing the second \texttt{1} while the first \texttt{1} is still unused, locking identical elements into left-to-right index order.
    \trapnote{Forgetting \texttt{std::ranges::sort(nums)} beforehand---\texttt{nums[i] == nums[i - 1]} misses non-adjacent duplicates!}

    \item \label{sol:ex11}\textbf{Exercise 11 (Debug) --- Broken N-Queens Diagonal Indexing:}
    At \texttt{(row = 0, col = 3)}, \texttt{row - col = -3} (negative out-of-bounds UB!). Shift by $+(n - 1)$: \texttt{d1 = row - col + (n - 1)} $\in [0, 2n - 2]$, with array length $\mathbf{2n - 1}$ ($7$ for $n = 4$).
    \trapnote{Allocating diagonal arrays of size $n$ instead of $2n - 1$---there are $2n - 1$ diagonals in each direction.}

    \item \label{sol:ex12}\textbf{Exercise 12 (Twist) --- Combination Sum with Unlimited Reuse:}
    Pass \texttt{i} instead of \texttt{i + 1} to the recursive call (permits reusing \texttt{nums[i]} while keeping picks non-decreasing). Mandatory termination: track \texttt{remaining} target, prune whenever \texttt{nums[i] > remaining} (positive candidates), and stop at \texttt{remaining == 0}.
    \trapnote{Passing \texttt{0} instead of \texttt{i}---that generates order duplicates like \texttt{[2, 2, 3]}, \texttt{[2, 3, 2]}, and \texttt{[3, 2, 2]}.}

    \item \label{sol:ex13}\textbf{Exercise 13 (Edge Cases) --- Boundary Cases Across Templates:}
    \textbf{(1)} \texttt{subsets(\{\})} returns \texttt{\{ \{\} \}} (size \textbf{1}: contains the empty subset, $2^0 = 1$).
    \textbf{(2)} \texttt{combinations(3, 0)} returns \texttt{\{ \{\} \}} (size \textbf{1}); \texttt{combinations(3, 5)} returns \texttt{\{\}} (size \textbf{0}).
    \textbf{(3)} \texttt{solve\_n\_queens(2)} and \texttt{solve\_n\_queens(3)} both return \texttt{\{\}} (size \textbf{0}: no valid placements exist).
    \trapnote{Returning an empty outer vector \texttt{\{\}} instead of \texttt{\{ \{\} \}} for $n = 0$ subsets or $k = 0$ combinations.}

    \item \label{sol:ex14}\textbf{Exercise 14 (Derive) --- Why Subsets Takes $O(n \cdot 2^n)$ Time:}
    For $n = 3$, lengths are $0, 1, 1, 1, 2, 2, 2, 3$ (sum $= 12 = 3 \cdot 2^2$). Pairing every subset $S$ with its complement $U \setminus S$ creates $2^{n-1}$ pairs, each of combined size $|S| + |U \setminus S| = n$. Total elements copied into \texttt{result} $= \mathbf{n \cdot 2^{n-1}} = \Theta(n \cdot 2^n)$.
    \trapnote{Counting only the $2^n$ recursive calls and forgetting the $O(|S|)$ vector copy performed by \texttt{result.push\_back(current)}.}
\end{enumerate}
