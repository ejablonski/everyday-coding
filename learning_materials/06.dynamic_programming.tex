% ============================================================================
\section{Foundations}
% ============================================================================

If you have written a recursive function, you already know how to break a big problem into smaller pieces. Dynamic Programming (DP) adds one decisive idea: \textbf{never solve the exact same subproblem twice}. By remembering subproblem answers in a table, exponential trees collapse into fast linear or quadratic sweeps.

\begin{notationbox}[Symbols Used in Foundations]
\texttt{dp[s]} & Stored optimal answer (cost, count, or boolean) for state $s$ & \texttt{dp[5] = 5} (\texttt{int} / \texttt{int64\_t}) \\
$f(n)$ & Value of the $n$-th subproblem in a recurrence & Fibonacci $f(5) = 5$ \\
$\infty$ (\texttt{INF}) & Safe sentinel representing an impossible or unreached state & \texttt{INT\_MAX / 2} \\
DAG & Directed Acyclic Graph formed by states (nodes) and transitions (edges) & No cycles allowed \\
\end{notationbox}

\subsection{Why Plain Recursion Blows Up}

\painbeat Consider computing the Fibonacci sequence ($f(0) = 0$, $f(1) = 1$, $f(n) = f(n-1) + f(n-2)$) with plain recursion. Calling $f(5)$ computes $f(3)$ twice and $f(2)$ three times, making $2 f(6) - 1 = 15$ total calls. By $f(40)$, plain recursion wastes over \textbf{331 million} calls recalculating the same 41 values!

\ahabeat There are only $n + 1$ distinct inputs between $0$ and $n$. If we save each computed result the first time we see it, every later call becomes an $O(1)$ cache lookup instead of an entire recursive subtree.

\examplebeat For $f(5)$, caching trims the call count from $15$ down to $2(5) - 1 = 9$ calls. For $f(40)$, the call count plunges from $331{,}160{,}281$ to just \textbf{79} calls---a $4$-million-fold speedup!

\subsection{The Two Properties Required for DP}

A problem admits Dynamic Programming when it satisfies two structural properties:

\begin{enumerate}
    \item \textbf{Overlapping Subproblems:} The recursive breakdown hits the exact same parameter tuple repeatedly (like $f(3)$ and $f(2)$ above). If every subproblem is unique---as in Merge Sort---caching buys nothing.
    \item \textbf{Optimal Substructure:} An optimal answer for a larger state can be built directly from optimal answers to smaller states. Everyday analogy: if the cheapest flight from Paris to Tokyo stops in Dubai, then the Paris-to-Dubai leg must itself be the cheapest flight to Dubai.
\end{enumerate}

\begin{watchoutbox}[When Optimal Substructure Breaks]
Suppose you want the \textbf{longest simple path} (no repeated cities) from City A to City C. Knowing the longest path from A to B does \emph{not} help, because that path might already use a city needed on the B-to-C leg! Because the past path cannot be summarized by a tiny state, ordinary DP fails here.
\end{watchoutbox}

\subsection{Core Vocabulary and How to Discover the State}

Every DP design reduces to five concrete pieces:

\begin{itemize}
    \item \textbf{State:} The minimal tuple of variables describing a subproblem (e.g., index $i$, or pair $(i, w)$).
    \item \textbf{Transition (Recurrence):} The formula computing a state from strictly smaller states.
    \item \textbf{Base Case:} Trivial boundary states filled directly without transitions (e.g., $f(0) = 0, f(1) = 1$).
    \item \textbf{Evaluation Order:} A loop sequence guaranteeing every dependency is computed before it is read.
    \item \textbf{Answer State:} The specific cell (or $\max/\min$ over a row) that answers the original question.
\end{itemize}

\begin{calloutbox}{Key Insight: How to Discover the State When Stuck}
Ask yourself one question: \emph{``What is the minimum information from the past I need right now to decide the future?''} Strip away everything else. If you only need the running sum (not which exact numbers created it), then the state is just the sum. Every valid DP is a \textbf{Directed Acyclic Graph (DAG)} whose states are nodes, transitions are directed edges, and evaluation order is a topological sort.
\end{calloutbox}

\begin{tryitbox}{Derive}{Discovering the Frog-Jump State}{ex1}
A frog starts on stone $0$ and wants to reach stone $N-1$ with minimum total energy. From stone $i$, it can jump to $i + 1$ or $i + 2$ at cost $|h_{\text{dest}} - h_i|$.
\begin{enumerate}
    \item Define the minimal 1D state \texttt{dp[i]}, write the transition and base cases.
    \item Compute \texttt{dp[0..3]} by hand for stone heights \texttt{h = [10, 30, 40, 20]}.
\end{enumerate}
\end{tryitbox}

\section{Main Topics}
% ============================================================================

This section introduces the core families of DP problems. For each family, focus on \textbf{what the state summarizes}, \textbf{which cells the transition reads}, and \textbf{why the loop order respects those arrows}.

\subsection{Top-Down Memoization vs.\ Bottom-Up Tabulation}

There are two ways to evaluate any DP DAG. Both visit every reachable state once and share the same time complexity, but they travel the dependency graph in opposite directions.

\begin{itemize}
    \item \textbf{Top-Down Memoization:} Start at the goal state (e.g., $W(n)$) and recurse toward base cases. Before computing, check a cache (such as \texttt{memo[s] != -1}).
    \item \textbf{Bottom-Up Tabulation:} Start at base cases and fill a table iteratively in topological order until you reach the answer state.
\end{itemize}

\begin{calloutbox}{Decision Guide: Memoization vs.\ Tabulation}
\begin{itemize}
    \item Prefer \textbf{Tabulation} by default: zero recursion overhead, no stack-overflow risk at $N = 10^5$, better CPU cache locality, and easy rolling-array space optimization.
    \item Choose \textbf{Memoization} when only a tiny fraction of states is reachable (sparse state space) or when the topological loop order is awkward to write iteratively.
\end{itemize}
\end{calloutbox}

\subsection{The 5-Step Recipe and 1D Linear DP}

\painbeat Beginners often jump straight to coding loops before deciding what \texttt{dp[i]} means, leading to mismatched base cases and off-by-one bugs.

\ahabeat Lock down the \textbf{5-Step Recipe} on paper first: (1) Define the state in plain English, (2) write the transition, (3) set base cases, (4) pick the evaluation order, and (5) identify the answer state.

\examplebeat In the \textbf{House Robber} problem, you maximize loot along a street without robbing two adjacent houses. Defining \texttt{dp[i]} as the best loot from houses $0 \dots i$ gives two choices at house $i$: \textbf{skip} it (keep \texttt{dp[i-1]}) or \textbf{rob} it (add $A[i]$ to \texttt{dp[i-2]}).

\begin{formulabox}[House Robber Transition in Plain English]
$$\texttt{dp[i]} = \max\big(\texttt{dp[i-1]},\; \texttt{dp[i-2]} + A[i]\big)$$
\textbf{Read this as:} The best haul up to house $i$ is the better of leaving house $i$ alone (keeping yesterday's best) or robbing house $i$ plus the best haul from two houses back.
\end{formulabox}

Because \texttt{dp[i]} reads only \texttt{dp[i-1]} and \texttt{dp[i-2]}, we can discard older cells and keep just two rolling variables (\texttt{prev2} and \texttt{prev1}), shrinking memory from $O(N)$ to $O(1)$ (Figure~\ref{fig:dp-1d-tape}).

\subsection{1D DP: Coin Change (Loop Order) and Subsequences}

\begin{notationbox}[Symbols Used in Coin Change \& LIS]
$A$ & Target monetary amount to build from coins & $A = 6$ \\
$c \in C$ & Denomination of a single coin in coin set $C$ & $C = \{1, 3, 4\}$ \\
\texttt{dp[a]} & Minimum coins (or total ways) to make exact amount $a$ & \texttt{dp[0] = 0} (min) or \texttt{1} (ways) \\
\texttt{dp[i]} & Length of Longest Increasing Subsequence ending at index $i$ & Base: \texttt{dp[i] = 1} \\
\end{notationbox}

\painbeat When counting ways to make change for amount $A$ with unlimited coins, swapping two \texttt{for} loops silently changes the answer! Why?

\ahabeat \textbf{Loop order decides whether coin order matters.} Putting coins in the \emph{outer} loop processes every \texttt{1}-coin before any \texttt{2}-coin is ever considered, forcing canonical sorted multisets (\textbf{combinations}). Putting amounts in the \emph{outer} loop allows any coin to be appended at any step, counting distinct ordered sequences (\textbf{permutations}).

\subsection{2D DP on Grids}

\painbeat On an $M \times N$ grid where you can only move \textbf{right} or \textbf{down}, the number of paths grows like $\binom{M+N-2}{M-1}$---already over $10^{11}$ on a $20 \times 20$ grid! Exploring every path with recursion is impossible.

\ahabeat Any path reaching cell $(i, j)$ must step in from either the cell directly \textbf{above} $(i-1, j)$ or directly to the \textbf{left} $(i, j-1)$. Merging all paths that arrive at $(i, j)$ into one optimal cost collapses exponential routes into $M \times N$ cells.

\begin{formulabox}[2D Grid Minimum Path Transition]
$$\texttt{dp[i][j]} = \text{cost}[i][j] + \min\big(\texttt{dp[i-1][j]},\; \texttt{dp[i][j-1]}\big)$$
\textbf{Read this as:} The cheapest route to cell $(i, j)$ pays this cell's toll plus whichever entrance---from above or from the left---was cheaper.
\end{formulabox}

\invariantbeat{2D Grid Row Sweep} Before updating cell $(i, j)$, every cell in row $i-1$ and every cell to the left in row $i$ already holds its final optimal cost.

\subsection{Contiguous Subarrays and Substrings (The ``Ends Exactly At'' Pattern)}

\painbeat Suppose you want the maximum sum of a \textbf{contiguous} subarray. If you define \texttt{dp[i]} as ``the best subarray anywhere inside $0 \dots i$,'' you cannot attach element $i$ cleanly---that earlier best subarray might have ended three indices ago!

\ahabeat Force the state to stay glued to index $i$: define \texttt{dp[i]} as the optimal contiguous segment that \textbf{ends exactly at index $i$}. Now you have just two legal moves: extend the previous segment ending at $i-1$, or start fresh at $i$.

\begin{formulabox}[Kadane's Algorithm (``Ends Exactly At'' Recurrence)]
$$\texttt{dp[i]} = \max\big(A[i],\; \texttt{dp[i-1]} + A[i]\big), \qquad \text{Answer} = \max_{0 \le i < n} \texttt{dp[i]}$$
\textbf{Read this as:} Either discard a dragging negative prefix and start fresh at $A[i]$, or extend the best streak ending right before you.
\end{formulabox}

\examplebeat Tracing Kadane's algorithm on $A = [-2, 1, -3, 4, -1, 2]$:
\begin{enumerate}
    \item $i = 0$ ($-2$): $\texttt{dp[0]} = -2$.
    \item $i = 1$ ($1$): extend ($-2 + 1 = -1$) vs.\ fresh ($1$) $\implies \texttt{dp[1]} = 1$.
    \item $i = 2$ ($-3$): extend ($1 - 3 = -2$) vs.\ fresh ($-3$) $\implies \texttt{dp[2]} = -2$.
    \item $i = 3$ ($4$): extend ($-2 + 4 = 2$) vs.\ fresh ($4$) $\implies \texttt{dp[3]} = 4$.
    \item $i = 4$ ($-1$): extend ($4 - 1 = 3$) vs.\ fresh ($-1$) $\implies \texttt{dp[4]} = 3$.
    \item $i = 5$ ($2$): extend ($3 + 2 = 5$) vs.\ fresh ($2$) $\implies \texttt{dp[5]} = 5$.
\end{enumerate}
The global optimum is $\max(\texttt{dp}) = \mathbf{5}$ (subarray $[4, -1, 2]$). This exact ``ends at $i$'' trick powers Longest Valid Parentheses and Maximum Product Subarray.

\subsection{Two-Sequence DP: LCS and Edit Distance}

\begin{notationbox}[Symbols Used in Two-Sequence DP]
$S_1, S_2$ & Two input strings of lengths $M$ and $N$ & $S_1 = \texttt{"ABCDE"}$, $S_2 = \texttt{"ACE"}$ \\
$S_1[0 \dots i-1]$ & Prefix of $S_1$ containing its first $i$ characters & $i = 0$ means empty string $\emptyset$ \\
\texttt{dp[i][j]} & Optimal LCS length (or Edit Distance) for prefixes of length $i$ and $j$ & Table size $(M+1) \times (N+1)$ \\
\end{notationbox}

\painbeat Aligning two strings of lengths $M$ and $N$ by brute-force subsequence search checks up to $2^M$ subsets---hopeless even for $M = 40$.

\ahabeat Compare the two strings from the end of their prefixes $(i, j)$. Every decision consumes one character from $S_1$, one from $S_2$, or both simultaneously, forming an $(M+1) \times (N+1)$ \textbf{2D DAG} whose edges only move right, down, or diagonally down-right!

\begin{formulabox}[LCS and Edit Distance Transitions]
\textbf{Longest Common Subsequence (LCS):}
$$\texttt{dp[i][j]} = \begin{cases} \texttt{dp[i-1][j-1]} + 1 & \text{if } S_1[i-1] = S_2[j-1], \\ \max(\texttt{dp[i-1][j]},\; \texttt{dp[i][j-1]}) & \text{otherwise.} \end{cases}$$
\textbf{Edit Distance (Levenshtein):}
$$\texttt{dp[i][j]} = \begin{cases} \texttt{dp[i-1][j-1]} & \text{if } S_1[i-1] = S_2[j-1], \\ 1 + \min(\underbrace{\texttt{dp[i-1][j]}}_{\text{delete}},\; \underbrace{\texttt{dp[i][j-1]}}_{\text{insert}},\; \underbrace{\texttt{dp[i-1][j-1]}}_{\text{replace}}) & \text{otherwise.} \end{cases}$$
\textbf{Read this as:} Matching final characters advances both prefixes diagonally; a mismatch pays the best local edit or skips one character from either string.
\end{formulabox}

\subsection{The Knapsack Family: Why 0/1 Loops Backward}

\begin{notationbox}[Symbols Used in Knapsack DP]
$N,\; W$ & Number of items and maximum knapsack weight capacity & $N = 3,\; W = 5$ \\
$w_i,\; v_i$ & Weight and value of item $i$ & $(w_i, v_i) = (2, 3)$ \\
\texttt{dp[i][w]} & Best value using a subset of the first $i$ items within capacity $w$ & 2D table: $O(N \cdot W)$ space \\
\texttt{dp[w]} & Space-optimized 1D array holding best value for capacity $w$ & 1D table: $O(W)$ space \\
\end{notationbox}

\painbeat With $N$ items, trying all subsets takes $O(2^N)$ time. A 2D table \texttt{dp[i][w]} solves it in $O(N \cdot W)$, yet compressing that table to a 1D array \texttt{dp[w]} hides one of DP's most famous traps: \textbf{iterating capacity forward corrupts 0/1 Knapsack!}

\ahabeat In row $i$, computing \texttt{dp[i][w]} reads \texttt{dp[i-1][w - w\_i]} from the \emph{previous} row. When you collapse the table to one array \texttt{dp[w]}, looping \textbf{backward} ($w = W$ down to $w_i$) guarantees that \texttt{dp[w - w\_i]} has not been overwritten yet---so it still holds row $i-1$ (each item used \textbf{at most once}). Looping \textbf{forward} ($w = w_i$ up to $W$) reads the freshly updated row $i$, permitting \textbf{unlimited reuse} (Unbounded Knapsack)!

\begin{formulabox}[0/1 Knapsack 1D Recurrence]
$$\text{For each item } (w_i, v_i), \quad \text{for } w = W \text{ down to } w_i: \quad \texttt{dp[w]} = \max\big(\texttt{dp[w]},\; \texttt{dp[w - w\_i]} + v_i\big)$$
\textbf{Read this as:} Sweeping right-to-left protects smaller capacities from already containing item $i$, enforcing strict take-once semantics in $O(W)$ RAM.
\end{formulabox}

\textbf{Subset-Sum} is simply the boolean version of 0/1 Knapsack: \texttt{dp[w]} tracks whether some subset sums to $w$, initialized with \texttt{dp[0] = true} and updated backward via \texttt{dp[w] = dp[w] || dp[w - x]}. \subsection{Interval DP: Filling by Length, Not Row-by-Row}

\begin{notationbox}[Symbols Used in Interval DP]
$[L, R]$ & Contiguous subarray or subchain from index $L$ to $R$ inclusive & $0 \le L \le R < N$ \\
$k$ & Split point dividing $[L, R]$ into $[L, k]$ and $[k+1, R]$ & $L \le k < R$ \\
$\text{len}$ & Interval length $R - L + 1$, used as the \textbf{outer} loop variable & $\text{len} = 2, 3, \dots, N$ \\
\end{notationbox}

\painbeat When merging adjacent items (Matrix Chain Multiplication, bursting balloons, merging stone piles), the final step merges two smaller contiguous blocks $[L, k]$ and $[k+1, R]$. Filling \texttt{dp[L][R]} row-by-row top-down breaks because \texttt{dp[0][n-1]} needs \texttt{dp[k+1][n-1]} from rows not computed yet!

\ahabeat Every sub-interval $[L, k]$ and $[k+1, R]$ is strictly \textbf{shorter} than $[L, R]$. Therefore, looping over interval \textbf{length} $\text{len} = 2, 3, \dots, N$ in the outer loop guarantees every smaller sub-interval is already solved!

\begin{formulabox}[Interval DP Template]
$$\texttt{dp[L][R]} = \min_{L \le k < R}\big(\texttt{dp[L][k]} + \texttt{dp[k+1][R]} + \text{mergeCost}(L, k, R)\big)$$
\textbf{Read this as:} Try every possible last cut $k$ inside $[L, R]$; add the optimal costs of the left and right halves plus the cost to combine them.
\end{formulabox}

\begin{tryitbox}{Debug}{Wrong Loop Order in Interval DP}{ex6}
A programmer implements Matrix Chain Multiplication using \texttt{for (L = 0; L < n; ++L) for (R = L + 1; R < n; ++R)} instead of looping by interval length. On $n = 3$ matrices, identify the exact first cell $(L, R)$ that reads an uncomputed dependency and name the uncomputed cell it reads.
\end{tryitbox}

\subsection{Space Optimization (Rolling Arrays)}

Whenever row $i$ of a 2D DP table only reads row $i - 1$ (and possibly earlier cells in row $i$), older rows $0 \dots i - 2$ are dead memory. Keeping just two rows (or one carefully ordered row) shrinks space dramatically:

\begin{itemize}
    \item \textbf{2D Grid Min Path:} Reads \texttt{dp[i-1][j]} (top) and \texttt{dp[i][j-1]} (left) $\implies$ single 1D row swept \textbf{left-to-right}, $O(N)$ space.
    \item \textbf{0/1 Knapsack:} Reads \texttt{dp[i-1][w]} and \texttt{dp[i-1][w - wt]} $\implies$ single 1D row swept \textbf{right-to-left}, $O(W)$ space.
    \item \textbf{LCS / Edit Distance (value only):} Reads $(i-1, j-1)$, $(i-1, j)$, and $(i, j-1)$ $\implies$ two rows \texttt{prev} and \texttt{curr} swapped each step, $O(\min(M, N))$ space.
\end{itemize}

\begin{watchoutbox}[When NOT to Compress Space]
If you must \textbf{reconstruct the full solution path} (such as the actual LCS string or the chosen Knapsack items), dropping older rows destroys the backtrack table! Keep the 2D table (or store compact parent-choice bits) whenever reconstruction is required.
\end{watchoutbox}

\subsection{Bitmask DP}

\begin{notationbox}[Symbols Used in Bitmask DP]
\texttt{mask} & $N$-bit integer encoding a subset of visited items (bit $u = 1 \iff u$ visited) & $\texttt{0b101} = 5 \equiv \{0, 2\}$ \\
\texttt{1ULL << u} & Bitmask with only bit $u$ set (unsigned shift prevents UB) & Bit $2 \to \texttt{0b100} = 4$ \\
\texttt{dp[mask][u]} & Best tour cost having visited subset \texttt{mask} and currently standing at node $u$ & Size $2^N \times N$ \\
\end{notationbox}

\painbeat Finding the shortest tour visiting all $N$ cities tries $N!$ permutations---at $N = 18$, $18! \approx 6.4 \times 10^{15}$ is completely hopeless.

\ahabeat To extend a partial tour, you do \textbf{not} care in what order the visited cities were toured---only \emph{which subset} has been visited (\texttt{mask}) and \emph{where you stand now} (\texttt{last}). Encoding the subset as an $N$-bit integer collapses $N!$ paths into $N \cdot 2^N$ states (at $N = 18$, only $4.7 \times 10^6$ states!).

\begin{formulabox}[Bitmask Shortest-Tour Transition]
$$\texttt{dp[mask | (1 << nxt)][nxt]} = \min\big(\dots,\; \texttt{dp[mask][last]} + \text{dist}[\text{last}][\text{nxt}]\big)$$
\textbf{Read this as:} From every reachable state $(\texttt{mask}, \texttt{last})$, try stepping to each unvisited node \texttt{nxt} (where bit \texttt{nxt} of \texttt{mask} is $0$) and flip its bit on.
\end{formulabox}

Because adding a bit strictly increases the integer value of \texttt{mask}, iterating \texttt{mask} from $1$ up to $(1 \ll N) - 1$ is automatically a valid topological order!

\subsection{Solution Reconstruction, Counting Modulo \texorpdfstring{$M$}{M}, and DP vs.\ Greedy}

\textbf{Reconstructing the Optimal Choices:} Two clean techniques recover the actual path or items instead of just the optimal number:
\begin{enumerate}
    \item \textbf{Walk-back via the DP table:} Starting at the answer cell, check which neighbor satisfied the transition equation (used for LCS and Edit Distance).
    \item \textbf{Explicit \texttt{parent} array:} Whenever a transition improves \texttt{dp[s]}, record the exact move in \texttt{parent[s]}, then follow pointers backward to the base case (used in Coin Change).
\end{enumerate}

\textbf{Counting Modulo $M$:} Path counts explode past 64-bit integers quickly. Whenever a problem asks for the answer modulo $M = 10^9 + 7$, reduce on every addition: \texttt{dp[i] = (dp[i] + val) \% MOD}. When subtracting in C++, negative dividends produce negative remainders, so always add \texttt{MOD} first: \texttt{((a - b) \% MOD + MOD) \% MOD}. If no modulus is requested, default to \texttt{std::int64\_t}.

\begin{calloutbox}{Decision Guide: Backtracking vs.\ Greedy vs.\ DP}
\begin{itemize}
    \item \textbf{Backtracking:} Must emit \emph{every} valid configuration, or $N$ is tiny ($N \le 15$) with no overlapping subproblems.
    \item \textbf{Greedy:} Makes one irreversible local choice per step. Blazingly fast when provable, but fails whenever local optimum $\neq$ global optimum (e.g., coins $\{1, 3, 4\}$ for target $6$: greedy picks $4+1+1$, DP picks $3+3$).
    \item \textbf{DP:} Optimizes (min/max), counts ways, or checks feasibility when subproblems overlap and the past compresses into a small state.
\end{itemize}
\end{calloutbox}

\begin{enumerate}
    \item What happens in C++ if you initialize a minimum-cost \texttt{int} DP array to \texttt{std::numeric\_limits<int>::max()} and evaluate \texttt{dp[u] + 5} on an unreachable state?
    \item In C++, what does \texttt{(3 - 5) \% 7} evaluate to, and what expression fixes it safely?

\section{Key Algorithmic Patterns}
% ============================================================================

Every DP problem in this library maps onto one of six recurring structural templates. Recognizing which template governs the dependency graph immediately reveals both the table dimensions and the required loop order.

\begingroup\small\rowcolors{2}{codebg}{white}
\begin{tabularx}{\textwidth}{>{\raggedright\arraybackslash\bfseries}p{3.3cm} >{\raggedright\arraybackslash}p{3.0cm} >{\raggedright\arraybackslash}p{3.3cm} >{\raggedright\arraybackslash}X}
\arrayrulecolor{primaryblue}\toprule[1.2pt]
\rowcolor{primaryblue!10}
\textcolor{primaryblue}{\textbf{DP Family}} & \textcolor{primaryblue}{\textbf{Canonical State}} & \textcolor{primaryblue}{\textbf{Evaluation Order}} & \textcolor{primaryblue}{\textbf{Core Intuition / Signature}} \\
\arrayrulecolor{codeframe}\midrule[0.6pt]
1D Linear / ``Ends At'' & \texttt{dp[i]} & $i = 0 \to N-1$ & Prefix decisions or unbroken subarrays (Stairs, Robber, Kadane, LIS) \\
2D Grid & \texttt{dp[i][j]} & Row-by-row, left-to-right & Moving right/down on a matrix; collapses to 1D left-to-right row \\
Two-Sequence & \texttt{dp[i][j]} & $i = 1 \to M$, $j = 1 \to N$ & Prefix alignment of two strings (LCS, Edit Distance) \\
Knapsack / Subset & \texttt{dp[w]} & Outer item; inner $w$ \textbf{back} (0/1) or \textbf{fwd} (Unbounded) & Budgeted selection or exact-sum reachability \\
Interval DP & \texttt{dp[L][R]} & Outer $\text{len} = 2 \to N$; inner $L$, split $k$ & Merging adjacent blocks or palindrome windows \\
Bitmask DP & \texttt{dp[mask][u]} & $\texttt{mask} = 1 \to 2^N - 1$ & Small subset tracking ($N \le 20$): TSP, assignment \\
\arrayrulecolor{primaryblue}\bottomrule[1.2pt]
\end{tabularx}\endgroup

\begin{watchoutbox}[Three Classic DP Pitfalls]
\begin{enumerate}
    \item \textbf{Forgetting base cases:} Leaving \texttt{dp[0] = 0} in a counting problem causes the entire table to stay zero forever.
    \item \textbf{Sentinel overflow:} Using \texttt{INT\_MAX} instead of \texttt{INT\_MAX / 2} (and forgetting to skip \texttt{dp == INF}) causes signed overflow wrap-around to negative infinity.
    \item \textbf{Wrong 1D sweep direction:} Sweeping forward in 0/1 Knapsack silently turns it into Unbounded Knapsack; sweeping backward in 1D Grid Min Path breaks the left-neighbor dependency.
\end{enumerate}
\end{watchoutbox}

\begin{example}[The House Robber --- 1D Linear DP]
Maximize money robbed from street values $A = [2, 7, 9, 3, 1]$ without robbing two adjacent houses.
\begin{itemize}
    \item \textbf{State:} \texttt{dp[i]} = maximum money robbed from houses $0 \dots i$.
    \item \textbf{Transition:} $\texttt{dp[i]} = \max(\texttt{dp[i-1]},\; \texttt{dp[i-2]} + A[i])$.
\end{itemize}
\begin{enumerate}
    \item Base cases: $\texttt{dp[0]} = 2$; $\texttt{dp[1]} = \max(2, 7) = 7$.
    \item $i = 2$ ($A[2] = 9$): skip $= 7$, rob $= 2 + 9 = 11 \implies \texttt{dp[2]} = 11$.
    \item $i = 3$ ($A[3] = 3$): skip $= 11$, rob $= 7 + 3 = 10 \implies \texttt{dp[3]} = 11$.
    \item $i = 4$ ($A[4] = 1$): skip $= 11$, rob $= 11 + 1 = 12 \implies \texttt{dp[4]} = 12$.
\end{enumerate}
\textbf{Answer:} $\texttt{dp[4]} = \mathbf{12}$ (robbing houses $0, 2, 4$: $2 + 9 + 1 = 12$).
\end{example}

\begin{example}[Longest Increasing Subsequence --- $O(N^2)$ 1D DP]
Find the length of the longest strictly increasing subsequence of $A = [10, 9, 2, 5, 3, 7, 101, 18]$.
State: \texttt{dp[i]} = length of LIS ending exactly at index $i$ (initialized to $1$).
\begin{enumerate}
    \item $i = 0$ ($10$): $\texttt{dp[0]} = 1$. \quad $i = 1$ ($9$): none smaller $\implies \texttt{dp[1]} = 1$. \quad $i = 2$ ($2$): $\texttt{dp[2]} = 1$.
    \item $i = 3$ ($5$): $2 < 5 \implies \texttt{dp[3]} = \texttt{dp[2]} + 1 = 2$.
    \item $i = 4$ ($3$): $2 < 3 \implies \texttt{dp[4]} = \texttt{dp[2]} + 1 = 2$.
    \item $i = 5$ ($7$): smaller predecessors are $2, 5, 3$ (max \texttt{dp} $= 2$) $\implies \texttt{dp[5]} = 3$.
    \item $i = 6$ ($101$): all precede and are smaller (max \texttt{dp} $= 3$ at $7$) $\implies \texttt{dp[6]} = 4$.
    \item $i = 7$ ($18$): smaller predecessors up to $7$ give max \texttt{dp} $= 3 \implies \texttt{dp[7]} = 4$.
\end{enumerate}
\textbf{Answer:} $\max(\texttt{dp}) = \mathbf{4}$ (e.g., $[2, 3, 7, 18]$).
\end{example}

\section{C++ Implementations}
% ============================================================================

Every listing below is standalone C++23 (\texttt{-std=c++23 -Wall -Wextra} clean) with explicit boundary guards, safe sentinels (\texttt{INF = std::numeric\_limits<int>::max() / 2}), and \texttt{[[nodiscard]]} where appropriate.

\subsection{Tabulated Fibonacci}
Fills a 1D table bottom-up from $0$ to $n$. Uses \texttt{std::int64\_t} so values up to $f(92)$ stay overflow-free.

\begin{lstlisting}[caption={Fibonacci with bottom-up tabulation}]
#include <cstddef>
#include <cstdint>
#include <vector>

[[nodiscard]] std::int64_t fib_tabulated(int n) {
    if (n <= 0) return 0;
    if (n == 1) return 1;

    std::vector<std::int64_t> dp(static_cast<std::size_t>(n) + 1, 0);
    dp[1] = 1;

    for (std::size_t i = 2; i <= static_cast<std::size_t>(n); ++i) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[static_cast<std::size_t>(n)];
}
\end{lstlisting}

\subsection{House Robber (\texorpdfstring{$O(1)$}{O(1)} Rolling Space)}
Because each house depends only on the previous two totals, two local variables replace the entire \texttt{dp} vector.

\begin{lstlisting}[caption={House Robber optimized to $O(1)$ auxiliary space}]
#include <algorithm>
#include <cstddef>
#include <span>

[[nodiscard]] int house_robber(std::span<const int> nums) noexcept {
    if (nums.empty()) return 0;
    if (nums.size() == 1) return nums[0];

    int prev2 = nums[0];
    int prev1 = std::max(nums[0], nums[1]);

    for (std::size_t i = 2; i < nums.size(); ++i) {
        const int curr = std::max(prev1, prev2 + nums[i]);
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}
\end{lstlisting}

\subsection{Grid Minimum Path Sum (2D and Rolling 1D)}
Both versions guard against empty grids. In the 1D rolling version, \texttt{dp[j]} before updating represents the cell directly \emph{above}, while \texttt{dp[j - 1]} has already been updated for the current row (\emph{left}).

\begin{lstlisting}[caption={Grid Minimum Path Sum in 2D and rolling 1D space}]
#include <algorithm>
#include <cstddef>
#include <vector>

[[nodiscard]] int min_path_sum_2d(const std::vector<std::vector<int>>& grid) {
    if (grid.empty() || grid[0].empty()) return 0;
    const std::size_t m = grid.size();
    const std::size_t n = grid[0].size();
    std::vector<std::vector<int>> dp = grid;

    for (std::size_t i = 1; i < m; ++i) dp[i][0] += dp[i - 1][0];
    for (std::size_t j = 1; j < n; ++j) dp[0][j] += dp[0][j - 1];

    for (std::size_t i = 1; i < m; ++i) {
        for (std::size_t j = 1; j < n; ++j) {
            dp[i][j] += std::min(dp[i - 1][j], dp[i][j - 1]);
        }
    }
    return dp[m - 1][n - 1];
}

[[nodiscard]] int min_path_sum_1d(const std::vector<std::vector<int>>& grid) {
    if (grid.empty() || grid[0].empty()) return 0;
    const std::size_t m = grid.size();
    const std::size_t n = grid[0].size();
    std::vector<int> dp(n, 0);

    dp[0] = grid[0][0];
    for (std::size_t j = 1; j < n; ++j) dp[j] = dp[j - 1] + grid[0][j];

    for (std::size_t i = 1; i < m; ++i) {
        dp[0] += grid[i][0];
        for (std::size_t j = 1; j < n; ++j) {
            dp[j] = grid[i][j] + std::min(dp[j], dp[j - 1]);
        }
    }
    return dp[n - 1];
}
\end{lstlisting}

\subsection{Longest Common Subsequence with String Reconstruction}
Builds the full $(M + 1) \times (N + 1)$ table, walks backward from $(M, N)$ collecting matched characters, and calls C++20/23 \texttt{std::ranges::reverse}.

\begin{lstlisting}[caption={LCS length computation and string reconstruction}]
#include <algorithm>
#include <cstddef>
#include <string>
#include <string_view>
#include <vector>

[[nodiscard]] std::string get_lcs(std::string_view s1, std::string_view s2) {
    const std::size_t m = s1.size();
    const std::size_t n = s2.size();
    std::vector<std::vector<int>> dp(m + 1, std::vector<int>(n + 1, 0));

    for (std::size_t i = 1; i <= m; ++i) {
        for (std::size_t j = 1; j <= n; ++j) {
            if (s1[i - 1] == s2[j - 1]) {
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                dp[i][j] = std::max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }

    std::string lcs;
    std::size_t i = m;
    std::size_t j = n;
    while (i > 0 && j > 0) {
        if (s1[i - 1] == s2[j - 1]) {
            lcs.push_back(s1[i - 1]);
            --i;
            --j;
        } else if (dp[i - 1][j] > dp[i][j - 1]) {
            --i;
        } else {
            --j;
        }
    }

    std::ranges::reverse(lcs);
    return lcs;
}
\end{lstlisting}

\subsection{Edit Distance (Levenshtein)}
Initializes row $0$ and column $0$ to prefix lengths (all insertions or all deletions), then relaxes every interior cell over delete, insert, and replace.

\begin{lstlisting}[caption={Edit Distance using a 2D DP table}]
#include <algorithm>
#include <cstddef>
#include <string_view>
#include <vector>

[[nodiscard]] int edit_distance(std::string_view word1, std::string_view word2) {
    const std::size_t m = word1.size();
    const std::size_t n = word2.size();
    std::vector<std::vector<int>> dp(m + 1, std::vector<int>(n + 1, 0));

    for (std::size_t i = 0; i <= m; ++i) dp[i][0] = static_cast<int>(i);
    for (std::size_t j = 0; j <= n; ++j) dp[0][j] = static_cast<int>(j);

    for (std::size_t i = 1; i <= m; ++i) {
        for (std::size_t j = 1; j <= n; ++j) {
            if (word1[i - 1] == word2[j - 1]) {
                dp[i][j] = dp[i - 1][j - 1];
            } else {
                dp[i][j] = 1 + std::min({
                    dp[i - 1][j],    // Delete from word1
                    dp[i][j - 1],    // Insert into word1
                    dp[i - 1][j - 1] // Replace
                });
            }
        }
    }
    return dp[m][n];
}
\end{lstlisting}

\subsection{Longest Increasing Subsequence (\texorpdfstring{$O(N^2)$}{O(N^2)})}
For each index $i$, scans every earlier index $j < i$ with \texttt{nums[j] < nums[i]} to extend the longest valid chain ending at $i$.

\begin{lstlisting}[caption={Longest Increasing Subsequence in $O(N^2)$ time}]
#include <algorithm>
#include <cstddef>
#include <span>
#include <vector>

[[nodiscard]] int length_of_lis(std::span<const int> nums) {
    if (nums.empty()) return 0;
    const std::size_t n = nums.size();
    std::vector<int> dp(n, 1);
    int max_len = 1;

    for (std::size_t i = 1; i < n; ++i) {
        for (std::size_t j = 0; j < i; ++j) {
            if (nums[j] < nums[i]) {
                dp[i] = std::max(dp[i], dp[j] + 1);
            }
        }
        max_len = std::max(max_len, dp[i]);
    }
    return max_len;
}
\end{lstlisting}

\subsection{0/1 Knapsack and Boolean Subset-Sum (1D Backward Sweep)}
Both listings guard negative capacities and invalid item weights, and sweep capacity \textbf{backward} so every item is taken at most once.

\begin{lstlisting}[caption={0/1 Knapsack space-optimized to a 1D backward loop}]
#include <algorithm>
#include <cstddef>
#include <span>
#include <vector>

[[nodiscard]] int knapsack_01(
    int capacity,
    std::span<const int> weights,
    std::span<const int> values
) {
    if (capacity <= 0 || weights.size() != values.size()) return 0;

    std::vector<int> dp(static_cast<std::size_t>(capacity) + 1, 0);
    for (std::size_t i = 0; i < weights.size(); ++i) {
        const int wt = weights[i];
        const int val = values[i];
        if (wt <= 0 || wt > capacity) continue;

        for (int w = capacity; w >= wt; --w) {
            const auto idx = static_cast<std::size_t>(w);
            const auto prev = static_cast<std::size_t>(w - wt);
            dp[idx] = std::max(dp[idx], dp[prev] + val);
        }
    }
    return dp[static_cast<std::size_t>(capacity)];
}
\end{lstlisting}

\begin{lstlisting}[caption={Boolean Subset-Sum optimized to 1D backward loop}]
#include <cstddef>
#include <span>
#include <vector>

[[nodiscard]] bool can_reach_sum(std::span<const int> nums, int target) {
    if (target < 0) return false;
    if (target == 0) return true;

    std::vector<bool> dp(static_cast<std::size_t>(target) + 1, false);
    dp[0] = true;

    for (int num : nums) {
        if (num <= 0 || num > target) continue;
        for (int w = target; w >= num; --w) {
            if (dp[static_cast<std::size_t>(w - num)]) {
                dp[static_cast<std::size_t>(w)] = true;
            }
        }
    }
    return dp[static_cast<std::size_t>(target)];
}
\end{lstlisting}

\subsection{Matrix Chain Multiplication (Interval DP)}
Guards \texttt{dims.size() < 2} to prevent unsigned underflow, then sweeps outer interval length from $2$ up to $n$.

\begin{lstlisting}[caption={Matrix Chain Multiplication filled by interval length}]
#include <algorithm>
#include <cstddef>
#include <limits>
#include <span>
#include <vector>

[[nodiscard]] int matrix_chain(std::span<const int> dims) {
    if (dims.size() < 2) return 0;
    constexpr int INF = std::numeric_limits<int>::max() / 2;
    const std::size_t n = dims.size() - 1;
    std::vector<std::vector<int>> dp(n, std::vector<int>(n, 0));

    for (std::size_t length = 2; length <= n; ++length) {
        for (std::size_t left = 0; left <= n - length; ++left) {
            const std::size_t right = left + length - 1;
            dp[left][right] = INF;
            for (std::size_t k = left; k < right; ++k) {
                const int cost = dp[left][k] + dp[k + 1][right] +
                                 dims[left] * dims[k + 1] * dims[right + 1];
                dp[left][right] = std::min(dp[left][right], cost);
            }
        }
    }
    return dp[0][n - 1];
}
\end{lstlisting}

\subsection{Bitmask DP (Shortest Hamiltonian Path)}
Uses unsigned shifts (\texttt{std::size\_t\{1\} << n}), guards $n \le 1$, defines a local overflow-safe \texttt{INF}, and uses C++20 \texttt{std::popcount} to skip masks that already visited all nodes.

\begin{lstlisting}[caption={Shortest Hamiltonian path from node 0 using bitmask DP}]
#include <algorithm>
#include <bit>
#include <cstddef>
#include <limits>
#include <vector>

[[nodiscard]] int shortest_tour(const std::vector<std::vector<int>>& dist) {
    constexpr int INF = std::numeric_limits<int>::max() / 2;
    const std::size_t n = dist.size();
    if (n <= 1) return 0;

    const std::size_t limit = std::size_t{1} << n;
    std::vector<std::vector<int>> dp(limit, std::vector<int>(n, INF));
    dp[1][0] = 0; // Start at node 0 with mask 0b...001

    for (std::size_t mask = 1; mask < limit; ++mask) {
        if (static_cast<std::size_t>(std::popcount(mask)) == n) continue;

        for (std::size_t last = 0; last < n; ++last) {
            if ((mask & (std::size_t{1} << last)) == 0) continue;
            if (dp[mask][last] == INF) continue;

            for (std::size_t nxt = 0; nxt < n; ++nxt) {
                if ((mask & (std::size_t{1} << nxt)) != 0) continue;
                const std::size_t next_mask = mask | (std::size_t{1} << nxt);
                dp[next_mask][nxt] = std::min(
                    dp[next_mask][nxt],
                    dp[mask][last] + dist[last][nxt]
                );
            }
        }
    }

    int best = INF;
    for (std::size_t last = 1; last < n; ++last) {
        best = std::min(best, dp[limit - 1][last]);
    }
    return best;
}
\end{lstlisting}

\subsection{Top-Down Memoization with C++23 Deducing \texorpdfstring{\texttt{this}}{this}}
Uses a C++23 explicit-object (\texttt{this auto\& self}) recursive lambda with explicit empty-grid guards and a local \texttt{INF} sentinel.

\begin{lstlisting}[caption={Top-down grid memoization using a C++23 recursive lambda}]
#include <algorithm>
#include <cstddef>
#include <limits>
#include <vector>

[[nodiscard]] int min_path_memo(const std::vector<std::vector<int>>& grid) {
    if (grid.empty() || grid[0].empty()) return 0;
    constexpr int INF = std::numeric_limits<int>::max() / 2;
    const std::size_t m = grid.size();
    const std::size_t n = grid[0].size();
    std::vector<std::vector<int>> memo(m, std::vector<int>(n, -1));

    auto dfs = [&](this auto& self, std::size_t i, std::size_t j) -> int {
        if (i == 0 && j == 0) return grid[0][0];
        if (memo[i][j] != -1) return memo[i][j];

        const int cost_up = (i > 0) ? self(i - 1, j) : INF;
        const int cost_left = (j > 0) ? self(i, j - 1) : INF;

        memo[i][j] = grid[i][j] + std::min(cost_up, cost_left);
        return memo[i][j];
    };

    return dfs(m - 1, n - 1);
}
\end{lstlisting}

\subsection{Coin Change (Combinations Count and Parent Reconstruction)}
Demonstrates both combination counting (outer loop over coins) and optimal coin reconstruction via explicit \texttt{parent} pointers, guarding negative amounts and non-positive coin values.

\begin{lstlisting}[caption={Coin Change: combination count and parent-pointer reconstruction}]
#include <cstddef>
#include <cstdint>
#include <limits>
#include <span>
#include <vector>

[[nodiscard]] std::int64_t count_coin_ways(std::span<const int> coins, int amount) {
    if (amount < 0) return 0;
    std::vector<std::int64_t> dp(static_cast<std::size_t>(amount) + 1, 0);
    dp[0] = 1;

    for (int coin : coins) {
        if (coin <= 0 || coin > amount) continue;
        for (int a = coin; a <= amount; ++a) {
            const auto idx = static_cast<std::size_t>(a);
            dp[idx] += dp[static_cast<std::size_t>(a - coin)];
        }
    }
    return dp[static_cast<std::size_t>(amount)];
}

[[nodiscard]] std::vector<int> get_min_coins(std::span<const int> coins, int amount) {
    if (amount <= 0) return {};
    constexpr int INF = std::numeric_limits<int>::max() / 2;
    const auto sz = static_cast<std::size_t>(amount) + 1;
    std::vector<int> dp(sz, INF);
    std::vector<int> parent(sz, -1);
    dp[0] = 0;

    for (int a = 1; a <= amount; ++a) {
        const auto idx = static_cast<std::size_t>(a);
        for (int coin : coins) {
            if (coin <= 0 || coin > a) continue;
            const auto prev = static_cast<std::size_t>(a - coin);
            if (dp[prev] != INF && dp[prev] + 1 < dp[idx]) {
                dp[idx] = dp[prev] + 1;
                parent[idx] = coin;
            }
        }
    }

    std::vector<int> result;
    if (dp[static_cast<std::size_t>(amount)] == INF) return result;

    int curr = amount;
    while (curr > 0) {
        const int chosen = parent[static_cast<std::size_t>(curr)];
        result.push_back(chosen);
        curr -= chosen;
    }
    return result;
}
\end{lstlisting}

\section{Problem Pattern Recognition}
% ============================================================================

Use this three-step filter to diagnose whether an unseen problem belongs to Dynamic Programming and which table shape to draw first.

\subsection*{Step 1: What Kind of Answer Does the Problem Ask For?}
\begin{itemize}
    \item \textbf{Minimum or maximum cost / profit / length} $\implies$ Optimization DP ($\min$ / $\max$ transitions).
    \item \textbf{Total number of ways} (often modulo $10^9 + 7$) $\implies$ Counting DP (additive transitions).
    \item \textbf{``Is it possible to reach target $T$?''} $\implies$ Boolean feasibility DP (\texttt{||} transitions).
    \item \textbf{``List ALL valid solutions''} $\implies$ \textbf{Not DP}; use Backtracking (Module 05).
\end{itemize}

\subsection*{Step 2: What Is the Key Constraint?}
\begin{itemize}
    \item Can you summarize the entire past with $1$--$3$ small integers (indices, remaining budget, last state)? If yes, DP applies.
    \item Must you remember the exact set of visited items? Only feasible as \textbf{Bitmask DP} when $N \le 20$.
\end{itemize}

\subsection*{Step 3: Constraint Thresholds (Reading the Budget)}
\begin{itemize}
    \item $N \le 10^5$: Needs $O(N)$ 1D DP (or $O(N \log N)$ patience-sorting LIS).
    \item $N \le 5{,}000$: Fits $O(N^2)$ 1D/2D DP; use rolling rows if $5{,}000 \times 5{,}000 \times 4\text{ B} = 100\text{ MB}$ approaches memory limits.
    \item $N \cdot W \le 10^7$: Pseudo-polynomial Knapsack fits comfortably.
    \item $N \le 500$: Permits $O(N^3)$ Interval DP.
    \item $N \le 20$: Signals $O(N^2 \cdot 2^N)$ Bitmask DP.
\end{itemize}

\section{Glossary}
% ============================================================================

\subsection*{Core Concepts}
\begin{itemize}
    \item \textbf{0/1 Knapsack:} Budgeted item selection where each item is used at most once (backward 1D capacity loop).
    \item \textbf{Answer State:} The specific cell (or aggregation over cells) holding the overall problem's final answer.
    \item \textbf{Backtracking:} Exhaustive DFS search that explores and undoes choices; required when listing all solutions.
    \item \textbf{Base Case:} Smallest boundary states initialized directly without transitions.
    \item \textbf{Bitmask:} Integer whose binary bits encode membership in a subset ($N \le 20$).
    \item \textbf{Directed Acyclic Graph (DAG):} Graph with directed edges and zero cycles; every valid DP forms a DAG.
    \item \textbf{Edit Distance (Levenshtein):} Minimum insertions, deletions, and replacements transforming one string into another.
    \item \textbf{Evaluation Order:} Loop order (topological sort) guaranteeing dependencies are computed before being read.
    \item \textbf{Greedy:} Making one irreversible locally optimal choice per step; fails without a provable exchange property.
    \item \textbf{Longest Common Subsequence (LCS):} Longest sequence of characters appearing in the same relative order in two strings.
    \item \textbf{Longest Increasing Subsequence (LIS):} Longest strictly increasing subsequence of a numeric sequence.
    \item \textbf{Memoization:} Top-down recursion augmented with a cache storing solved subproblem answers.
    \item \textbf{Optimal Substructure:} Property that an optimal solution is composed of optimal solutions to smaller subproblems.
    \item \textbf{Overlapping Subproblems:} Property that the same subproblem parameters recur repeatedly in a recursive tree.
    \item \textbf{Parent Pointer:} Auxiliary array recording the decision taken at each state for fast solution reconstruction.
    \item \textbf{Popcount:} Number of \texttt{1}-bits set in an integer's binary representation (\texttt{std::popcount}).
    \item \textbf{Pseudo-Polynomial:} Runtime polynomial in a numeric parameter's \emph{value} (like capacity $W$) rather than its bit length.
    \item \textbf{Reconstruction:} Walking backward through the DP table or parent pointers to emit the actual optimal choices.
    \item \textbf{Rolling Array:} Space optimization keeping only the active frontier slice of the DP table.
    \item \textbf{State:} Minimal tuple of parameters uniquely identifying a subproblem.
    \item \textbf{Subsequence vs.\ Substring:} A subsequence may delete elements (order preserved); a substring must be contiguous.
    \item \textbf{Tabulation:} Bottom-up iterative filling of a DP table from base cases upward.
    \item \textbf{Topological Order:} Linear ordering of DAG nodes so every node follows all of its prerequisites.
    \item \textbf{Transition (Recurrence):} Formula computing a state's value from strictly smaller prerequisite states.
    \item \textbf{Unbounded Knapsack:} Budgeted item selection permitting unlimited reuse of each item (forward 1D capacity loop).
\end{itemize}

\subsection*{Mathematical Symbols}
\begin{itemize}
    \item \texttt{dp[i]}, \texttt{dp[i][j]}: Stored optimal value for a 1D or 2D DP state.
    \item $\infty$ (\texttt{INF}): Overflow-safe sentinel (\texttt{INT\_MAX / 2}) marking unreachable minimization states.
    \item $\max / \min,\; \min_k$: Maximum/minimum across candidate choices or split points $k$.
    \item $2^N,\; N!$: Exponential subset count (Bitmask DP) vs.\ factorial permutation count (brute-force TSP).
    \item $\texttt{<<},\; \texttt{\&},\; \texttt{|}$: Bitwise left-shift, AND, and OR used to test and set bits in a bitmask.
    \item $\% \text{ MOD}$: Modular reduction applied at every addition/subtraction in counting DP.
\end{itemize}

\begin{enumerate}[itemsep=2pt]
    \item \label{sol:ex1}\textbf{Exercise 1 (Derive) --- Discovering the Frog-Jump State:}
    State: \texttt{dp[i]} = min energy to reach stone $i$. Base: $\texttt{dp[0]} = 0$, $\texttt{dp[1]} = |h_1 - h_0|$. Transition: $\texttt{dp[i]} = \min(\texttt{dp[i-1]} + |h_i - h_{i-1}|,\; \texttt{dp[i-2]} + |h_i - h_{i-2}|)$.
    For \texttt{[10, 30, 40, 20]}: $\texttt{dp[0]} = 0$, $\texttt{dp[1]} = 20$, $\texttt{dp[2]} = \min(20 + 10,\; 0 + 30) = 30$, $\texttt{dp[3]} = \min(30 + 20,\; 20 + 10) = \mathbf{30}$.
    \trapnote{Forgetting the base case \texttt{dp[1]} and reading \texttt{dp[-1]} out of bounds at $i = 1$.}

    \item \label{sol:ex2}\textbf{Exercise 2 (Trace) --- Coin Change \texttt{\{1, 3, 4\}} for Target $6$:}
    $\texttt{dp[0..6]} = [0, 1, 2, 1, 1, 2, \mathbf{2}]$; $\texttt{parent[0..6]} = [-1, 1, 1, 3, 4, 1, 3]$. Walk-back from $6$: \texttt{parent[6] = 3} ($6 \to 3$), \texttt{parent[3] = 3} ($3 \to 0$) $\implies \mathbf{[3, 3]}$ ($2$ coins). Greedy picks $4$ first and gets stuck paying $4 + 1 + 1$ ($3$ coins).
    \trapnote{Assuming greedy largest-coin-first works for arbitrary coin sets---it only works for canonical systems like US currency.}

    \item \label{sol:ex3}\textbf{Exercise 3 (Twist) --- Maximum Product Subarray:}
    On \texttt{[-2, 3, -4]}, tracking only \texttt{max\_end} drops $-2 \times 3 = -6$ in favor of $3$, missing $(-6) \times (-4) = \mathbf{+24}$! Fix by tracking both \texttt{max\_end[i]} and \texttt{min\_end[i]} at every index, updating both from $\{x,\; \texttt{max\_end} \cdot x,\; \texttt{min\_end} \cdot x\}$.
    \trapnote{Overwriting \texttt{max\_end} before using its old value to compute \texttt{min\_end}---save the previous \texttt{max\_end} in a temporary variable first.}

    \item \label{sol:ex4}\textbf{Exercise 4 (Trace) --- Edit Distance \texttt{"cat"} $\to$ \texttt{"cut"}:}
    Table rows ($i = 0 \dots 3$, cols $\emptyset, \texttt{c}, \texttt{u}, \texttt{t}$): Row $0 = [0, 1, 2, 3]$; Row $1 (\texttt{c}) = [1, 0, 1, 2]$; Row $2 (\texttt{a}) = [2, 1, 1, 2]$; Row $3 (\texttt{t}) = [3, 2, 2, \mathbf{1}]$. Walk-back: $(3,3) = 1$ [match \texttt{'t'}] $\to (2,2) = 1$ [\textbf{replace \texttt{'a'}$\to$\texttt{'u'}}] $\to (1,1) = 0$ [match \texttt{'c'}] $\to (0,0) = 0$. Total $= \mathbf{1}$ edit.
    \trapnote{Forgetting the empty-prefix row $0$ and column $0$, making the table $3 \times 3$ instead of $4 \times 4$ and dropping insertion/deletion base cases.}

    \item \label{sol:ex5}\textbf{Exercise 5 (Trace) --- 4-Item 1D Knapsack Forward vs.\ Backward:}
    Items $(1, 2), (2, 5), (3, 6), (4, 7)$, $W = 5$:
    \textbf{(1) Backward (0/1):} after $(1,2)$: $[0,2,2,2,2,2]$; after $(2,5)$: $[0,2,5,7,7,7]$; after $(3,6)$: $[0,2,5,7,8,11]$; after $(4,7)$: $[0,2,5,7,8,\mathbf{11}]$ (items $(2,5) + (3,6)$).
    \textbf{(2) Forward (Unbounded):} after $(1,2)$: $[0,2,4,6,8,10]$; after $(2,5)$: $[0,2,5,7,10,12]$; after $(3,6)$ and $(4,7)$: $[0,2,5,7,10,\mathbf{12}]$.
    Forward beats backward at $w = 5$ ($12$ vs.\ $11$) because it illegally reuses $(2, 5)$ \emph{twice} plus $(1, 2)$.
    \trapnote{Sweeping forward on 0/1 Knapsack and mistaking the inflated unbounded score for a valid take-once solution.}

    \item \label{sol:ex6}\textbf{Exercise 6 (Debug) --- Wrong Loop Order in Interval DP:}
    On $n = 3$, the loop visits $(0, 1)$ (OK) and then immediately visits $\mathbf{(0, 2)}$. Evaluating split $k = 0$ reads $\mathbf{\texttt{dp[1][2]}}$, which has not been computed yet (still $0$), corrupting the minimization!
    \trapnote{Testing only on $n = 2$ (where $(0, 1)$ has no interior splits) and missing the dependency violation that first appears at length $3$.}

    \item \label{sol:ex7}\textbf{Exercise 7 (Edge Cases) --- Sentinel Overflow \& Negative Modulo:}
    \textbf{(1)} \texttt{INT\_MAX + 5} causes signed integer overflow (UB; wraps to $-2{,}147{,}483{,}644$, fooling \texttt{std::min} into picking an impossible state!). Always use \texttt{INF = max() / 2} and skip states with \texttt{dp == INF}.
    \textbf{(2)} \texttt{(3 - 5) \% 7} evaluates to $\mathbf{-2}$ in C++. Fix with \texttt{((a - b) \% MOD + MOD) \% MOD}.
    \trapnote{Using \texttt{INT\_MAX} as \texttt{INF} or assuming C++'s \texttt{\%} operator always returns a non-negative remainder like Python.}

    \item \label{sol:ex8}\textbf{Exercise 8 (Debug) --- Three Boundary Bugs in DP Code:}
    \textbf{(1)} For $n = 1$, \texttt{for (last = 1; last < 1; ++last)} executes zero times, returning \texttt{INF} instead of $0$.
    \textbf{(2)} Literal \texttt{1} is signed 32-bit \texttt{int}; \texttt{1 << 31} is signed overflow UB (and negative if cast to \texttt{std::size\_t}!). Use \texttt{std::size\_t\{1\} << n}.
    \textbf{(3)} On an empty grid, \texttt{grid[0]} dereferences out-of-bounds memory (crash / UB).
    \trapnote{Assuming $n \ge 2$ or non-empty grids without guarding trivial edge inputs at function entry.}

    \item \label{sol:ex9}\textbf{Exercise 9 (Triage) --- Choosing the DP State for Unseen Problems:}
    \textbf{(1)} 1D State-Machine DP: \texttt{dp[i][c]} = min cost to paint houses $0 \dots i$ ending with color $c \in \{0, 1, 2\}$ ($O(N)$ time, $O(1)$ rolling space).
    \textbf{(2)} Interval + 1D DP: precompute \texttt{is\_pal[L][R]} in $O(N^2)$, then \texttt{cuts[i]} = min cuts for prefix $0 \dots i$ ($O(N^2)$ time).
    \textbf{(3)} \textbf{Backtracking} (not DP): must enumerate \emph{all} paths, and $N = 12$ fits pruned DFS.
    \trapnote{Trying to force DP when a problem asks to \emph{print every solution} instead of counting or optimizing.}

    \item \label{sol:ex10}\textbf{Exercise 10 (Trace) --- Rolling 1D Grid Min Path Sum:}
    Row $0$: $[2, 3, 6]$; Row $1$: $\texttt{dp[0]} = 8$, $\texttt{dp[1]} = 5 + \min(3, 8) = 8$, $\texttt{dp[2]} = 4 + \min(6, 8) = 10 \implies [8, 8, 10]$; Row $2$: $\texttt{dp[0]} = 15$, $\texttt{dp[1]} = 8 + \min(8, 15) = 16$, $\texttt{dp[2]} = 9 + \min(10, 16) = 19 \implies [15, 16, \mathbf{19}]$.
    Column $j$ sweeps \textbf{left-to-right} because \texttt{dp[j - 1]} must hold the \emph{current} row (left neighbor) while \texttt{dp[j]} still holds the \emph{previous} row (top neighbor).
    \trapnote{Blindly copying 0/1 Knapsack's backward loop into a 2D grid, which reads stale previous-row values for the left neighbor.}

    \item \label{sol:ex11}\textbf{Exercise 11 (Debug) --- Swapped Loops in Coin Combinations:}
    True combinations for $4$ using $\{1, 2, 5\}$: $\mathbf{3}$ (\texttt{1+1+1+1}, \texttt{1+1+2}, \texttt{2+2}). Outer-amount loop counts \textbf{permutations}: \texttt{dp = [1, 1, 2, 3, 5]}, returning $\mathbf{5}$ because \texttt{1+1+2}, \texttt{1+2+1}, and \texttt{2+1+1} are counted as $3$ separate sequences!
    \trapnote{Writing the coin loop inside the amount loop when order is supposed to be ignored.}

    \item \label{sol:ex12}\textbf{Exercise 12 (Twist) --- House Robber on a Circle:}
    If $n = 1$, return \texttt{nums[0]}. Otherwise, house $0$ and house $n-1$ cannot both be picked, so return the larger of \texttt{house\_robber} on \texttt{nums[0..n-2]} and on \texttt{nums[1..n-1]}.
    Checks: for \texttt{[2, 3, 2]}, $\max(\text{rob}([2,3]),\; \text{rob}([3,2])) = \max(3, 3) = \mathbf{3}$; for \texttt{[1, 2, 3, 1]}, $\max(\text{rob}([1,2,3]),\; \text{rob}([2,3,1])) = \max(4, 3) = \mathbf{4}$.
    \trapnote{Forgetting the $n = 1$ special case---slicing off either endpoint turns a $1$-house circle into two empty slices and wrongly returns $0$.}

    \item \label{sol:ex13}\textbf{Exercise 13 (Edge Cases) --- Empty, Impossible, and Single-Element Inputs:}
    \textbf{(1)} \texttt{true} (empty subset sums to $0$; base case \texttt{dp[0] = true}).
    \textbf{(2)} \texttt{\{\}} (empty vector; omitting the \texttt{dp[amount] == INF} check reads \texttt{parent[5] = -1}, incrementing \texttt{curr} to $6$ and reading out of bounds!).
    \textbf{(3)} Both return $\mathbf{0}$ ($0$ multiplications needed; omitting \texttt{dims.size() < 2} underflows unsigned \texttt{dims.size() - 1} to \texttt{SIZE\_MAX} on empty input!).
    \trapnote{Skipping reachability checks (\texttt{dp[target] == INF}) before entering a \texttt{while (curr > 0)} reconstruction loop.}

    \item \label{sol:ex14}\textbf{Exercise 14 (Derive) --- Bitmask TSP Complexity \& $N \le 20$ Cutoff:}
    There are $2^N$ masks and $N$ choices for \texttt{last} $\implies O(N \cdot 2^N)$ states (Space $O(2^N \cdot N)$). Each valid state scans up to $N$ candidate \texttt{nxt} cities $\implies$ Time $O(2^N \cdot N^2)$.
    Rough operations: $N = 15 \to 2^{15} \cdot 225 \approx 7.4 \times 10^6$ (instant); $N = 20 \to 2^{20} \cdot 400 \approx 4.2 \times 10^8$ (borderline $\sim 1\text{ s}$, halved by skipping unset bits); $N = 25 \to 2^{25} \cdot 625 \approx 2.1 \times 10^{10}$ ops and $\sim 3.4\text{ GB}$ RAM (exceeds both time and memory limits).
    \trapnote{Reporting Bitmask TSP time as $O(2^N \cdot N)$---that is only the number of states, forgetting the $O(N)$ transition loop inside each state!}
\end{enumerate}
