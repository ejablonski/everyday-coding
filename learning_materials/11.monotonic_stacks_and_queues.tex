This document covers monotonic stacks and monotonic queues (deques), specialized data structures that maintain elements in sorted order to answer nearest-neighbor and sliding-window queries in linear time. It is written for programmers who want an intuitive, visual explanation of why discarding dominated elements turns slow nested loops into amortized constant-time updates. We cover the four nearest extrema queries, index-based span calculations, duplicate symmetry breaking, histogram rectangle expansion, lexicographical digit removal, and sliding-window extrema. Complete C++23 implementations, pen-and-paper drills, and pattern-recognition rules provide practical templates for sequence algorithms.
\end{abstract}

\subsection{What Is Monotonicity?}

A sequence is called \emph{monotonic} if its values move in only one direction, never reversing course. For a sequence $S = \langle s_0, s_1, \dots, s_{k-1} \rangle$:
\begin{itemize}
    \item \textbf{Monotonically increasing}: $s_0 \le s_1 \le \dots \le s_{k-1}$ (or strictly increasing when each relation is $<$).
    \item \textbf{Monotonically decreasing}: $s_0 \ge s_1 \ge \dots \ge s_{k-1}$ (or strictly decreasing when each relation is $>$).
\end{itemize}

A standard stack accepts pushes in any order. A \textbf{monotonic stack} adds one invariant: before pushing a new element $x$, we pop from the top until inserting $x$ keeps the stack sorted from bottom to top.

\subsection{Why Discarding Elements Is Safe: The Skyline Shadow Proof}

\textbf{The Pain Point:} Finding the first taller building to the right of every building in a skyline naively requires scanning rightward from each index, taking $O(N^2)$ comparisons on a descending skyline.

\textbf{The ``Aha!'' Observation:} Imagine standing in a flat concert crowd looking toward the stage. If a $185\text{ cm}$ person stands directly in front of a $170\text{ cm}$ person, nobody behind them can ever see the $170\text{ cm}$ person first---the taller, closer person casts a permanent \emph{shadow}.

\textbf{Concrete Mini-Example:} Suppose heights seen so far from the right are $[170, 185]$. For any viewer standing further left, $185$ is both closer and taller than $170$, so $170$ can never be the nearest taller neighbor for anyone to its left. Throwing away $170$ leaves only useful candidates, which automatically form a sorted (monotonic) staircase.

\textbf{When It Breaks:} This elimination relies on asking for the \emph{nearest} greater (or smaller) item. If a problem instead asks for the \emph{second} greater element, or the maximum over an arbitrary non-contiguous subset, a shadowed element might still matter and cannot be discarded on first sight.

\begin{calloutbox}{The Elimination Principle}
If a newer element is both ``better'' (larger for a max query, smaller for a min query) and closer to all future queries than an older element, the older element is permanently dominated and can be popped immediately.
\end{calloutbox}

\subsection{Monotonic Stack vs. Monotonic Deque}

A stack operates at one end only, whereas a \textbf{monotonic deque} (double-ended queue) maintains a sorted list of candidates across a moving interval $[i - K + 1, i]$:
\begin{itemize}
    \item \textbf{Monotonic Stack}: Answers \emph{nearest-neighbor} queries (first strictly greater or smaller element to the left or right). Waiting elements sit on the stack until an arriving element resolves and pops them.
    \item \textbf{Monotonic Deque}: Answers \emph{sliding-window extremum} queries (maximum or minimum inside a window of length $K$). It performs two evictions:
    \begin{enumerate}
        \item \emph{Back eviction}: Pops dominated elements from the back as new elements arrive.
        \item \emph{Front eviction}: Pops expired elements from the front once their index falls left of $i - K + 1$.
    \end{enumerate}
\end{itemize}

\subsection{The Four Nearest Extrema Queries}
\label{sec:four_queries}

\begin{notationbox}[Symbols Used in This Subsection]
$A[i]$ & Value at $0$-based index $i$ of the input array & \texttt{int} (e.g., $A[2] = 4$) \\ \hline
$N$ & Number of elements in $A$ & $N = \texttt{A.size()}$ \\ \hline
$\text{NGE}, \text{PGE}$ & Next Greater ($j > i$) and Previous Greater ($j < i$) element & First $A[j] > A[i]$ \\ \hline
$\text{NSE}, \text{PSE}$ & Next Smaller ($j > i$) and Previous Smaller ($j < i$) element & First $A[j] < A[i]$ \\ \hline
\end{notationbox}

Many array problems reduce to finding, for every $A[i]$, the nearest index to its left or right whose value crosses a strict threshold:
\begin{enumerate}
    \item \textbf{Next Greater Element (NGE)}: First index $j > i$ with $A[j] > A[i]$.
    \item \textbf{Previous Greater Element (PGE)}: First index $j < i$ with $A[j] > A[i]$.
    \item \textbf{Next Smaller Element (NSE)}: First index $j > i$ with $A[j] < A[i]$.
    \item \textbf{Previous Smaller Element (PSE)}: First index $j < i$ with $A[j] < A[i]$.
\end{enumerate}

\textbf{Loop Invariant (Decreasing Stack for NGE, Left-to-Right):} At the start of iteration $i$, the stack holds indices of all earlier elements that have not yet seen a greater value to their right, ordered from bottom to top in non-increasing order of $A[\cdot]$.

\begin{calloutbox}{Rule of Stack Monotonicity}
\begin{itemize}
    \item To find a \textbf{Greater} element, keep a \textbf{decreasing stack} (bottom to top). An arriving larger value breaks the decreasing order and pops smaller waiting items.
    \item To find a \textbf{Smaller} element, keep an \textbf{increasing stack} (bottom to top). An arriving smaller value breaks the increasing order and pops larger waiting items.
    \item To find a \textbf{Next} element ($j > i$), either scan left-to-right (resolving items on pop) or scan right-to-left (reading the surviving stack top).
    \item To find a \textbf{Previous} element ($j < i$), scan left-to-right and read the surviving stack top after popping.
\end{itemize}
\end{calloutbox}

\vspace{0.2cm}
\noindent
\begin{tabularx}{\textwidth}{|l|l|l|X|}
\hline
\textbf{Query Target} & \textbf{Stack Invariant} & \textbf{Iteration Order} & \textbf{Pop Condition for Candidate $x$} \\ \hline
Next Greater (NGE) & Decreasing & L-to-R (on pop) / R-to-L (top) & L-to-R: $A[\text{top}] < x$; R-to-L: $A[\text{top}] \le x$ \\ \hline
Previous Greater (PGE) & Decreasing & Left-to-Right & Pop top while $A[\text{top}] \le x$ \\ \hline
Next Smaller (NSE) & Increasing & L-to-R (on pop) / R-to-L (top) & L-to-R: $A[\text{top}] > x$; R-to-L: $A[\text{top}] \ge x$ \\ \hline
Previous Smaller (PSE) & Increasing & Left-to-Right & Pop top while $A[\text{top}] \ge x$ \\ \hline
\end{tabularx}
\vspace{0.3cm}

\begin{example}[Worked Trace of the Four Extrema Queries]
Consider array $A = [3, 1, 4, 2]$ of length $N = 4$ with indices $0, 1, 2, 3$. We trace each of the four queries:
\begin{enumerate}
    \item \textbf{Next Greater Element (NGE)}:
    \begin{itemize}
        \item $A[0] = 3$: scans right past $1$, hits $A[2] = 4 > 3 \implies \text{NGE}[0] = 4$ (index $2$).
        \item $A[1] = 1$: hits $A[2] = 4 > 1 \implies \text{NGE}[1] = 4$ (index $2$).
        \item $A[2] = 4$ and $A[3] = 2$: no larger element to the right $\implies -1$.
    \end{itemize}
    Result: $\text{NGE} = [4, 4, -1, -1]$.

    \item \textbf{Previous Greater Element (PGE)}:
    \begin{itemize}
        \item $A[0] = 3$: nothing to the left $\implies -1$.
        \item $A[1] = 1$: hits $A[0] = 3 > 1 \implies \text{PGE}[1] = 3$ (index $0$).
        \item $A[2] = 4$: neither $1$ nor $3$ exceeds $4 \implies -1$.
        \item $A[3] = 2$: hits $A[2] = 4 > 2 \implies \text{PGE}[3] = 4$ (index $2$).
    \end{itemize}
    Result: $\text{PGE} = [-1, 3, -1, 4]$.

    \item \textbf{Next Smaller Element (NSE)}:
    \begin{itemize}
        \item $A[0] = 3$: hits $A[1] = 1 < 3 \implies \text{NSE}[0] = 1$ (index $1$).
        \item $A[1] = 1$: no smaller element to the right $\implies -1$.
        \item $A[2] = 4$: hits $A[3] = 2 < 4 \implies \text{NSE}[2] = 2$ (index $3$).
        \item $A[3] = 2$: nothing to the right $\implies -1$.
    \end{itemize}
    Result: $\text{NSE} = [1, -1, 2, -1]$.

    \item \textbf{Previous Smaller Element (PSE)}:
    \begin{itemize}
        \item $A[0] = 3$ and $A[1] = 1$: no smaller element to the left $\implies -1$.
        \item $A[2] = 4$: hits $A[1] = 1 < 4 \implies \text{PSE}[2] = 1$ (index $1$).
        \item $A[3] = 2$: skips $4$, hits $A[1] = 1 < 2 \implies \text{PSE}[3] = 1$ (index $1$).
    \end{itemize}
    Result: $\text{PSE} = [-1, -1, 1, 1]$.
\end{enumerate}
\end{example}

\subsection{Why Storing Indices Dominates Storing Values}

Beginners often push raw values $A[i]$ onto the stack, which breaks down as soon as distances or duplicates appear. Storing array \textbf{indices} $i$ instead strictly dominates storing values:
\begin{enumerate}
    \item \textbf{Direct Value Lookup}: Given index $i$, $A[i]$ is available in $O(1)$ time. The reverse fails whenever two positions hold equal values.
    \item \textbf{Instant Spans and Widths}: When index $i$ pops waiting index $j$, the distance is immediately $i - j$ with no extra bookkeeping.
\end{enumerate}

\begin{example}[Distance Calculation and Duplicate Resolution with Indices]
Consider $A = [5, 2, 5, 7]$. We want the distance (span) to the Next Greater Element for each position.
\begin{enumerate}
    \item \textbf{Why Raw Values Fail}: Pushing raw values produces $[5, 5]$ before $7$ arrives. When $7$ pops both $5$s, you cannot tell which $5$ lived at index $0$ and which lived at index $2$.
    \item \textbf{How Index Storing Succeeds}:
    \begin{itemize}
        \item $i = 0$ ($5$): push $0$. Stack: $[0]$.
        \item $i = 1$ ($2$): $2 < 5$, push $1$. Stack: $[0, 1]$.
        \item $i = 2$ ($5$): $5 > A[1]$, pop $1$ ($\text{span}[1] = 2 - 1 = 1$). Push $2$. Stack: $[0, 2]$.
        \item $i = 3$ ($7$): $7 > A[2]$, pop $2$ ($\text{span}[2] = 3 - 2 = 1$). Next $7 > A[0]$, pop $0$ ($\text{span}[0] = 3 - 0 = 3$). Push $3$. Stack: $[3]$.
    \end{itemize}
    Output spans: $[3, 1, 1, 0]$ (where $0$ means no greater element exists).
\end{enumerate}
\end{example}

\begin{tryitbox}{Hand-Trace Drill}{ex1}
Trace \textbf{Next Greater Element (NGE)} from left to right on $A = [2, 5, 3, 7, 1]$ using a decreasing monotonic stack of \emph{indices}. Write down the stack contents after each step $i = 0, 1, 2, 3, 4$, and state the final $\text{NGE}$ value array (using $-1$ when none exists).
\end{tryitbox}

\subsection{Handling Duplicate Values and Avoiding Double-Counting}
\label{sec:duplicates}

\begin{notationbox}[Symbols Used in This Subsection]
$\text{PLE}[i]$ & Previous Less Element: nearest $j < i$ with $A[j] < A[i]$ (strict) & $-1$ if none exists \\ \hline
$\text{NLE}[i]$ & Next Less or Equal Element: nearest $j > i$ with $A[j] \le A[i]$ (non-strict) & $N$ if none exists \\ \hline
$(i - \text{PLE}[i])(\text{NLE}[i] - i)$ & Number of contiguous subarrays where $A[i]$ is the designated minimum & \texttt{long long} \\ \hline
\end{notationbox}

\textbf{The Pain Point:} To sum the minimum of every contiguous subarray in $O(N)$ time, we want to count how many subarrays have $A[i]$ as their minimum and add $A[i] \times \text{count}_i$. When an array has duplicate minimums like $A = [2, 1, 2, 1]$, both $1$s can claim subarrays containing them both, corrupting the sum.

\textbf{The ``Aha!'' Observation:} Every subarray has a unique \emph{rightmost} (last) occurrence of its minimum value (or symmetrically, a unique \emph{leftmost} occurrence). By making one boundary strict ($<$) and the opposite boundary non-strict ($\le$), every tied subarray is assigned to exactly one index with zero overlap and zero gaps.

\textbf{Concrete Mini-Example First:} Take $A = [2, 1, 2, 1]$ ($N = 4$, so $\frac{4 \times 5}{2} = 10$ contiguous subarrays). Two subarrays contain both $1$s: $A[0 \dots 3] = [2, 1, 2, 1]$ and $A[1 \dots 3] = [1, 2, 1]$.
\begin{itemize}
    \item Let the left stop be \textbf{strict} ($A[j] < A[i]$, so equal values to the left do \emph{not} stop expansion) and the right stop be \textbf{non-strict} ($A[j] \le A[i]$, so equal values to the right \emph{do} stop expansion).
    \item Then $i = 1$ stops right before $i = 3$, while $i = 3$ stretches left across $i = 1$. Both tied subarrays belong uniquely to $i = 3$ (their \textbf{last / rightmost} minimum).
\end{itemize}

\textbf{General Formula:} With $\text{PLE}[i]$ strict ($<$) and $\text{NLE}[i]$ non-strict ($\le$), the number of subarrays uniquely owned by index $i$ is:
$$
\text{count}_i = (i - \text{PLE}[i]) \times (\text{NLE}[i] - i)
$$
(Using non-strict $\le$ on the left and strict $<$ on the right is equally valid and designates the \emph{first / leftmost} occurrence instead.)

\textbf{When It Breaks:} Using the \emph{same} comparison on both sides always fails on duplicates:
\begin{itemize}
    \item \textbf{Both strict ($<$)}: Equal values never stop expansion on either side, so both $i = 1$ and $i = 3$ claim $[2, 1, 2, 1]$ and $[1, 2, 1]$, \textbf{double-counting} ($12$ subarrays instead of $10$).
    \item \textbf{Both non-strict ($\le$)}: Equal values stop expansion on both sides, so neither $i = 1$ nor $i = 3$ can cross the other, \textbf{under-counting} ($8$ subarrays instead of $10$).
\end{itemize}

\begin{example}[Symmetry Breaking Verification on $A = \text{[2, 1, 2, 1]}$]
We verify all three boundary rules on $A = [2, 1, 2, 1]$ (total true subarrays $= 10$):
\begin{enumerate}
    \item \textbf{Both Strict ($<$ on Left and Right --- Double-Counts)}:
    \begin{itemize}
        \item $i = 1$: $L = -1$, $R = 4$ ($A[3]=1$ is not $< 1$) $\implies (1 - (-1)) \times (4 - 1) = 6$ subarrays (claims both $[2,1,2,1]$ and $[1,2,1]$).
        \item $i = 3$: $L = -1$ ($A[1]=1$ is not $< 1$), $R = 4 \implies (3 - (-1)) \times (4 - 3) = 4$ subarrays (also claims both $[2,1,2,1]$ and $[1,2,1]$).
        \item $i = 0$ and $i = 2$ each claim $1$ subarray ($[2]$). Total $= 6 + 4 + 1 + 1 = 12$ ($2$ over-counted).
    \end{itemize}
    \item \textbf{Both Non-Strict ($\le$ on Left and Right --- Under-Counts)}:
    \begin{itemize}
        \item $i = 1$: $L = -1$, $R = 3$ (stopped by $A[3]=1 \le 1$) $\implies 2 \times 2 = 4$ subarrays.
        \item $i = 3$: $L = 1$ (stopped by $A[1]=1 \le 1$), $R = 4 \implies 2 \times 1 = 2$ subarrays.
        \item $i = 0$ and $i = 2$ each claim $1$ subarray. Total $= 4 + 2 + 1 + 1 = 8$ ($[2,1,2,1]$ and $[1,2,1]$ are missed).
    \end{itemize}
    \item \textbf{Asymmetric (Strict $<$ Left, Non-Strict $\le$ Right --- Exact)}:
    \begin{itemize}
        \item $i = 1$: $\text{PLE}[1] = -1$, $\text{NLE}[1] = 3 \implies 2 \times 2 = 4$ ($[2, 1], [2, 1, 2], [1], [1, 2]$).
        \item $i = 3$: $\text{PLE}[3] = -1$, $\text{NLE}[3] = 4 \implies 4 \times 1 = 4$ ($[2, 1, 2, 1], [1, 2, 1], [2, 1], [1]$).
        \item $i = 0$ and $i = 2$: $1$ each. Total $= 4 + 4 + 1 + 1 = 10$, an exact partition.
    \end{itemize}
\end{enumerate}
\end{example}

\subsection{Boundary Expansion: Largest Rectangle in Histogram}

\begin{notationbox}[Symbols Used in This Subsection]
$H[i]$ & Height of the $i$-th histogram bar (each bar has unit width $1$) & Non-negative \texttt{int} \\ \hline
$L$ & Left boundary: index of first bar left of $i$ strictly shorter than $H[i]$ & $\text{PSE}[i]$ ($-1$ if none) \\ \hline
$R$ & Right boundary: index of first bar right of $i$ strictly shorter than $H[i]$ & $\text{NSE}[i]$ ($N$ if none) \\ \hline
$\text{Width}$ & Horizontal span of the widest rectangle of height $H[i]$ & $R - L - 1$ \\ \hline
\end{notationbox}

\textbf{The Pain Point:} Testing every pair of left and right bar indices $[l, r]$ and tracking the minimum bar height between them requires $O(N^2)$ pairs.

\textbf{The ``Aha!'' Observation:} Any maximum-area rectangle must have its top edge flush with at least one bar $H[i]$ (otherwise you could grow it upward). Flipping the question from ``pick two endpoints'' to ``pick the bottleneck bar $i$ and expand it as wide as possible'' reduces the search to $N$ bars.

\textbf{Concrete Mini-Example First:} Look at bar $2$ ($H[2] = 5$) in $H = [2, 1, 5, 6, 2, 3]$ (Figure~\ref{fig:histogram_expansion}). Moving left, bar $1$ ($H[1]=1 < 5$) stops expansion at $L = 1$. Moving right, bar $3$ ($H[3]=6 \ge 5$) fits, and bar $4$ ($H[4]=2 < 5$) stops expansion at $R = 4$. The open interval $(1, 4)$ contains bars $\{2, 3\}$, giving width $4 - 1 - 1 = 2$ and area $5 \times 2 = 10$.

In general, for any bar $i$ bounded by $L$ and $R$:
$$
\text{Width} = R - L - 1, \qquad \text{Area} = H[i] \times (R - L - 1)
$$
A single pass with an increasing monotonic stack computes both $L$ and $R$ at once: when bar $R$ pops bar $i$, the right boundary is $R$ and the left boundary $L$ is the new stack top (or $-1$ if empty).

\textbf{When It Breaks:} If you omit the trailing sentinel bar (height $-1$ at index $N$), bars that never meet a shorter bar to their right stay on the stack forever. On an increasing histogram like $H = [1, 2, 3]$, zero bars get popped and the algorithm falsely returns area $0$.

\begin{example}[Numerical Bar-by-Bar Expansion for Histogram]
For $H = [2, 1, 5, 6, 2, 3]$ in Figure~\ref{fig:histogram_expansion}, the maximal rectangle anchored at each bar $i$ is:
\begin{enumerate}
    \item \textbf{Bar $0$ ($H[0] = 2$)}: $L = -1$, $R = 1 \implies \text{Width} = 1$, $\text{Area} = 2 \times 1 = 2$.
    \item \textbf{Bar $1$ ($H[1] = 1$)}: $L = -1$, $R = 6 \implies \text{Width} = 6$, $\text{Area} = 1 \times 6 = 6$.
    \item \textbf{Bar $2$ ($H[2] = 5$)}: $L = 1$, $R = 4 \implies \text{Width} = 2$, $\text{Area} = 5 \times 2 = 10$.
    \item \textbf{Bar $3$ ($H[3] = 6$)}: $L = 2$, $R = 4 \implies \text{Width} = 1$, $\text{Area} = 6 \times 1 = 6$.
    \item \textbf{Bar $4$ ($H[4] = 2$)}: $L = 1$, $R = 6 \implies \text{Width} = 4$, $\text{Area} = 2 \times 4 = 8$.
    \item \textbf{Bar $5$ ($H[5] = 3$)}: $L = 4$, $R = 6 \implies \text{Width} = 1$, $\text{Area} = 3 \times 1 = 3$.
\end{enumerate}
The maximum area over all bars is $\max(2, 6, 10, 6, 8, 3) = 10$, achieved at bar $2$.
\end{example}

\subsection{Monotonic Deque for Sliding Window Range Extrema}

\begin{notationbox}[Symbols Used in This Subsection]
$K$ & Fixed length of the sliding window ($1 \le K \le N$) & \texttt{int} \\ \hline
$[i - K + 1, i]$ & Active index window ending at step $i$ (for $i \ge K - 1$) & Closed range of size $K$ \\ \hline
\texttt{dq.front()} & Index of the current window maximum (oldest surviving candidate) & Front of \texttt{std::deque<int>} \\ \hline
\texttt{dq.back()} & Index of the most recently inserted candidate & Back of \texttt{std::deque<int>} \\ \hline
\end{notationbox}

\textbf{The Pain Point:} Scanning all $K$ elements inside every window takes $O(NK)$ time (up to $2.5 \times 10^9$ steps when $N = 10^5, K = 5 \times 10^4$). A balanced BST or max-heap cuts this to $O(N \log K)$, which still pays a logarithmic factor per step.

\textbf{The ``Aha!'' Observation:} When a new element $A[i]$ enters the right side of the window, any older element already in the window with $A[j] \le A[i]$ is doubly beaten: $A[i]$ is at least as large \emph{and} will expire later. Thus $A[j]$ can never be the maximum of this window or any future window.

\textbf{Concrete Mini-Example First:} Suppose the window holds $[4, 2]$ (indices $0, 1$) and $A[2] = 5$ arrives. Both $2$ and $4$ are $\le 5$ and older than $5$, so we pop both from the back, leaving only $[5]$. Every surviving candidate in the deque is therefore strictly decreasing from front to back, so \texttt{dq.front()} is always the window maximum.

\textbf{Loop Invariant (Sliding Window Maximum Deque):} After step $i$, \texttt{dq} contains only indices within $[i - K + 1, i]$, sorted in strictly increasing order of index and strictly decreasing order of value $A[\cdot]$.

\begin{enumerate}
    \item \textbf{Front expiry}: If $\texttt{dq.front()} \le i - K$, it has left the window; call \texttt{dq.pop\_front()}.
    \item \textbf{Back domination}: While $A[\texttt{dq.back()}] \le A[i]$, call \texttt{dq.pop\_back()}.
    \item \textbf{Push \& query}: Push $i$ to the back; once $i \ge K - 1$, record $A[\texttt{dq.front()}]$.
\end{enumerate}

\textbf{When It Breaks:} Omitting the front expiry check leaves stale maximums stuck at the front forever. On $A = [9, 1, 1, 1]$ with $K = 2$, the front stays at index $0$ ($9$) even for windows $[1, 1]$, returning $[9, 9, 9]$ instead of $[9, 1, 1]$.

\begin{example}[Step-by-Step Monotonic Deque Sliding Window Trace]
Let $A = [4, 2, 5, 1, 3]$ with window size $K = 3$. We find the maximum of each window:
\begin{enumerate}
    \item \textbf{$i = 0$, $A[0] = 4$}: Push $0$. Deque indices: $[0]$ (values: $[4]$).
    \item \textbf{$i = 1$, $A[1] = 2$}: $2 < 4$, push $1$. Deque: $[0, 1]$ (values: $[4, 2]$).
    \item \textbf{$i = 2$, $A[2] = 5$}:
    \begin{itemize}
        \item Back evictions: $A[1] = 2 \le 5$ (pop $1$); $A[0] = 4 \le 5$ (pop $0$).
        \item Push $2$. Deque: $[2]$ (values: $[5]$). Window $[0 \dots 2]$ max $= A[2] = 5$.
    \end{itemize}
    \item \textbf{$i = 3$, $A[3] = 1$}:
    \begin{itemize}
        \item Front $2 > 3 - 3 = 0$ (still valid). $1 < 5$, push $3$. Deque: $[2, 3]$ (values: $[5, 1]$).
        \item Window $[1 \dots 3]$ max $= A[2] = 5$.
    \end{itemize}
    \item \textbf{$i = 4$, $A[4] = 3$}:
    \begin{itemize}
        \item Front $2 > 4 - 3 = 1$ (valid). Back eviction: $A[3] = 1 \le 3$ (pop $3$).
        \item Push $4$. Deque: $[2, 4]$ (values: $[5, 3]$). Window $[2 \dots 4]$ max $= A[2] = 5$.
    \end{itemize}
\end{enumerate}
Final window maximums: $[5, 5, 5]$, computed in amortized $O(1)$ per step.
\end{example}

After each step $i = 0 \dots 4$, write the deque's stored \emph{indices}, the emitted window maximum (for $i \ge 2$), and identify which index is evicted from the \textbf{front} versus which indices are evicted from the \textbf{back}.
\end{tryitbox}

\subsection{Why Naive Brute-Force Fails}

A naive algorithm searches for the Next Greater Element with a nested scan:
\begin{lstlisting}[numbers=none]
// Naive O(N^2) search
for (int i = 0; i < n; ++i) {
    int nge = -1;
    for (int j = i + 1; j < n; ++j) {
        if (A[j] > A[i]) { nge = A[j]; break; }
    }
    ans[i] = nge;
}
\end{lstlisting}

On a strictly descending array $[10^5, 10^5 - 1, \dots, 1]$, every index $i$ inspects all $N - 1 - i$ elements to its right before giving up:
$$
\sum_{i=0}^{N-1} (N - 1 - i) = \frac{N(N - 1)}{2} = O(N^2)
$$
At $N = 10^5$, that is $\approx 5 \times 10^9$ comparisons, far beyond a typical $1$-second budget ($\approx 10^8$ operations).

\vspace{0.2cm}
\noindent
\begin{tabularx}{\textwidth}{|p{3.4cm}|X|X|p{2.3cm}|}
\hline
\textbf{Problem Class} & \textbf{Naive Approach} & \textbf{Monotonic Insight} & \textbf{Speedup} \\ \hline
Nearest Extrema & Inner loop scans right/left per element & Stack keeps only undominated candidates & $O(N^2) \to O(N)$ \\ \hline
Histogram Area & Check all $\binom{N}{2}$ pairs $[l, r]$ & Expand each bar $i$ to $\text{PSE}$ and $\text{NSE}$ & $O(N^2) \to O(N)$ \\ \hline
Sliding Window Max & Rescan $K$ elements (or heap $O(\log K)$) & Deque evicts expired front \& dominated back & $O(NK) \to O(N)$ \\ \hline
\end{tabularx}
\vspace{0.3cm}

\subsection{The Amortized Linear Time Invariant}

\textbf{The Pain Point:} Seeing a \texttt{while} loop nested inside a \texttt{for} loop looks like $O(N^2)$ at first glance:
\begin{lstlisting}[numbers=none]
for (int i = 0; i < n; ++i) {
    while (!st.empty() && A[st.top()] < A[i]) {
        ans[st.top()] = A[i];
        st.pop();
    }
    st.push(i);
}
\end{lstlisting}

\textbf{The ``Aha!'' Observation (Charge the Element, Not the Iteration):} Instead of bounding the worst single iteration (which can pop up to $N - 1$ items), count how many times each individual element touches the stack across the \emph{entire} run:
\begin{itemize}
    \item Each index $i \in \{0, \dots, N - 1\}$ is pushed onto the stack \textbf{exactly once} ($\le N$ pushes total).
    \item Only an element currently on the stack can be popped, so each index is popped \textbf{at most once} ($\le N$ pops total).
    \item The \texttt{while} loop body executes once per pop.
\end{itemize}

Therefore the nested loop executes at most $N$ pushes plus $N$ pops across all iterations combined, giving $O(N)$ total time and $O(1)$ amortized cost per element. The exact same $2N$ push/pop budget holds for the monotonic deque.

\subsection{Example 1: Next Greater Element (NGE)}
\label{ex:nge}

\textbf{Problem Statement}: Given array $A = [4, 5, 2, 25, 10, 8]$, find the Next Greater Element for every element. If none exists, output $-1$.

\textbf{Method}: Iterate left-to-right maintaining a decreasing stack of indices. Any index still on the stack at the end has no greater element to its right.

\begin{enumerate}
    \item \textbf{Initialize}: $ans = [-1, -1, -1, -1, -1, -1]$, $st = []$.
    \item \textbf{$i = 0$, $A[0] = 4$}: Stack empty. Push $0$. Stack: $[0]$.
    \item \textbf{$i = 1$, $A[1] = 5$}: $A[0] = 4 < 5 \implies$ pop $0$, set $ans[0] = 5$. Push $1$. Stack: $[1]$.
    \item \textbf{$i = 2$, $A[2] = 2$}: $A[1] = 5 \not< 2$. Push $2$. Stack: $[1, 2]$.
    \item \textbf{$i = 3$, $A[3] = 25$}:
    \begin{itemize}
        \item $A[2] = 2 < 25 \implies$ pop $2$, set $ans[2] = 25$.
        \item $A[1] = 5 < 25 \implies$ pop $1$, set $ans[1] = 25$.
        \item Stack empty. Push $3$. Stack: $[3]$.
    \end{itemize}
    \item \textbf{$i = 4$, $A[4] = 10$}: $A[3] = 25 \not< 10$. Push $4$. Stack: $[3, 4]$.
    \item \textbf{$i = 5$, $A[5] = 8$}: $A[4] = 10 \not< 8$. Push $5$. Stack: $[3, 4, 5]$.
    \item \textbf{Completion}: Indices $3, 4, 5$ remain unresolved, keeping $-1$.
\end{enumerate}

\noindent\textbf{Final Result}: $ans = [5, 25, 25, -1, -1, -1]$.

\subsection{Example 2: Daily Temperature Span (Index Distance)}

\textbf{Problem Statement}: Given daily temperatures $T = [73, 74, 75, 71, 69, 72, 76, 73]$, find how many days you must wait until a warmer temperature occurs. If no warmer day exists, record $0$.

\textbf{Method}: Maintain a decreasing stack of indices. When day $i$ is warmer than day $st.\text{top}()$, the span is $i - st.\text{top}()$.

\vspace{0.2cm}
\noindent
\begin{tabularx}{\textwidth}{|c|c|c|X|X|c|}
\hline
\textbf{Day $i$} & \textbf{Temp $T[i]$} & \textbf{Stack Before} & \textbf{Popped Indices} & \textbf{Span Result ($i - \text{top}$)} & \textbf{Stack After} \\ \hline
$0$ & $73$ & $[]$ & None & None & $[0]$ \\ \hline
$1$ & $74$ & $[0]$ & $0$ ($73 < 74$) & $span[0] = 1 - 0 = 1$ & $[1]$ \\ \hline
$2$ & $75$ & $[1]$ & $1$ ($74 < 75$) & $span[1] = 2 - 1 = 1$ & $[2]$ \\ \hline
$3$ & $71$ & $[2]$ & None & None & $[2, 3]$ \\ \hline
$4$ & $69$ & $[2, 3]$ & None & None & $[2, 3, 4]$ \\ \hline
$5$ & $72$ & $[2, 3, 4]$ & $4$ ($69 < 72$), $3$ ($71 < 72$) & $span[4] = 5 - 4 = 1$, $span[3] = 5 - 3 = 2$ & $[2, 5]$ \\ \hline

$7$ & $73$ & $[6]$ & None & None & $[6, 7]$ \\ \hline
\end{tabularx}

\noindent\textbf{Final Result}: $span = [1, 1, 4, 2, 1, 1, 0, 0]$.

\subsection{Example 3: Largest Rectangle in Histogram Trace}

\textbf{Problem Statement}: Heights $H = [2, 1, 5, 6, 2, 3]$. Compute the maximum rectangular area.

\textbf{Method}: Maintain an increasing stack of indices. Append a sentinel bar of height $-1$ at index $6$ to flush all remaining bars.

\begin{enumerate}
    \item \textbf{Initialize}: $max\_area = 0$, $st = []$.
    \item \textbf{$i = 0$, $H[0] = 2$}: Push $0$. Stack: $[0]$.
    \item \textbf{$i = 1$, $H[1] = 1$}: $H[0] = 2 > 1$. Pop $0$.
    \begin{itemize}
        \item $h = 2$, stack empty ($L = -1$), $\text{Width} = 1 - (-1) - 1 = 1$, $\text{Area} = 2$. $max\_area = 2$.
        \item Push $1$. Stack: $[1]$.
    \end{itemize}
    \item \textbf{$i = 2$, $H[2] = 5$}: Push $2$. Stack: $[1, 2]$.
    \item \textbf{$i = 3$, $H[3] = 6$}: Push $3$. Stack: $[1, 2, 3]$.
    \item \textbf{$i = 4$, $H[4] = 2$}: $H[3] = 6 > 2$.
    \begin{itemize}
        \item Pop $3$: $h = 6$, new top $L = 2$, $\text{Width} = 4 - 2 - 1 = 1$, $\text{Area} = 6$. $max\_area = 6$.
        \item Pop $2$ ($H[2] = 5 > 2$): $h = 5$, new top $L = 1$, $\text{Width} = 4 - 1 - 1 = 2$, $\text{Area} = 10$. $max\_area = 10$.
        \item Top is $1$ ($H[1] = 1 \le 2$). Stop. Push $4$. Stack: $[1, 4]$.
    \end{itemize}
    \item \textbf{$i = 5$, $H[5] = 3$}: Push $5$. Stack: $[1, 4, 5]$.
    \item \textbf{$i = 6$ (Sentinel $-1$)}: Flushes remaining bars:
    \begin{itemize}
        \item Pop $5$: $h = 3$, $L = 4$, $\text{Width} = 6 - 4 - 1 = 1$, $\text{Area} = 3$.
        \item Pop $4$: $h = 2$, $L = 1$, $\text{Width} = 6 - 1 - 1 = 4$, $\text{Area} = 8$.
        \item Pop $1$: $h = 1$, $L = -1$, $\text{Width} = 6 - (-1) - 1 = 6$, $\text{Area} = 6$.
    \end{itemize}
\end{enumerate}

\noindent\textbf{Final Result}: $max\_area = 10$ (spanning indices $2$ and $3$).

\subsection{Example 4: Sliding Window Maximum Trace}

\textbf{Problem Statement}: $A = [1, 3, -1, -3, 5, 3, 6, 7]$, window size $K = 3$. Compute the maximum for each window.

\begin{enumerate}
    \item $i = 0$, $A[0] = 1$: Deque: $[0]$.
    \item $i = 1$, $A[1] = 3$: $1 \le 3$, pop $0$ from back. Push $1$. Deque: $[1]$.
    \item $i = 2$, $A[2] = -1$: $A[\text{back}] = 3 \le -1$ is false. Push $2$. Deque: $[1, 2]$. Window $[0 \dots 2]$ max $= A[1] = 3$.
    \item $i = 3$, $A[3] = -3$: Front $1 > 3 - 3 = 0$; $-1 \le -3$ is false. Push $3$. Deque: $[1, 2, 3]$. Window $[1 \dots 3]$ max $= A[1] = 3$.
    \item $i = 4$, $A[4] = 5$:
    \begin{itemize}
        \item Front check: $1 \le 4 - 3 = 1$, expired! Pop $1$ from front.
        \item Back pops: $-3 \le 5 \implies$ pop $3$; $-1 \le 5 \implies$ pop $2$.
        \item Push $4$. Deque: $[4]$. Window $[2 \dots 4]$ max $= A[4] = 5$.
    \end{itemize}
    \item $i = 5$, $A[5] = 3$: Push $5$. Deque: $[4, 5]$. Window $[3 \dots 5]$ max $= A[4] = 5$.
    \item $i = 6$, $A[6] = 6$: Pop $5$ ($3 \le 6$) and $4$ ($5 \le 6$) from back. Push $6$. Deque: $[6]$. Window $[4 \dots 6]$ max $= A[6] = 6$.
    \item $i = 7$, $A[7] = 7$: Pop $6$ ($6 \le 7$) from back. Push $7$. Deque: $[7]$. Window $[5 \dots 7]$ max $= A[7] = 7$.
\end{enumerate}

\noindent\textbf{Final Result}: Window maximums $= [3, 3, 5, 5, 6, 7]$.

\subsection{Example 5: Sum of Subarray Minimums (Handling Duplicates)}
\label{ex:subarray_mins}

\textbf{Problem Statement}: Given array $A = [3, 1, 2, 1]$, compute the sum of $\min(B)$ over all contiguous subarrays $B$, modulo $10^9 + 7$.

\textbf{Method}: Break duplicate ties by assigning each subarray to the \emph{last} (rightmost) occurrence of its minimum:
\begin{itemize}
    \item $\text{PLE}[i]$: Previous Less Element using a \emph{strict} comparison ($A[j] < A[i]$).
    \item $\text{NLE}[i]$: Next Less or Equal Element using a \emph{non-strict} comparison ($A[j] \le A[i]$).
\end{itemize}

\begin{enumerate}
    \item \textbf{Step 1: Compute $\text{PLE}$ (Strict $<$, pop while $A[\text{top}] \ge A[i]$)}:
    \begin{itemize}
        \item $i = 0$ ($3$): stack empty $\implies \text{PLE}[0] = -1$. Push $0$. Stack: $[0]$.
        \item $i = 1$ ($1$): $3 \ge 1$, pop $0 \implies \text{PLE}[1] = -1$. Push $1$. Stack: $[1]$.
        \item $i = 2$ ($2$): $1 < 2$, no pop $\implies \text{PLE}[2] = 1$. Push $2$. Stack: $[1, 2]$.
        \item $i = 3$ ($1$): $2 \ge 1$ (pop $2$), $1 \ge 1$ (pop $1$) $\implies \text{PLE}[3] = -1$. Push $3$. Stack: $[3]$.
    \end{itemize}
    Result: $\text{PLE} = [-1, -1, 1, -1]$.

    \item \textbf{Step 2: Compute $\text{NLE}$ (Non-strict $\le$, scan right-to-left, pop while $A[\text{top}] > A[i]$)}:
    \begin{itemize}
        \item $i = 3$ ($1$): stack empty $\implies \text{NLE}[3] = 4$. Push $3$. Stack: $[3]$.
        \item $i = 2$ ($2$): $1 \ngtr 2$, no pop $\implies \text{NLE}[2] = 3$. Push $2$. Stack: $[3, 2]$.
        \item $i = 1$ ($1$): $2 > 1$ (pop $2$), $1 \ngtr 1$ (stop!) $\implies \text{NLE}[1] = 3$. Push $1$. Stack: $[3, 1]$.
        \item $i = 0$ ($3$): $1 \ngtr 3$, no pop $\implies \text{NLE}[0] = 1$. Push $0$. Stack: $[3, 1, 0]$.
    \end{itemize}
    Result: $\text{NLE} = [1, 3, 3, 4]$.

    \item \textbf{Step 3: Subarray Contribution Products}:
    \begin{itemize}
        \item $i = 0$ ($3$): $(0 - (-1)) \times (1 - 0) = 1 \implies 3 \times 1 = 3$ ($[3]$).
        \item $i = 1$ ($1$): $(1 - (-1)) \times (3 - 1) = 4 \implies 1 \times 4 = 4$ ($[3,1], [3,1,2], [1], [1,2]$).
        \item $i = 2$ ($2$): $(2 - 1) \times (3 - 2) = 1 \implies 2 \times 1 = 2$ ($[2]$).
        \item $i = 3$ ($1$): $(3 - (-1)) \times (4 - 3) = 4 \implies 1 \times 4 = 4$ ($[3,1,2,1], [1,2,1], [2,1], [1]$).
    \end{itemize}

    \item \textbf{Step 4: Total Sum}:
    $$
    \text{Total Sum} = 3 + 4 + 2 + 4 = 13 \pmod{10^9 + 7}
    $$
    Notice that $A[0 \dots 3] = [3, 1, 2, 1]$ and $A[1 \dots 3] = [1, 2, 1]$ are claimed uniquely by $i = 3$ (the last occurrence of $1$), while $A[1 \dots 2] = [1, 2]$ is claimed by $i = 1$. All $10$ subarrays are counted once.
\end{enumerate}

\noindent\textbf{Final Result}: Total subarray minimum sum $= 13$.

\subsection{Example 6: Remove $K$ Digits (Lexicographical Monotonic Stack)}
\label{ex:remove_k_digits}

\textbf{Problem Statement}: Given a non-negative integer string $S = \texttt{"1432219"}$ and removal budget $K = 3$, remove exactly $K$ digits to form the smallest possible integer.

\textbf{Method}: A smaller digit in an earlier (more significant) place value always beats any change in later digits. Maintain a non-decreasing stack of digits: whenever an incoming digit $d$ is strictly smaller than the stack top and $K > 0$, pop the larger top digit and decrement $K$.

\begin{enumerate}
    \item $d = \texttt{'1'}$: stack empty, push $\texttt{'1'}$. Stack: $\texttt{"1"}$, $K = 3$.
    \item $d = \texttt{'4'}$: $\texttt{'1'} \le \texttt{'4'}$, push $\texttt{'4'}$. Stack: $\texttt{"14"}$, $K = 3$.
    \item $d = \texttt{'3'}$: $\texttt{'4'} > \texttt{'3'}$ and $K = 3 > 0 \implies$ pop $\texttt{'4'}$ ($K = 2$). $\texttt{'1'} \le \texttt{'3'}$, stop. Push $\texttt{'3'}$. Stack: $\texttt{"13"}$, $K = 2$.
    \item $d = \texttt{'2'}$: $\texttt{'3'} > \texttt{'2'}$ and $K = 2 > 0 \implies$ pop $\texttt{'3'}$ ($K = 1$). $\texttt{'1'} \le \texttt{'2'}$, stop. Push $\texttt{'2'}$. Stack: $\texttt{"12"}$, $K = 1$.
    \item $d = \texttt{'2'}$: $\texttt{'2'} \not> \texttt{'2'}$ (do not waste budget on equal digits). Push $\texttt{'2'}$. Stack: $\texttt{"122"}$, $K = 1$.
    \item $d = \texttt{'1'}$: $\texttt{'2'} > \texttt{'1'}$ and $K = 1 > 0 \implies$ pop $\texttt{'2'}$ ($K = 0$). Budget spent; push $\texttt{'1'}$. Stack: $\texttt{"121"}$, $K = 0$.
    \item $d = \texttt{'9'}$: $K = 0$, push $\texttt{'9'}$. Stack: $\texttt{"1219"}$, $K = 0$.
    \item \textbf{Post-processing}: If $K > 0$ remains (e.g., $\texttt{"12345"}$), pop $K$ largest digits from the back; then strip leading zeros (returning $\texttt{"0"}$ if empty).
\end{enumerate}

\noindent\textbf{Final Result}: $\texttt{"1219"}$.

\section{C++ Implementations}
% ============================================================================

All implementations use modern C++23. Sequence inputs are passed as \texttt{std::span<const int>} or \texttt{std::string\_view} for zero-copy views, with explicit sizing and \texttt{[[nodiscard]]}.

\subsection{Next Greater Element}

We scan left-to-right keeping indices of unresolved elements in a decreasing stack backed by \texttt{std::vector<int>}. Whenever \texttt{nums[i]} exceeds \texttt{nums[stack.back()]}, it resolves and pops that index immediately.

\begin{lstlisting}[caption=Next Greater Element in C++23]
#include <vector>
#include <span>

[[nodiscard]] std::vector<int> next_greater_elements(std::span<const int> nums) {
    const int n = static_cast<int>(nums.size());
    std::vector<int> result(n, -1);
    std::vector<int> stack; // Stores indices
    stack.reserve(n);

    for (int i = 0; i < n; ++i) {
        // Pop elements whose next greater element is nums[i]
        while (!stack.empty() && nums[stack.back()] < nums[i]) {
            result[stack.back()] = nums[i];
            stack.pop_back();
        }
        stack.push_back(i);
    }
    return result;
}
\end{lstlisting}

\subsection{Next Smaller Element}

Mirroring NGE, we maintain an increasing monotonic stack of indices. Whenever an incoming value is strictly smaller than the value at the stack top, it pops and resolves all waiting taller entries.

\begin{lstlisting}[caption=Next Smaller Element in C++23]
#include <vector>
#include <span>

[[nodiscard]] std::vector<int> next_smaller_elements(std::span<const int> nums) {
    const int n = static_cast<int>(nums.size());
    std::vector<int> result(n, -1);
    std::vector<int> stack; // Stores indices
    stack.reserve(n);

    for (int i = 0; i < n; ++i) {
        // Pop elements whose next smaller element is nums[i]
        while (!stack.empty() && nums[stack.back()] > nums[i]) {
            result[stack.back()] = nums[i];
            stack.pop_back();
        }
        stack.push_back(i);
    }
    return result;
}
\end{lstlisting}

\subsection{Distance to Next Warmer Day (Span Calculation)}

Because the stack stores indices rather than raw temperatures, the waiting distance for each popped day is simply \texttt{i - prev\_index}.

\begin{lstlisting}[caption=Span Calculation / Daily Temperatures in C++23]
#include <vector>
#include <span>

[[nodiscard]] std::vector<int> daily_temperatures(std::span<const int> temperatures) {
    const int n = static_cast<int>(temperatures.size());
    std::vector<int> answer(n, 0);
    std::vector<int> stack;
    stack.reserve(n);

    for (int i = 0; i < n; ++i) {
        while (!stack.empty() && temperatures[stack.back()] < temperatures[i]) {
            const int prev_index = stack.back();
            stack.pop_back();
            answer[prev_index] = i - prev_index;
        }
        stack.push_back(i);
    }
    return answer;
}
\end{lstlisting}

\subsection{Largest Rectangle in Histogram}

An increasing stack tracks candidate bars (assuming non-negative heights). When a shorter or equal bar arrives at index \texttt{i}, every popped bar knows both its right boundary (\texttt{i}) and its left boundary (the new stack top, or \texttt{-1}). A sentinel height \texttt{-1} at \texttt{i == n} flushes all remaining bars.

\begin{lstlisting}[caption=Largest Rectangle in Histogram in C++23]
#include <vector>
#include <span>
#include <algorithm>

[[nodiscard]] long long largest_rectangle_area(std::span<const int> heights) {
    const int n = static_cast<int>(heights.size());
    std::vector<int> stack;
    stack.reserve(n);
    long long max_area = 0;

    for (int i = 0; i <= n; ++i) {
        // Use -1 as sentinel height at index n to flush all non-negative bars
        const int current_height = (i == n) ? -1 : heights[i];

        while (!stack.empty() && heights[stack.back()] >= current_height) {
            const int h = heights[stack.back()];
            stack.pop_back();
            const int left_boundary = stack.empty() ? -1 : stack.back();
            const long long width = i - left_boundary - 1;
            max_area = std::max(max_area, static_cast<long long>(h) * width);
        }
        stack.push_back(i);
    }
    return max_area;
}
\end{lstlisting}

\subsection{Sliding Window Maximum with Monotonic Deque}

A \texttt{std::deque<int>} stores indices in strictly decreasing order of value. Each iteration removes any expired front index, purges dominated back indices, pushes \texttt{i}, and emits \texttt{nums[dq.front()]} once the window reaches size \texttt{k}.

\begin{lstlisting}[caption=Sliding Window Maximum in C++23]
#include <vector>
#include <deque>
#include <span>

[[nodiscard]] std::vector<int> max_sliding_window(std::span<const int> nums, int k) {
    const int n = static_cast<int>(nums.size());
    if (n == 0 || k <= 0 || k > n) return {};

    std::vector<int> result;
    result.reserve(n - k + 1);
    std::deque<int> dq; // Stores indices of candidate maximums

    for (int i = 0; i < n; ++i) {
        // 1. Remove indices that fell out of the window boundary
        if (!dq.empty() && dq.front() <= i - k) {
            dq.pop_front();
        }

        // 2. Remove indices whose values are dominated by nums[i]
        while (!dq.empty() && nums[dq.back()] <= nums[i]) {
            dq.pop_back();
        }

        // 3. Add current element index to the back
        dq.push_back(i);

        // 4. Record current window maximum once initial window is full
        if (i >= k - 1) {
            result.push_back(nums[dq.front()]);
        }
    }
    return result;
}
\end{lstlisting}

\subsection{Sum of Subarray Minimums with Duplicate Prevention}

Two linear passes compute strict $\text{PLE}$ (left) and non-strict $\text{NLE}$ (right), assigning every subarray uniquely to the last occurrence of its minimum. Modular reduction uses positive normalization so negative array entries stay safe.

\begin{lstlisting}[caption=Sum of Subarray Minimums with Symmetry Breaking in C++23]
#include <vector>
#include <span>

[[nodiscard]] long long sum_subarray_mins(std::span<const int> arr) {
    const int n = static_cast<int>(arr.size());
    constexpr long long MOD = 1'000'000'007;

    std::vector<int> ple(n); // Previous Less Element (Strict)
    std::vector<int> nle(n); // Next Less or Equal Element (Non-strict)
    std::vector<int> stack;
    stack.reserve(n);

    // Compute Previous Less Element (strictly less)
    for (int i = 0; i < n; ++i) {
        while (!stack.empty() && arr[stack.back()] >= arr[i]) {
            stack.pop_back();
        }
        ple[i] = stack.empty() ? -1 : stack.back();
        stack.push_back(i);
    }

    stack.clear();

    // Compute Next Less or Equal Element (less than or equal)
    for (int i = n - 1; i >= 0; --i) {
        while (!stack.empty() && arr[stack.back()] > arr[i]) {
            stack.pop_back();
        }
        nle[i] = stack.empty() ? n : stack.back();
        stack.push_back(i);
    }

    long long total_sum = 0;
    for (int i = 0; i < n; ++i) {
        const long long left_count = i - ple[i];
        const long long right_count = nle[i] - i;
        const long long count = (left_count * right_count) % MOD;
        const long long term = (count * ((arr[i] % MOD + MOD) % MOD)) % MOD;
        total_sum = (total_sum + term) % MOD;
    }
    return total_sum;
}
\end{lstlisting}

\subsection{Remove $K$ Digits (Lexicographical Monotonic Stack)}

Using \texttt{std::string} directly as a non-decreasing stack avoids extra allocations. We pop larger preceding digits while the budget \texttt{k} allows, trim any leftover removals from the right end, and strip leading zeros.

\begin{lstlisting}[caption=Remove K Digits with Monotonic Stack in C++23]
#include <string>
#include <string_view>

[[nodiscard]] std::string remove_k_digits(std::string_view num, int k) {
    if (num.empty() || k >= static_cast<int>(num.size())) return "0";
    if (k < 0) k = 0;

    std::string stack;
    stack.reserve(num.size());

    for (char digit : num) {
        // Pop strictly larger preceding digits while removal budget remains
        while (!stack.empty() && k > 0 && stack.back() > digit) {
            stack.pop_back();
            --k;
        }
        stack.push_back(digit);
    }

    // Remaining digits are non-decreasing: discard leftover budget from the back
    while (k > 0 && !stack.empty()) {
        stack.pop_back();
        --k;
    }

    // Strip leading zeros; return "0" if all remaining characters are zeros
    const auto first_nonzero = stack.find_first_not_of('0');
    if (first_nonzero == std::string::npos) return "0";
    return stack.substr(first_nonzero);
}
\end{lstlisting}

\section{Problem Pattern Recognition}
% ============================================================================

When analyzing an unfamiliar problem, apply this three-step decision check:

\subsection*{Step 1: What Does the Problem Ask For?}
\begin{itemize}
    \item \textbf{Nearest Extrema Queries}: First strictly larger or smaller element to the left or right $\implies$ Monotonic Stack.
    \item \textbf{Index Distance / Waiting Time}: Days or steps until a threshold is crossed $\implies$ Monotonic Stack storing indices.
    \item \textbf{Subarray Extremum Contributions / Histogram Area}: Sum of subarray mins/maxes or widest bounded rectangle $\implies$ Monotonic Stack with boundary expansion and symmetry breaking.
    \item \textbf{Sliding Window Extremum}: Running min or max over shifting interval $[i - K + 1, i]$ $\implies$ Monotonic Deque.
    \item \textbf{Lexicographically Optimal Subsequence}: Remove $K$ digits/characters to minimize or maximize the remaining sequence $\implies$ Monotonic Stack with removal budget.
\end{itemize}

\subsection*{Step 2: What Is the Key Constraint?}
\begin{itemize}
    \item \textbf{Domination Property}: Does a newer, better element make an older element permanently useless for every future query? If yes, discard dominated items immediately.
    \item \textbf{Contiguous Ranges}: Does the query depend on contiguous order rather than arbitrary subsets? Monotonic stacks and deques rely on index order.
    \item \textbf{Duplicate Values}: Can values repeat? Apply asymmetric bounds (strict on one side, non-strict on the other) whenever partitioning subarrays.
\end{itemize}

\subsection*{Step 3: Is Input Too Large for Direct Solution?}
\begin{itemize}
    \item \textbf{$N \le 10^3$}: An $O(N^2)$ double loop takes $\approx 10^6$ operations and passes easily.
    \item \textbf{$N \ge 10^5$}: An $O(N^2)$ scan takes $\approx 10^{10}$ operations and triggers Time Limit Exceeded (TLE). A monotonic stack or deque runs in $O(N)$ ($\approx 10^5$ operations), finishing in well under $0.05$ seconds.
\end{itemize}

\section{Glossary}
% ============================================================================

\subsection{Core Concepts}
\begin{itemize}
    \item \textbf{Monotonic Stack}: A stack whose elements from bottom to top stay strictly or non-strictly sorted (increasing or decreasing).
    \item \textbf{Monotonic Deque}: A double-ended queue maintaining sorted candidates for $O(1)$ amortized sliding-window queries via front expiry and back dominance eviction.
    \item \textbf{Cascading Pops}: Sequential popping of multiple stack entries when an incoming element violates the monotonic invariant.
    \item \textbf{Domination}: A property where a newer element is both more optimal in value and stays alive longer, making an older element permanently useless.
    \item \textbf{Amortized $O(1)$}: Although one step may trigger up to $N$ pops, every element is pushed once and popped at most once across the entire run, averaging constant work per item.
    \item \textbf{Symmetry Breaking}: Pairing a strict comparison ($<$) on one boundary with a non-strict comparison ($\le$) on the opposite boundary so tied subarrays are counted exactly once.
\end{itemize}

\subsection{Mathematical Symbols}
\begin{itemize}
    \item $N$: Number of elements in the array.
    \item $K$: Fixed length of a sliding window, or digit removal budget.
    \item $O(N)$: Linear time complexity, proportional to the input size.
    \item $A[i]$: Value at $0$-based index $i$ of array $A$.
    \item $H[i]$: Height of the $i$-th bar in a histogram.
    \item $L, R$: Left and right bounding indices limiting horizontal expansion of a histogram bar.
    \item $\text{NGE}, \text{PGE}$: Next Greater Element and Previous Greater Element.
    \item $\text{NSE}, \text{PSE}$: Next Smaller Element and Previous Smaller Element.
    \item $\text{PLE}, \text{NLE}$: Previous Less Element (strict $<$) and Next Less or Equal Element (non-strict $\le$) for symmetry breaking.
    \item $\text{MOD}$: Large prime modulus (commonly $10^9 + 7$) used to prevent integer overflow.
    \item $\le, \ge$: Non-strict inequalities (inclusive of duplicates).
    \item $<, >$: Strict inequalities (exclusive of duplicates).
    \item $\sum$: Summation of terms.
\end{itemize}

\section*{Solutions to Pen-and-Paper Exercises}
\addcontentsline{toc}{section}{Solutions to Pen-and-Paper Exercises}

\begin{enumerate}
    \item \hypertarget{sol:ex1}{\textbf{Next Greater Element Trace on $A = [2, 5, 3, 7, 1]$:}}
    Initialize $\text{NGE} = [-1, -1, -1, -1, -1]$, stack $st = []$.
    \begin{itemize}
        \item $i = 0$ ($2$): push $0$. $st = [0]$.
        \item $i = 1$ ($5$): $A[0] = 2 < 5 \implies$ pop $0$, $\text{NGE}[0] = 5$. Push $1$. $st = [1]$.
        \item $i = 2$ ($3$): $A[1] = 5 \not< 3$. Push $2$. $st = [1, 2]$.
        \item $i = 3$ ($7$): $A[2] = 3 < 7 \implies$ pop $2$, $\text{NGE}[2] = 7$; $A[1] = 5 < 7 \implies$ pop $1$, $\text{NGE}[1] = 7$. Push $3$. $st = [3]$.
        \item $i = 4$ ($1$): $A[3] = 7 \not< 1$. Push $4$. $st = [3, 4]$.
    \end{itemize}
    Final result: $\text{NGE} = [5, 7, 7, -1, -1]$.

    \item \hypertarget{sol:ex2}{\textbf{Histogram Expansion for $H = [3, 1, 4, 2]$ \& Sentinel Break-It:}}
    \textbf{(a)} Bar-by-bar bounds ($N = 4$):
    \begin{itemize}
        \item Bar $0$ ($3$): $L = -1, R = 1 \implies \text{Width} = 1$, $\text{Area} = 3 \times 1 = 3$.
        \item Bar $1$ ($1$): $L = -1, R = 4 \implies \text{Width} = 4$, $\text{Area} = 1 \times 4 = 4$.
        \item Bar $2$ ($4$): $L = 1, R = 3 \implies \text{Width} = 1$, $\text{Area} = 4 \times 1 = 4$.
        \item Bar $3$ ($2$): $L = 1, R = 4 \implies \text{Width} = 2$, $\text{Area} = 2 \times 2 = 4$.
    \end{itemize}
    Maximum area is $\max(3, 4, 4, 4) = 4$.\\
    \textbf{(b)} Take any strictly increasing histogram such as $H = [2, 4, 6]$. Every incoming bar is taller than the stack top, so zero pops occur during $i = 0, 1, 2$. Without the sentinel $-1$ at $i = 3$, the loop ends with $max\_area = 0$ instead of the true maximum $8$ (bars $1$ and $2$ at height $4$).

    \item \hypertarget{sol:ex3}{\textbf{Sliding Window Maximum ($K = 3$) on $A = [4, 1, 3, 5, 2]$:}}
    \begin{itemize}
        \item $i = 0$ ($4$): push $0$. Deque: $[0]$.
        \item $i = 1$ ($1$): $4 > 1$, push $1$. Deque: $[0, 1]$.
        \item $i = 2$ ($3$): pop $1$ from \textbf{back} ($1 \le 3$); push $2$. Deque: $[0, 2]$. Window $[0 \dots 2]$ max $= A[0] = 4$.
        \item $i = 3$ ($5$): pop $0$ from \textbf{front} (expired: $0 \le 3 - 3$); pop $2$ from \textbf{back} ($3 \le 5$); push $3$. Deque: $[3]$. Window $[1 \dots 3]$ max $= A[3] = 5$.
        \item $i = 4$ ($2$): front $3 > 4 - 3$; $5 > 2$; push $4$. Deque: $[3, 4]$. Window $[2 \dots 4]$ max $= A[3] = 5$.
    \end{itemize}
    Final output: $[4, 5, 5]$. Index $0$ was evicted from the \textbf{front} (expired); indices $1$ and $2$ were evicted from the \textbf{back} (dominated).
\end{enumerate}
