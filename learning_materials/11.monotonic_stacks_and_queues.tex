\subsection{What Does ``Monotonic'' Actually Mean?}

A list of numbers is \textbf{monotonic} if it only moves in one direction---never going up and then back down:
\begin{itemize}
    \item \textbf{Increasing (going up)}: like $[1, 3, 5, 8]$, or $[1, 3, 3, 8]$ if equal neighbors are allowed.
    \item \textbf{Decreasing (going down)}: like $[9, 6, 4, 1]$, or $[9, 6, 6, 1]$ if equal neighbors are allowed.
\end{itemize}

A normal stack lets you push anything on top. A \textbf{monotonic stack} enforces one simple rule: before pushing a new value $x$, pop items off the top until pushing $x$ keeps the stack sorted from bottom to top.

\subsection{Why Throwing Away Elements Is Safe: The Skyline Shadow Proof}

\painbeat Finding the first taller building to the right of every building in a row naively takes a nested loop: from each building, walk rightward until you see a taller one. On a staircase going downhill, that checks roughly $N^2 / 2$ pairs.

\ahabeat Imagine standing in a flat concert crowd looking toward the stage. If a $185\text{ cm}$ person stands directly in front of a $170\text{ cm}$ person, nobody further back can ever see the $170\text{ cm}$ person first. The taller, closer person casts a permanent \textbf{shadow} over the shorter one.

\examplebeat Suppose you scan heights from right to left and have seen $[170, 185]$ (with $185$ closer to all viewers on the left). For any viewer standing further left, $185$ is both \emph{closer} and \emph{taller} than $170$. So $170$ can never be the first taller neighbor for anyone left of it---throwing $170$ away loses nothing, and the surviving candidates automatically form a sorted staircase.

\begin{calloutbox}{The Elimination Principle}
Whenever a newer element is both \textbf{better} (larger for a max query, smaller for a min query) and \textbf{closer} to all future queries than an older element, the older element is permanently dominated and can be popped immediately.
\end{calloutbox}

\begin{watchoutbox}[When It Breaks]
Shadow elimination only works when you want the \textbf{nearest} greater (or smaller) item. If a problem instead asks for the \emph{second} greater element, or the maximum over an arbitrary non-contiguous subset, a shadowed item might still matter and cannot be discarded on first sight.
\end{watchoutbox}

\begin{tryitbox}{Trace}{Skyline Shadows Check}{ex1}
You want the \textbf{Next Greater Element} (first taller building to the right) for heights $[160, 190, 175]$. Scanning from right to left:
\begin{enumerate}
    \item Which building height is permanently shadowed and popped?
    \item Which heights survive on the stack (bottom to top), and why does $160$ survive even though $190$ is taller?
\end{enumerate}
\end{tryitbox}

\subsection{Monotonic Stack vs. Monotonic Deque}

A stack only adds and removes from one end. A \textbf{monotonic deque} (double-ended queue) adds a second exit at the front so it can track the maximum or minimum inside a moving window of width $K$:

\begin{itemize}
    \item \textbf{Monotonic Stack}: Best for \emph{nearest-neighbor} questions (first larger or smaller value to the left or right). Waiting indices sit on the stack until an incoming value resolves and pops them.
    \item \textbf{Monotonic Deque}: Best for \emph{sliding-window} questions (largest or smallest value inside the current $K$-element window). It trims from both ends:
    \begin{enumerate}
        \item \textbf{Back eviction}: Pop smaller (dominated) elements from the back when a better value arrives.
        \item \textbf{Front eviction}: Pop expired elements from the front once the window moves past their index.
    \end{enumerate}
\end{itemize}

\subsection{The Four Nearest Extrema Queries}
\label{sec:four_queries}

\begin{notationbox}[Symbols Used in This Subsection]
$A[i]$ & Value at $0$-based position $i$ in the array & \texttt{int} (e.g., $A[2] = 4$) \\
$N$ & Total number of elements in $A$ & $N = \texttt{A.size()}$ \\
NGE / PGE & Next Greater (to the right) / Previous Greater (to the left) & First value $> A[i]$ \\
NSE / PSE & Next Smaller (to the right) / Previous Smaller (to the left) & First value $< A[i]$ \\
\end{notationbox}

Most monotonic-stack problems boil down to one of four simple questions for every position $i$:
\begin{enumerate}
    \item \textbf{Next Greater Element (NGE)}: First position to the right ($j > i$) where $A[j] > A[i]$.
    \item \textbf{Previous Greater Element (PGE)}: First position to the left ($j < i$) where $A[j] > A[i]$.
    \item \textbf{Next Smaller Element (NSE)}: First position to the right ($j > i$) where $A[j] < A[i]$.
    \item \textbf{Previous Smaller Element (PSE)}: First position to the left ($j < i$) where $A[j] < A[i]$.
\end{enumerate}

\invariantbeat{Decreasing Stack for NGE, Left-to-Right} Before processing index $i$, the stack holds all earlier indices that still haven't seen a larger number to their right, ordered from bottom to top from largest value to smallest.

\begin{calloutbox}{Quick Rule: Which Stack Order Do I Need?}
\begin{itemize}
    \item Looking for a \textbf{Greater} neighbor? Keep a \textbf{decreasing stack}. A bigger incoming number breaks the decreasing order and pops smaller waiting items.
    \item Looking for a \textbf{Smaller} neighbor? Keep an \textbf{increasing stack}. A smaller incoming number breaks the increasing order and pops taller waiting items.
    \item Looking \textbf{Right (Next)}? Either scan left-to-right (answer items when popped) or right-to-left (read the surviving top). Looking \textbf{Left (Previous)}? Always scan left-to-right.
\end{itemize}
\end{calloutbox}

\begin{example}[Worked Trace of All Four Queries on $A = {[3, 1, 4, 2]}$]
With indices $0, 1, 2, 3$ and $-1$ meaning ``none exists'':
\begin{enumerate}
    \item \textbf{Next Greater (NGE)}: $3 \to 4$ (idx $2$), $1 \to 4$ (idx $2$), $4 \to -1$, $2 \to -1$. Result: $[4, 4, -1, -1]$.
    \item \textbf{Previous Greater (PGE)}: $3 \to -1$, $1 \to 3$ (idx $0$), $4 \to -1$, $2 \to 4$ (idx $2$). Result: $[-1, 3, -1, 4]$.
    \item \textbf{Next Smaller (NSE)}: $3 \to 1$ (idx $1$), $1 \to -1$, $4 \to 2$ (idx $3$), $2 \to -1$. Result: $[1, -1, 2, -1]$.
    \item \textbf{Previous Smaller (PSE)}: $3 \to -1$, $1 \to -1$, $4 \to 1$ (idx $1$), $2 \to 1$ (idx $1$). Result: $[-1, -1, 1, 1]$.
\end{enumerate}
\end{example}

\subsection{Why Storing Indices Always Beats Storing Raw Values}

A common beginner mistake is pushing raw numbers $A[i]$ onto the stack. Pushing \textbf{array indices} $i$ instead gives you everything for free:
\begin{enumerate}
    \item \textbf{Value is one lookup away}: From index $i$, you always know $A[i]$ in $O(1)$ time. From a raw value like $5$, you cannot tell \emph{which} $5$ it was when duplicates exist.
    \item \textbf{Distances are one subtraction away}: When incoming index $i$ pops waiting index $j$, the gap between them is instantly $i - j$.
\end{enumerate}

\begin{example}[Why Raw Values Fail on $A = {[5, 2, 5, 7]}$]
Suppose we want the distance (span) from each entry to its Next Greater Element:
\begin{enumerate}
    \item \textbf{Raw values fail}: Before $7$ arrives, the stack holds $[5, 5]$. When $7$ pops both $5$s, you cannot tell which $5$ belongs to index $0$ (distance $3$) and which belongs to index $2$ (distance $1$).
    \item \textbf{Indices succeed cleanly}:
    \begin{itemize}
        \item $i = 0$ ($5$): push $0$. Stack: $[0]$.
        \item $i = 1$ ($2$): $2 < 5$, push $1$. Stack: $[0, 1]$.
        \item $i = 2$ ($5$): $5 > A[1] = 2$, so pop $1$ and record $\text{span}[1] = 2 - 1 = 1$. Push $2$. Stack: $[0, 2]$.
        \item $i = 3$ ($7$): pop $2$ ($\text{span}[2] = 3 - 2 = 1$), then pop $0$ ($\text{span}[0] = 3 - 0 = 3$). Push $3$. Stack: $[3]$.
    \end{itemize}
    Final spans: $[3, 1, 1, 0]$ (where $0$ means no larger value lies to the right).
\end{enumerate}
\end{example}

\begin{tryitbox}{Edge Cases}{Index Stack Stress Test}{ex3}
Trace left-to-right \textbf{Daily Temperature Span} (pop while $T[\text{top}] < T[i]$, record $\text{span} = i - \text{top}$, default $0$) on three inputs, recording the output \texttt{span} array and final stack size for each:
\begin{enumerate}
    \item Mixed: $T = [2, 5, 3, 7, 1]$
    \item All equal: $T = [5, 5, 5, 5]$
    \item Strictly decreasing: $T = [9, 7, 5, 3]$
\end{enumerate}
\end{tryitbox}

\subsection{Handling Duplicate Values Without Double-Counting}
\label{sec:duplicates}

\begin{notationbox}[Symbols Used in This Subsection]
$\text{PLE}[i]$ & Previous Less Element: nearest left index with $A[j] < A[i]$ (strict) & $-1$ if none exists \\
$\text{NLE}[i]$ & Next Less or Equal Element: nearest right index with $A[j] \le A[i]$ & $N$ if none exists \\
$\text{left}_i,\;\text{right}_i$ & Choices for subarray start ($i - \text{PLE}[i]$) and end ($\text{NLE}[i] - i$) & Positive integers \\
\end{notationbox}

\painbeat Suppose you want the sum of $\min(B)$ across \emph{every} contiguous subarray $B$ in $O(N)$ time. The trick is to count how many subarrays have $A[i]$ as their minimum, then add $A[i] \times \text{count}_i$. But if the array has duplicate minimums like $A = [2, 1, 2, 1]$, both $1$s fight over subarrays containing them both!

\ahabeat Every subarray containing tied minimums has one unique \textbf{rightmost (last)} copy of that minimum. If we let each index expand \emph{past} equal values on its left (strict stop $<$) but \emph{stop} at equal values on its right (non-strict stop $\le$), every tied subarray is claimed by its rightmost minimum---never twice and never zero times.

\examplebeat Take $A = [2, 1, 2, 1]$ ($N = 4$, giving $10$ total contiguous subarrays). Two subarrays contain both $1$s: $[2, 1, 2, 1]$ and $[1, 2, 1]$.
\begin{itemize}
    \item Index $1$ ($A[1] = 1$) stops on the right at index $3$ (because $A[3] = 1 \le 1$). So index $1$ claims only the $4$ subarrays ending before index $3$.
    \item Index $3$ ($A[3] = 1$) does \emph{not} stop on the left at index $1$ (because $1$ is not strictly less than $1$). So index $3$ claims $[2, 1, 2, 1]$ and $[1, 2, 1]$ uniquely!
\end{itemize}

\begin{formulabox}[Subarray Contribution Formula --- In Plain English]
$$
\text{count}_i = (i - \text{PLE}[i]) \times (\text{NLE}[i] - i)
$$
\textbf{Read this as:} \emph{(number of valid start positions on the left, including $i$)} $\times$ \emph{(number of valid end positions on the right, including $i$)}. Using strict $<$ on the left and non-strict $\le$ on the right assigns every tied subarray to its \textbf{last (rightmost)} minimum. (Swapping them to $\le$ left and $<$ right assigns ties to the \textbf{first} minimum instead.)
\end{formulabox}

\begin{watchoutbox}[When It Breaks --- Symmetric Comparisons]
Using the \emph{same} comparison on both sides always breaks when duplicates exist:
\begin{itemize}
    \item \textbf{Both strict ($<$ on left and right)}: Equal values never stop expansion on either side, so both $1$s claim $[2, 1, 2, 1]$ and $[1, 2, 1]$ --- \textbf{double-counting} ($12$ subarrays instead of $10$).
    \item \textbf{Both non-strict ($\le$ on left and right)}: Equal values stop expansion on both sides, so neither $1$ can reach the other --- \textbf{under-counting} ($8$ subarrays instead of $10$).
\end{itemize}
\end{watchoutbox}

\begin{example}[Checking All Three Rules on $A = {[2, 1, 2, 1]}$ (True Total $= 10$ Subarrays)]
Comparing all three boundary strategies side by side:
\begin{enumerate}
    \item \textbf{Both Strict ($<$) --- Double-Counts ($12$)}: $i=1$ claims $2 \times 3 = 6$ subarrays; $i=3$ claims $4 \times 1 = 4$; $i=0, 2$ claim $1$ each. Sum $= 6 + 4 + 1 + 1 = 12$ ($2$ duplicates).
    \item \textbf{Both Non-Strict ($\le$) --- Under-Counts ($8$)}: $i=1$ claims $2 \times 2 = 4$; $i=3$ claims $2 \times 1 = 2$; $i=0, 2$ claim $1$ each. Sum $= 4 + 2 + 1 + 1 = 8$ ($2$ missed).
    \item \textbf{Asymmetric (Strict $<$ Left, Non-Strict $\le$ Right) --- Exact ($10$)}:
    \begin{itemize}
        \item $i = 1$: $\text{PLE}[1] = -1$, $\text{NLE}[1] = 3 \implies 2 \times 2 = 4$ ($[2, 1], [2, 1, 2], [1], [1, 2]$).
        \item $i = 3$: $\text{PLE}[3] = -1$, $\text{NLE}[3] = 4 \implies 4 \times 1 = 4$ ($[2, 1, 2, 1], [1, 2, 1], [2, 1], [1]$).
        \item $i = 0$ and $i = 2$: $1$ each ($[2]$). Total $= 4 + 4 + 1 + 1 = 10$, an exact partition.
    \end{itemize}
\end{enumerate}
\end{example}

\begin{enumerate}

    \item What wrong count if \textbf{both} stops use non-strict $\le$, and which subarray is missed?
    \item Compute $\text{PLE}$ (strict $<$) and $\text{NLE}$ (non-strict $\le$) for all $3$ indices and find the exact sum of subarray minimums.

\subsection{Boundary Expansion: Largest Rectangle in Histogram}

\begin{notationbox}[Symbols Used in This Subsection]
$H[i]$ & Height of bar $i$ (every bar has width $1$) & Non-negative \texttt{int} \\
$L$ & First bar to the left strictly shorter than $H[i]$ (blocking wall) & $\text{PSE}[i]$ ($-1$ if none) \\
$R$ & First bar to the right strictly shorter than $H[i]$ (blocking wall) & $\text{NSE}[i]$ ($N$ if none) \\
$\text{Width}$ & Number of contiguous bars strictly between $L$ and $R$ & $R - L - 1$ \\
\end{notationbox}

\painbeat Checking every pair of left and right bars $[l, r]$ and tracking the shortest bar between them visits $O(N^2)$ pairs.

\ahabeat Any largest rectangle must touch the top of at least one bar $H[i]$---otherwise you could stretch it taller. Flip the question from ``try every pair of edges'' to ``treat each bar $i$ as the ceiling and stretch it left and right until a shorter bar blocks you.''

\begin{formulabox}[Histogram Rectangle Formula --- In Plain English]
$$
\text{Width} = R - L - 1, \qquad \text{Area} = H[i] \times (R - L - 1)
$$
\textbf{Read this as:} Count how many bars sit \emph{strictly between} the left shorter wall $L$ and the right shorter wall $R$, then multiply by bar $i$'s height. An increasing stack finds both walls in one pass: when bar $R$ pops bar $i$, the right wall is $R$ and the left wall $L$ is the new stack top (or $-1$ if the stack becomes empty).
\end{formulabox}

\begin{watchoutbox}[When It Breaks --- Missing Sentinel]

\end{watchoutbox}

\subsection{Monotonic Deque for Sliding Window Range Extrema}

\begin{notationbox}[Symbols Used in This Subsection]
$K$ & Fixed number of elements inside the sliding window & $1 \le K \le N$ \\
$[i - K + 1,\; i]$ & Active window of indices ending at current step $i$ & Full once $i \ge K - 1$ \\
\texttt{dq.front()} & Index of the current window's maximum value & Oldest survivor in deque \\
\texttt{dq.back()} & Index of the most recently added candidate & Right end of deque \\
\end{notationbox}

\painbeat Scanning all $K$ elements inside every window takes $O(NK)$ time (up to $2.5 \times 10^9$ steps when $N = 10^5, K = 5 \times 10^4$). Even a max-heap pays $O(\log K)$ per step.

\ahabeat When a new element $A[i]$ enters the window, any older element already sitting in the window with value $\le A[i]$ loses on \emph{both} fronts: $A[i]$ is at least as big \textbf{and} will stay inside the window longer. Those older candidates can never win a future window and can be dropped from the back immediately.

\examplebeat Suppose the deque currently holds values $[4, 2]$ and $5$ arrives. Both $2$ and $4$ are $\le 5$ and older than $5$, so we pop both from the back, leaving just $[5]$. Because every weaker older item is evicted on sight, the deque stays strictly decreasing from front to back---making \texttt{dq.front()} the window maximum in $O(1)$ time.

\invariantbeat{Sliding Window Maximum Deque} After step $i$, \texttt{dq} holds only indices inside $[i - K + 1, i]$, sorted in strictly increasing order of index and strictly decreasing order of value.

\begin{enumerate}
    \item \textbf{Front expiry}: If $\texttt{dq.front()} \le i - K$, it fell off the left edge; call \texttt{dq.pop\_front()}.
    \item \textbf{Back domination}: While $A[\texttt{dq.back()}] \le A[i]$, call \texttt{dq.pop\_back()}.
    \item \textbf{Push \& read}: Push $i$ onto the back; once $i \ge K - 1$, read $A[\texttt{dq.front()}]$.
\end{enumerate}

\begin{watchoutbox}[When It Breaks --- Missing Front Expiry]
Forgetting the front-expiry check leaves old champions stuck at the front forever. On $A = [9, 1, 1, 1]$ with $K = 2$, index $0$ (value $9$) stays at the front even for windows $[1, 1]$, falsely reporting $[9, 9, 9]$ instead of $[9, 1, 1]$.
\end{watchoutbox}

\begin{example}[Step-by-Step Sliding Window Trace on $A = {[4, 2, 5, 1, 3]}$, $K = 3$]
Tracking the deque indices at each step:
\begin{enumerate}
    \item $i = 0$ ($4$): push $0$. Deque indices: $[0]$ (values $[4]$).
    \item $i = 1$ ($2$): $2 < 4$, push $1$. Deque: $[0, 1]$ (values $[4, 2]$).
    \item $i = 2$ ($5$): pop $1$ ($2 \le 5$) and pop $0$ ($4 \le 5$) from back; push $2$. Deque: $[2]$ ($[5]$). Window $[0 \dots 2]$ max $= 5$.
    \item $i = 3$ ($1$): front $2 > 3 - 3 = 0$ (still in window); $1 < 5$, push $3$. Deque: $[2, 3]$ ($[5, 1]$). Window $[1 \dots 3]$ max $= 5$.
    \item $i = 4$ ($3$): front $2 > 4 - 3 = 1$ (still in window); pop $3$ ($1 \le 3$) from back; push $4$. Deque: $[2, 4]$ ($[5, 3]$). Window $[2 \dots 4]$ max $= 5$.
\end{enumerate}
Final window maximums: $[5, 5, 5]$.
\end{example}

\subsection{Why Naive Brute-Force Fails}

The obvious way to find every Next Greater Element runs an inner scan for each starting index:
\begin{lstlisting}[numbers=none, xleftmargin=4pt, framexleftmargin=4pt]
// Naive O(N^2) search
for (int i = 0; i < n; ++i) {
    int nge = -1;
    for (int j = i + 1; j < n; ++j) {
        if (A[j] > A[i]) { nge = A[j]; break; }
    }
    ans[i] = nge;
}
\end{lstlisting}

On a strictly descending list $[10^5, 10^5 - 1, \dots, 1]$, every element scans all remaining items to its right and finds nothing:

\begin{formulabox}[Brute-Force Comparison Count --- In Plain English]
$$
(N - 1) + (N - 2) + \dots + 1 + 0 = \frac{N(N - 1)}{2} = O(N^2)
$$
\textbf{Read this as:} At $N = 10^5$, the inner loop runs about $5 \times 10^9$ comparisons---roughly $50\times$ slower than a typical $1$-second budget ($\approx 10^8$ operations).
\end{formulabox}

\subsection{Why a \texttt{while} Inside a \texttt{for} Is Still Linear Time}

\painbeat Looking at a \texttt{while} loop nested inside a \texttt{for} loop makes almost everyone suspect $O(N^2)$ time:
\begin{lstlisting}[numbers=none, xleftmargin=4pt, framexleftmargin=4pt]
for (int i = 0; i < n; ++i) {
    while (!st.empty() && A[st.top()] < A[i]) {
        ans[st.top()] = A[i];
        st.pop();
    }
    st.push(i);
}
\end{lstlisting}

\ahabeat Stop counting ``worst work per iteration'' (yes, one step can pop $N - 1$ items!) and instead count \textbf{total actions per element} over the whole run:
\begin{itemize}
    \item Every index enters the stack \textbf{exactly once} ($N$ pushes total).
    \item An index can only be popped if it is on the stack, so every index leaves \textbf{at most once} ($\le N$ pops total).
    \item The inner \texttt{while} body runs once per pop.
\end{itemize}

Across the entire program, the loop executes at most $N$ pushes plus $N$ pops ($2N$ stack operations total), giving $O(N)$ overall time---an average (amortized) cost of $O(1)$ per item. The exact same $2N$ budget holds for the monotonic deque.

\begin{tryitbox}{Derive}{Prove the Exact Push \& Pop Budget}{ex7}
Run the left-to-right NGE loop mentally on $A = [10, 9, 8, 7, 6, 100]$ ($N = 6$):
\begin{enumerate}
    \item How many pops happen in the single worst iteration ($i = 5$)?
    \item What are the \textbf{exact total} pushes and \textbf{exact total} pops across all $6$ iterations?
    \item Generalize to any length $N$: what is the tightest upper bound on $\text{pushes} + \text{pops}$?
\end{enumerate}
\end{tryitbox}

\subsection{Example 1: Next Greater Element (NGE)}
\label{ex:nge}

\textbf{Goal}: Given $A = [4, 5, 2, 25, 10, 8]$, find the first strictly greater value to the right of each entry (or $-1$ if none).

\textbf{Strategy}: Scan left-to-right with a decreasing stack of indices. Anything still left on the stack at the end stays $-1$.

\begin{enumerate}
    \item \textbf{Start}: $ans = [-1, -1, -1, -1, -1, -1]$, stack $st = []$.
    \item \textbf{$i = 0$ ($4$)}: Stack empty. Push $0$. Stack: $[0]$.
    \item \textbf{$i = 1$ ($5$)}: $4 < 5$, so pop $0$ and set $ans[0] = 5$. Push $1$. Stack: $[1]$.
    \item \textbf{$i = 2$ ($2$)}: $5$ is not less than $2$, so push $2$. Stack: $[1, 2]$.
    \item \textbf{$i = 3$ ($25$)}: Pop $2$ ($2 < 25 \to ans[2] = 25$); pop $1$ ($5 < 25 \to ans[1] = 25$). Push $3$. Stack: $[3]$.
    \item \textbf{$i = 4$ ($10$)}: $25 > 10$, push $4$. Stack: $[3, 4]$.
    \item \textbf{$i = 5$ ($8$)}: $10 > 8$, push $5$. Stack: $[3, 4, 5]$.
    \item \textbf{Finish}: Indices $3, 4, 5$ never got popped, so they keep $-1$.
\end{enumerate}

\textbf{Answer}: $ans = [5, 25, 25, -1, -1, -1]$.

\subsection{Example 3: Largest Rectangle in Histogram Trace}

\textbf{Goal}: Heights $H = [2, 1, 5, 6, 2, 3]$. Find the largest rectangular area.

\textbf{Strategy}: Increasing stack of indices, plus a fake sentinel bar of height $-1$ at index $6$ to flush every remaining bar.

\begin{enumerate}
    \item \textbf{$i = 0$ ($2$)}: Push $0$. Stack: $[0]$.
    \item \textbf{$i = 1$ ($1$)}: $2 > 1 \to$ pop $0$ ($h = 2$, stack empty so $L = -1$, width $= 1 - (-1) - 1 = 1$, area $= 2$). Push $1$. Stack: $[1]$.
    \item \textbf{$i = 2$ ($5$)} and \textbf{$i = 3$ ($6$)}: Both increasing; push $2$, then $3$. Stack: $[1, 2, 3]$.
    \item \textbf{$i = 4$ ($2$)}:
    \begin{itemize}
        \item Pop $3$ ($6 > 2$): $L = 2$, width $= 4 - 2 - 1 = 1$, area $= 6 \times 1 = 6$.
        \item Pop $2$ ($5 > 2$): $L = 1$, width $= 4 - 1 - 1 = 2$, area $= 5 \times 2 = 10$ (new best!).
        \item Top is $1$ ($H[1] = 1 \le 2$), stop. Push $4$. Stack: $[1, 4]$.
    \end{itemize}
    \item \textbf{$i = 5$ ($3$)}: $3 > 2$, push $5$. Stack: $[1, 4, 5]$.
    \item \textbf{$i = 6$ (Sentinel $-1$)}: Flushes remaining bars:
    \begin{itemize}
        \item Pop $5$: $h = 3$, $L = 4$, width $= 1$, area $= 3$.
        \item Pop $4$: $h = 2$, $L = 1$, width $= 4$, area $= 8$.
        \item Pop $1$: $h = 1$, $L = -1$, width $= 6$, area $= 6$.
    \end{itemize}
\end{enumerate}

\textbf{Answer}: $max\_area = 10$ (spanning bars $2$ and $3$).

\subsection{Example 4: Sliding Window Maximum Trace}

\textbf{Goal}: $A = [1, 3, -1, -3, 5, 3, 6, 7]$, window size $K = 3$. Find each window's maximum.

\begin{enumerate}
    \item $i = 0$ ($1$): Push $0$. Deque: $[0]$.
    \item $i = 1$ ($3$): $1 \le 3$, pop $0$ from back; push $1$. Deque: $[1]$.
    \item $i = 2$ ($-1$): Back value $3 \le -1$ is false; push $2$. Deque: $[1, 2]$. Window $[0 \dots 2]$ max $= A[1] = 3$.
    \item $i = 3$ ($-3$): Front $1 > 3 - 3 = 0$ (valid); $-1 \le -3$ is false; push $3$. Deque: $[1, 2, 3]$. Window $[1 \dots 3]$ max $= 3$.
    \item $i = 4$ ($5$): Front $1 \le 4 - 3 = 1$ (expired, pop front!); back pops $3$ ($-3 \le 5$) and $2$ ($-1 \le 5$); push $4$. Deque: $[4]$. Window $[2 \dots 4]$ max $= 5$.
    \item $i = 5$ ($3$): Push $5$. Deque: $[4, 5]$. Window $[3 \dots 5]$ max $= 5$.
    \item $i = 6$ ($6$): Pop $5$ ($3 \le 6$) and $4$ ($5 \le 6$) from back; push $6$. Deque: $[6]$. Window $[4 \dots 6]$ max $= 6$.
    \item $i = 7$ ($7$): Pop $6$ ($6 \le 7$) from back; push $7$. Deque: $[7]$. Window $[5 \dots 7]$ max $= 7$.
\end{enumerate}

\textbf{Answer}: $[3, 3, 5, 5, 6, 7]$.

\subsection{Example 5: Sum of Subarray Minimums (Handling Duplicates)}
\label{ex:subarray_mins}

\textbf{Goal}: Given $A = [3, 1, 2, 1]$, sum $\min(B)$ over all $10$ contiguous subarrays modulo $10^9 + 7$.

\textbf{Strategy}: Use strict $\text{PLE}$ ($<$) on the left and non-strict $\text{NLE}$ ($\le$) on the right so tied subarrays belong uniquely to their rightmost minimum.

\begin{enumerate}
    \item \textbf{Pass 1 --- $\text{PLE}$ (strict $<$, pop while $A[\text{top}] \ge A[i]$)}:
    \begin{itemize}
        \item $i=0$ ($3$): stack empty $\to -1$, stack $[0]$.
        \item $i=1$ ($1$): pop $0$ ($3 \ge 1$) $\to -1$, stack $[1]$.
        \item $i=2$ ($2$): $1 < 2$ $\to 1$, stack $[1, 2]$.
        \item $i=3$ ($1$): pop $2$ ($2 \ge 1$), pop $1$ ($1 \ge 1$) $\to -1$, stack $[3]$.
    \end{itemize}
    Result: $\text{PLE} = [-1, -1, 1, -1]$.

    \item \textbf{Pass 2 --- $\text{NLE}$ (non-strict $\le$, scan right-to-left, pop while $A[\text{top}] > A[i]$)}:
    \begin{itemize}
        \item $i=3$ ($1$): stack empty $\to 4$, stack $[3]$.
        \item $i=2$ ($2$): $1$ is not $> 2 \to 3$, stack $[3, 2]$.
        \item $i=1$ ($1$): pop $2$ ($2 > 1$); $1$ is not $> 1$ (stop!) $\to 3$, stack $[3, 1]$.
        \item $i=0$ ($3$): $1$ is not $> 3 \to 1$, stack $[3, 1, 0]$.
    \end{itemize}
    Result: $\text{NLE} = [1, 3, 3, 4]$.

    \item \textbf{Contributions $(i - \text{PLE}[i]) \times (\text{NLE}[i] - i) \times A[i]$}:
    \begin{itemize}
        \item $i=0$ ($3$): $1 \times 1 = 1$ subarray $\to 3 \times 1 = 3$.
        \item $i=1$ ($1$): $2 \times 2 = 4$ subarrays $\to 1 \times 4 = 4$.
        \item $i=2$ ($2$): $1 \times 1 = 1$ subarray $\to 2 \times 1 = 2$.
        \item $i=3$ ($1$): $4 \times 1 = 4$ subarrays $\to 1 \times 4 = 4$.
    \end{itemize}
\end{enumerate}

\textbf{Answer}: $3 + 4 + 2 + 4 = 13 \pmod{10^9 + 7}$.

\subsection{Example 6: Remove $K$ Digits (Lexicographical Stack)}
\label{ex:remove_k_digits}

\textbf{Goal}: Remove exactly $K = 3$ digits from $S = \texttt{"1432219"}$ to make the smallest possible number.

\textbf{Strategy}: A smaller digit on the left beats any digit change further right. Keep a non-decreasing stack of digits; whenever a smaller digit arrives and $K > 0$, pop the larger top digit and spend $1$ removal.

\begin{enumerate}
    \item \texttt{'1'}, \texttt{'4'}: push both. Stack: \texttt{"14"}, $K = 3$.
    \item \texttt{'3'}: $\texttt{'4'} > \texttt{'3'}$ and $K > 0 \to$ pop \texttt{'4'} ($K = 2$), push \texttt{'3'}. Stack: \texttt{"13"}.
    \item \texttt{'2'}: $\texttt{'3'} > \texttt{'2'}$ and $K > 0 \to$ pop \texttt{'3'} ($K = 1$), push \texttt{'2'}. Stack: \texttt{"12"}.
    \item \texttt{'2'}: equal to top---keep it to save budget! Stack: \texttt{"122"}, $K = 1$.
    \item \texttt{'1'}: $\texttt{'2'} > \texttt{'1'}$ and $K > 0 \to$ pop \texttt{'2'} ($K = 0$), push \texttt{'1'}. Stack: \texttt{"121"}.
    \item \texttt{'9'}: budget spent ($K = 0$), push \texttt{'9'}. Stack: \texttt{"1219"}.
    \item \textbf{Cleanup}: If $K > 0$ remains at the end, chop $K$ digits off the right end; then strip any leading zeros (returning \texttt{"0"} if empty).
\end{enumerate}

\textbf{Answer}: \texttt{"1219"}.

\section{C++ Implementations}
% ============================================================================

All listings below are standalone modern C++23 functions taking zero-copy \texttt{std::span<const int>} or \texttt{std::string\_view} inputs, compiled cleanly with \texttt{-Wall -Wextra}.

\subsection{Next Greater Element}

Scan left-to-right storing unresolved indices in a decreasing \texttt{std::vector<int>} stack. Whenever \texttt{nums[i]} exceeds \texttt{nums[stack.back()]}, it immediately resolves and pops that waiting index.

\begin{lstlisting}[caption=Next Greater Element in C++23]
#include <vector>
#include <span>

[[nodiscard]] std::vector<int> next_greater_elements(std::span<const int> nums) {
    const int n = static_cast<int>(nums.size());
    std::vector<int> result(n, -1);
    std::vector<int> stack; // Stores indices
    stack.reserve(n);

    for (int i = 0; i < n; ++i) {
        // Pop elements whose next greater element is nums[i]
        while (!stack.empty() && nums[stack.back()] < nums[i]) {
            result[stack.back()] = nums[i];
            stack.pop_back();
        }
        stack.push_back(i);
    }
    return result;
}
\end{lstlisting}

\subsection{Distance to Next Warmer Day (Span Calculation)}

Because the stack stores indices, the waiting distance for each resolved day is simply \texttt{i - prev\_index}.

\begin{lstlisting}[caption=Span Calculation / Daily Temperatures in C++23]
#include <vector>
#include <span>

[[nodiscard]] std::vector<int> daily_temperatures(std::span<const int> temperatures) {
    const int n = static_cast<int>(temperatures.size());
    std::vector<int> answer(n, 0);
    std::vector<int> stack;
    stack.reserve(n);

    for (int i = 0; i < n; ++i) {
        while (!stack.empty() && temperatures[stack.back()] < temperatures[i]) {
            const int prev_index = stack.back();
            stack.pop_back();
            answer[prev_index] = i - prev_index;
        }
        stack.push_back(i);
    }
    return answer;
}
\end{lstlisting}

\subsection{Largest Rectangle in Histogram}

An increasing stack tracks candidate bars (assuming non-negative heights). When bar \texttt{i} pops a taller or equal bar, \texttt{i} is the right wall and the new stack top (or \texttt{-1}) is the left wall. The fake sentinel \texttt{-1} at \texttt{i == n} guarantees every bar gets evaluated.

\begin{lstlisting}[caption=Largest Rectangle in Histogram in C++23]
#include <vector>
#include <span>
#include <algorithm>

[[nodiscard]] long long largest_rectangle_area(std::span<const int> heights) {
    const int n = static_cast<int>(heights.size());
    std::vector<int> stack;
    stack.reserve(n);
    long long max_area = 0;

    for (int i = 0; i <= n; ++i) {
        // Use -1 as sentinel height at index n to flush all non-negative bars
        const int current_height = (i == n) ? -1 : heights[i];

        while (!stack.empty() && heights[stack.back()] >= current_height) {
            const int h = heights[stack.back()];
            stack.pop_back();
            const int left_boundary = stack.empty() ? -1 : stack.back();
            const long long width = i - left_boundary - 1;
            max_area = std::max(max_area, static_cast<long long>(h) * width);
        }
        stack.push_back(i);
    }
    return max_area;
}
\end{lstlisting}

\subsection{Sliding Window Maximum with Monotonic Deque}

A \texttt{std::deque<int>} holds indices in strictly decreasing order of value: evict expired indices from the front, evict weaker values from the back, push \texttt{i}, and emit \texttt{nums[dq.front()]} once the window is full.

\begin{lstlisting}[caption=Sliding Window Maximum in C++23]
#include <vector>
#include <deque>
#include <span>

[[nodiscard]] std::vector<int> max_sliding_window(std::span<const int> nums, int k) {
    const int n = static_cast<int>(nums.size());
    if (n == 0 || k <= 0 || k > n) return {};

    std::vector<int> result;
    result.reserve(n - k + 1);
    std::deque<int> dq; // Stores indices of candidate maximums

    for (int i = 0; i < n; ++i) {
        // 1. Remove indices that fell out of the window boundary
        if (!dq.empty() && dq.front() <= i - k) {
            dq.pop_front();
        }

        // 2. Remove indices whose values are dominated by nums[i]
        while (!dq.empty() && nums[dq.back()] <= nums[i]) {
            dq.pop_back();
        }

        // 3. Add current element index to the back
        dq.push_back(i);

        // 4. Record current window maximum once initial window is full
        if (i >= k - 1) {
            result.push_back(nums[dq.front()]);
        }
    }
    return result;
}
\end{lstlisting}

\subsection{Sum of Subarray Minimums with Duplicate Prevention}

Two linear passes compute strict \texttt{ple} (left) and non-strict \texttt{nle} (right), giving every subarray a unique rightmost minimum. Positive modular normalization keeps negative entries safe.

\begin{lstlisting}[caption=Sum of Subarray Minimums with Symmetry Breaking in C++23]
#include <vector>
#include <span>

[[nodiscard]] long long sum_subarray_mins(std::span<const int> arr) {
    const int n = static_cast<int>(arr.size());
    constexpr long long MOD = 1'000'000'007;

    std::vector<int> ple(n); // Previous Less Element (Strict)
    std::vector<int> nle(n); // Next Less or Equal Element (Non-strict)
    std::vector<int> stack;
    stack.reserve(n);

    // Compute Previous Less Element (strictly less)
    for (int i = 0; i < n; ++i) {
        while (!stack.empty() && arr[stack.back()] >= arr[i]) {
            stack.pop_back();
        }
        ple[i] = stack.empty() ? -1 : stack.back();
        stack.push_back(i);
    }

    stack.clear();

    // Compute Next Less or Equal Element (less than or equal)
    for (int i = n - 1; i >= 0; --i) {
        while (!stack.empty() && arr[stack.back()] > arr[i]) {
            stack.pop_back();
        }
        nle[i] = stack.empty() ? n : stack.back();
        stack.push_back(i);
    }

    long long total_sum = 0;
    for (int i = 0; i < n; ++i) {
        const long long left_count = i - ple[i];
        const long long right_count = nle[i] - i;
        const long long count = (left_count * right_count) % MOD;
        const long long term = (count * ((arr[i] % MOD + MOD) % MOD)) % MOD;
        total_sum = (total_sum + term) % MOD;
    }
    return total_sum;
}
\end{lstlisting}

\subsection{Remove $K$ Digits (Lexicographical Monotonic Stack)}

Using \texttt{std::string} directly as a non-decreasing stack avoids extra allocations. Pop strictly larger preceding digits while budget \texttt{k} allows, trim leftover removals from the back, and strip leading zeros.

\begin{lstlisting}[caption=Remove K Digits with Monotonic Stack in C++23]
#include <string>
#include <string_view>

[[nodiscard]] std::string remove_k_digits(std::string_view num, int k) {
    if (num.empty() || k >= static_cast<int>(num.size())) return "0";
    if (k < 0) k = 0;

    std::string stack;
    stack.reserve(num.size());

    for (char digit : num) {
        // Pop strictly larger preceding digits while removal budget remains
        while (!stack.empty() && k > 0 && stack.back() > digit) {
            stack.pop_back();
            --k;
        }
        stack.push_back(digit);
    }

    // Remaining digits are non-decreasing: discard leftover budget from the back
    while (k > 0 && !stack.empty()) {
        stack.pop_back();
        --k;
    }

    // Strip leading zeros; return "0" if all remaining characters are zeros
    const auto first_nonzero = stack.find_first_not_of('0');
    if (first_nonzero == std::string::npos) return "0";
    return stack.substr(first_nonzero);
}
\end{lstlisting}

\section{Problem Pattern Recognition}
% ============================================================================

When you meet an unfamiliar sequence problem, walk through these three quick checks:

\subsection*{Step 1: What Does the Problem Ask For?}
\begin{itemize}
    \item \textbf{Nearest Extrema}: First strictly larger or smaller item to the left or right $\to$ \textbf{Monotonic Stack}.
    \item \textbf{Waiting Distance / Span}: Steps or days until a threshold is crossed $\to$ \textbf{Monotonic Stack of indices}.
    \item \textbf{Subarray Contributions / Histogram Area}: Sum of subarray mins/maxes or widest bounded rectangle $\to$ \textbf{Monotonic Stack with boundary expansion \& tie-breaking}.
    \item \textbf{Sliding Window Min/Max}: Running extremum over moving range $[i - K + 1, i]$ $\to$ \textbf{Monotonic Deque}.
    \item \textbf{Smallest/Largest Subsequence}: Remove $K$ digits/characters $\to$ \textbf{Monotonic Stack with removal budget}.
\end{itemize}

\subsection*{Step 2: What Is the Key Constraint?}
\begin{itemize}
    \item \textbf{Domination}: Does a newer, better item make an older item permanently useless for every future query?
    \item \textbf{Contiguous Order}: Does the answer depend on left-to-right index order (rather than arbitrary subsets)?
    \item \textbf{Duplicates}: Can values repeat? If partitioning subarrays, pair one strict ($<$) wall with one non-strict ($\le$) wall.
\end{itemize}

\subsection*{Step 3: Is Input Too Large for Brute Force?}
\begin{itemize}
    \item \textbf{$N \le 10^3$}: A nested $O(N^2)$ loop does $\approx 10^6$ steps and passes easily.
    \item \textbf{$N \ge 10^5$}: A nested loop does $\approx 10^{10}$ steps (TLE). A monotonic stack or deque finishes in $O(N)$ ($\approx 10^5$ steps, well under $0.05$ seconds).
\end{itemize}

\section{Glossary}
% ============================================================================

\subsection{Core Concepts}
\begin{itemize}
    \item \textbf{Monotonic Stack}: A stack whose elements stay sorted from bottom to top (always increasing or always decreasing).
    \item \textbf{Monotonic Deque}: A double-ended queue maintaining sorted candidates for $O(1)$ amortized sliding-window queries via front expiry and back dominance eviction.
    \item \textbf{Cascading Pops}: Popping several items in a row when a single incoming element breaks the monotonic order.
    \item \textbf{Domination}: When a newer item is both better in value and stays relevant longer, making an older item permanently useless.
    \item \textbf{Amortized $O(1)$}: Even if one step triggers many pops, each item is pushed once and popped at most once over the whole run, averaging constant work per item.
    \item \textbf{Symmetry Breaking}: Pairing a strict comparison ($<$) on one boundary with a non-strict comparison ($\le$) on the opposite boundary so tied subarrays are counted exactly once.
\end{itemize}

\subsection{Mathematical Symbols}
\begin{itemize}
    \item $N$: Number of elements in the array.
    \item $K$: Sliding window width, or digit removal budget.
    \item $O(N)$: Linear time complexity, proportional to input size.
    \item $A[i]$: Value at $0$-based index $i$ of array $A$.
    \item $H[i]$: Height of the $i$-th bar in a histogram.
    \item $L, R$: Left and right blocking indices limiting horizontal expansion of a histogram bar.
    \item $\text{NGE}, \text{PGE}$: Next Greater Element and Previous Greater Element.
    \item $\text{NSE}, \text{PSE}$: Next Smaller Element and Previous Smaller Element.
    \item $\text{PLE}, \text{NLE}$: Previous Less Element (strict $<$) and Next Less or Equal Element (non-strict $\le$) for symmetry breaking.
    \item $\text{MOD}$: Large prime modulus ($10^9 + 7$) used to prevent integer overflow.
    \item $\le, \ge$: Non-strict inequalities (equal values satisfy the condition).
    \item $<, >$: Strict inequalities (equal values do not satisfy the condition).
\end{itemize}

\section*{Practice Sheet: Mixed Pen-and-Paper Drills}
\addcontentsline{toc}{section}{Practice Sheet: Mixed Pen-and-Paper Drills}
\markboth{Practice Sheet: Mixed Pen-and-Paper Drills}{}
% ============================================================================

\noindent
Work through these six mixed drills on scratch paper \emph{without} flipping back to the chapter. Unlike the inline checks above, these combine patterns with no subsection hints---ideal for a timed 15-minute review or spaced repetition a week later.

\begin{tryitbox}{Triage}{Cold Tool Selection}{ex9}
Pick the exact data structure (\textbf{Decreasing Stack}, \textbf{Increasing Stack}, \textbf{Decreasing Deque}, or \textbf{Increasing Deque}) and key boundary rule for each disguised task:
\begin{enumerate}
    \item \textbf{Daily Stock Span}: For each day, count consecutive prior days (including today) whose price was $\le$ today's price.
    \item \textbf{Rolling Minimum Latency}: Maintain the smallest latency among the last $K$ server readings as readings stream in.
    \item \textbf{Widest Shelf Under Uneven Ceiling}: Given ceiling heights $C[0 \dots N-1]$, find the largest rectangle that fits underneath.
\end{enumerate}
\end{tryitbox}

\begin{tryitbox}{Debug}{Circular Waiting Span Bug}{ex10}
To adapt \textbf{Daily Temperature Span} to a \textbf{circular} array (wrapping around after index $n-1$), someone loops $i$ from $0$ to $2n - 1$ using $T[i \bmod n]$:
\begin{lstlisting}[numbers=none, xleftmargin=4pt, framexleftmargin=4pt]
for (int i = 0; i < 2 * n; ++i) {
    while (!st.empty() && T[st.back()] < T[i % n]) {
        span[st.back()] = i - st.back();
        st.pop_back();
    }
    st.push_back(i % n); // <-- Subtle bug!
}
\end{lstlisting}
Trace $T = [2, 3, 1]$ (true circular spans: $[1, 0, 1]$) to find which entry gets corrupted on the second pass, and write the 1-line fix.
\end{tryitbox}

\begin{tryitbox}{Twist}{Sum of Subarray Ranges ($\max - \min$)}{ex11}
Given $A = [1, 3, 2]$, you want the sum of $\max(B) - \min(B)$ across all contiguous subarrays $B$.
\begin{enumerate}
    \item Explain in one sentence how to solve this in $O(N)$ time by reusing \texttt{sum\_subarray\_mins} twice instead of designing a new data structure.
    \item Compute the exact answer for $A = [1, 3, 2]$ on paper using $\sum \max(B) - \sum \min(B)$.
\end{enumerate}
\end{tryitbox}

\begin{tryitbox}{Trace}{Visible People in a Queue}{ex12}
People stand in a line with heights $H = [10, 6, 8, 5, 11, 9]$. Person $i$ can see person $j > i$ to their right if everyone strictly between them is shorter than both $H[i]$ and $H[j]$. Scan right-to-left with a decreasing stack: for each $i$, pop every person shorter than $H[i]$ (counting each pop), and add $+1$ if a taller blocker still sits on top. Compute the visible count for all $6$ positions.
\end{tryitbox}

\begin{tryitbox}{Edge Cases}{Sliding Window Corner Cases}{ex13}
Trace \texttt{max\_sliding\_window(nums, k)} mentally on three edge cases:
\begin{enumerate}
    \item All equal: \texttt{nums = [7, 7, 7, 7]}, $k = 2$ --- what is the output, and what is the \emph{maximum size} the deque ever reaches?
    \item Single-item window: \texttt{nums = [5, 2, 8]}, $k = 1$.
    \item Full-array window: \texttt{nums = [5, 2, 8]}, $k = 3$.
\end{enumerate}
\end{tryitbox}

\begin{tryitbox}{Derive}{Longest Subarray With $\max - \min \le L$}{ex14}
You want the longest contiguous subarray whose $\max - \min \le L$ (test on $A = [8, 2, 4, 7]$ with $L = 4$).
\begin{enumerate}
    \item Why can't a \emph{single} monotonic deque track both the window maximum and window minimum at once?
    \item Use two deques (\texttt{max\_dq} decreasing, \texttt{min\_dq} increasing) and advance \texttt{left} whenever $A[\texttt{max\_dq.front()}] - A[\texttt{min\_dq.front()}] > L$. Trace $A = [8, 2, 4, 7]$, $L = 4$ to find the longest valid subarray length.
\end{enumerate}
\end{tryitbox}

\section*{Solutions to Pen-and-Paper Exercises}
\addcontentsline{toc}{section}{Solutions to Pen-and-Paper Exercises}
\markboth{Solutions to Pen-and-Paper Exercises}{}
% ============================================================================

\begin{enumerate}
    \item \label{sol:ex1}\textbf{Exercise 1 (Trace) --- Skyline Shadows Check:}
    \textbf{(1)} Only $175$ (index $2$) is shadowed by $190$ (closer and taller) and popped.
    \textbf{(2)} Stack keeps $[190, 160]$ (bottom to top). Height $160$ survives because a viewer of height $150$ to its left hits $160$ first, whereas a viewer of height $170$ looks over $160$ and hits $190$.
    \trapnote{Thinking $190$ shadows $160$---shadowing only eliminates elements \emph{behind} (further from future queries than) the taller item.}

    \item \label{sol:ex2}\textbf{Exercise 2 (Trace) --- Four Nearest Queries on $A = [6, 2, 5, 4]$:}
    $\text{NGE} = [-1, 5, -1, -1]$;\quad $\text{PGE} = [-1, 6, 6, 5]$;\quad $\text{NSE} = [2, -1, 4, -1]$;\quad $\text{PSE} = [-1, -1, 2, 2]$.
    \trapnote{Writing $\text{PGE}[2] = 2$ or $\text{PSE}[3] = 5$ by checking only the immediate neighbor instead of skipping past elements that fail the inequality.}

    \item \label{sol:ex3}\textbf{Exercise 3 (Edge Cases) --- Index Stack Stress Test:}
    \textbf{(1)} $[2, 5, 3, 7, 1] \to \text{span} = [1, 2, 1, 0, 0]$, final stack $[3, 4]$ (size $2$).
    \textbf{(2)} $[5, 5, 5, 5] \to \text{span} = [0, 0, 0, 0]$, final stack $[0, 1, 2, 3]$ (size $4$).
    \textbf{(3)} $[9, 7, 5, 3] \to \text{span} = [0, 0, 0, 0]$, final stack $[0, 1, 2, 3]$ (size $4$).
    \trapnote{Popping equal values ($\le$ instead of $<$) falsely outputs $[1, 1, 1, 0]$ on $[5, 5, 5, 5]$ even though no day was strictly warmer.}

    \item \label{sol:ex4}\textbf{Exercise 4 (Debug) --- Duplicate Subarray Tie-Breaking on $A = [1, 3, 1]$:}
    \textbf{(1)} Both $<$ counts $3 + 1 + 3 = 7$ (double-counts $[1, 3, 1]$).
    \textbf{(2)} Both $\le$ counts $2 + 1 + 2 = 5$ (misses $[1, 3, 1]$).
    \textbf{(3)} Strict $\text{PLE} = [-1, 0, -1]$, non-strict $\text{NLE} = [2, 2, 3]$; counts $2, 1, 3$ (sum $= 6$); total sum $= 1(2) + 3(1) + 1(3) = 8$.
    \trapnote{Getting $9$ (both $<$) or $7$ (both $\le$) instead of $8$ because symmetric bounds double-count or drop the subarray spanning both $1$s.}

    \item \label{sol:ex5}\textbf{Exercise 5 (Debug) --- Histogram Expansion \& Missing Sentinel:}
    \textbf{(1)} $H = [3, 1, 4, 2]$: Bar $0 \to (-1, 1, W=1, \text{Area}=3)$; Bar $1 \to (-1, 4, W=4, \text{Area}=4)$; Bar $2 \to (1, 3, W=1, \text{Area}=4)$; Bar $3 \to (1, 4, W=2, \text{Area}=4)$. Max area $= 4$.
    \textbf{(2)} Any strictly increasing histogram like $H = [2, 4, 6]$ triggers zero pops without sentinel $-1$, falsely returning $0$ instead of $8$ (bars $1$--$2$ at height $4$).
    \trapnote{Using $\text{Width} = R - L$ instead of $R - L - 1$, which overstates every width by $1$ because $L$ and $R$ are exclusive blocking walls.}

    \item \label{sol:ex6}\textbf{Exercise 6 (Twist) --- Sliding Window Trace \& Flip to Minimum:}
    \textbf{(1)} On $[4, 1, 3, 5, 2]$ ($K=3$): deque states $[0] \to [0,1] \to [0,2]$ (back pop $1$, max $4$) $\to [3]$ (\textbf{front} pop $0$ expired, \textbf{back} pop $2$, max $5$) $\to [3, 4]$ (max $5$). Output: $[4, 5, 5]$.
    \textbf{(2)} Change only back pruning from $A[\texttt{dq.back()}] \le A[i]$ to $A[\texttt{dq.back()}] \ge A[i]$. Front expiry ($\texttt{dq.front()} \le i - K$) does \emph{not} change.
    \trapnote{Flipping the front-expiry inequality too---window expiration depends only on index distance, never on min vs. max.}

    \item \label{sol:ex7}\textbf{Exercise 7 (Derive) --- Exact Push \& Pop Budget on $[10, 9, 8, 7, 6, 100]$:}
    \textbf{(1)} Iteration $i = 5$ triggers $5$ pops in one step.
    \textbf{(2)} Total across all $6$ iterations: exactly $6$ pushes and $5$ pops.
    \textbf{(3)} General tight bound: $N$ pushes + at most $(N - 1)$ pops $= 2N - 1 = O(N)$ (the final pushed element is never popped).
    \trapnote{Multiplying worst single-step pops ($N - 1$) by $N$ iterations to guess $O(N^2)$ instead of charging pushes and pops per element.}

    \item \label{sol:ex8}\textbf{Exercise 8 (Edge Cases) --- Remove $K$ Digits Killers:}
    \textbf{(1)} \texttt{"10200"}, $K=1 \to$ stack \texttt{"0200"} $\to$ \texttt{"200"}.
    \textbf{(2)} \texttt{"12345"}, $K=2 \to$ no loop pops, trim $2$ from back $\to$ \texttt{"123"}.
    \textbf{(3)} \texttt{"100"}, $K=1 \to$ stack \texttt{"00"} $\to$ strip zeros, fallback to \texttt{"0"}.
    \trapnote{Returning an empty string \texttt{""} on \texttt{"100"}, $K=1$ instead of \texttt{"0"} after stripping leading zeros.}

    \item \label{sol:ex9}\textbf{Exercise 9 (Triage) --- Cold Tool Selection:}
    \textbf{(1)} Stock Span $\to$ \textbf{Decreasing Stack} (Previous Greater Element: stops at first strictly greater day).
    \textbf{(2)} Rolling Minimum Latency $\to$ \textbf{Increasing Deque} (front expiry + pop back while $\ge$ incoming).
    \textbf{(3)} Widest Shelf Under Ceiling $\to$ \textbf{Increasing Stack with trailing $-1$ sentinel} (Histogram expansion).
    \trapnote{Picking an Increasing Stack for Stock Span because the prompt mentions ``lower or equal price''---you search for the first \emph{strictly greater} blocker.}

    \item \label{sol:ex10}\textbf{Exercise 10 (Debug) --- Circular Waiting Span Bug on $T = [2, 3, 1]$:}
    At $i=1$, index $0$ gets $\text{span}[0] = 1$. On pass $2$, $i=3$ pushes $0$ again, and $i=4$ pops $0$ and \textbf{overwrites} $\text{span}[0] = 4 - 0 = 4$ (corrupting $[1, 0, 1]$ into $[4, 0, 1]$).
    \textbf{1-line fix:} Guard the push with \texttt{if (i < n) st.push\_back(i);}.
    \trapnote{Assuming circular traversal is just ``loop to $2n$ and mod everything''---only first-pass indices should ever enter the waiting stack.}

    \item \label{sol:ex11}\textbf{Exercise 11 (Twist) --- Sum of Subarray Ranges on $A = [1, 3, 2]$:}
    \textbf{(1)} By linearity, $\sum(\max - \min) = \sum \max - \sum \min$, so run \texttt{sum\_subarray\_mins} on $A$ and again on $-A$ (negating the result), or flip the inequalities for maxes.
    \textbf{(2)} $\sum \min = 1(3) + 3(1) + 2(2) = 10$; $\sum \max = 1(1) + 3(4) + 2(1) = 15$; answer $= 15 - 10 = 5$.
    \trapnote{Trying to maintain both $\max$ and $\min$ inside one stack---splitting the sum keeps both passes completely independent.}

    \item \label{sol:ex12}\textbf{Exercise 12 (Trace) --- Visible People in a Queue on $[10, 6, 8, 5, 11, 9]$:}
    Right-to-left: $i=5\,(9) \to 0$, $st=[9]$; $i=4\,(11)$ pops $9 \to 1$, $st=[11]$; $i=3\,(5)$ sees blocker $11 \to 1$, $st=[11,5]$; $i=2\,(8)$ pops $5$ + blocker $11 \to 2$, $st=[11,8]$; $i=1\,(6)$ sees blocker $8 \to 1$, $st=[11,8,6]$; $i=0\,(10)$ pops $6, 8$ + blocker $11 \to 3$, $st=[11,10]$. Result: $[3, 1, 2, 1, 1, 0]$.
    \trapnote{Forgetting the $+1$ when the stack is still non-empty after popping---you can still see the first taller person who blocks further sight.}

    \item \label{sol:ex13}\textbf{Exercise 13 (Edge Cases) --- Sliding Window Corner Cases:}
    \textbf{(1)} $[7, 7, 7, 7], k=2 \to$ output $[7, 7, 7]$; because back pruning uses $\le$, every arriving $7$ pops the prior $7$, so max deque size is only $1$.
    \textbf{(2)} $[5, 2, 8], k=1 \to [5, 2, 8]$.
    \textbf{(3)} $[5, 2, 8], k=3 \to [8]$.
    \trapnote{Using strict $<$ instead of $\le$ in back pruning keeps duplicate indices in the deque unnecessarily up to size $k$.}

    \item \label{sol:ex14}\textbf{Exercise 14 (Derive) --- Longest Subarray With $\max - \min \le L$:}
    \textbf{(1)} Maximum requires a \emph{decreasing} deque while minimum requires an \emph{increasing} deque---one ordering cannot put both extrema at the front.
    \textbf{(2)} Trace on $[8, 2, 4, 7]$, $L=4$: $r=0$ ($[8]$, len $1$); $r=1$ ($8-2=6>4 \to$ shrink $l=1$, $[2]$, len $1$); $r=2$ ($4-2=2 \le 4$, $[2,4]$, len $2$); $r=3$ ($7-2=5>4 \to$ shrink $l=2$, $[4,7]$, len $2$). Longest valid length $= 2$.
    \trapnote{Forgetting to pop expired indices ($\le \text{left} - 1$) from \emph{both} \texttt{max\_dq} and \texttt{min\_dq} fronts when \texttt{left} advances.}
\end{enumerate}
